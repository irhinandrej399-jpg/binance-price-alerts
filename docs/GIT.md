# Git по тикетам

Пользователь разрешил агенту самостоятельно создавать локальные коммиты по завершённым тикетам. Повторное подтверждение для каждого коммита не нужно. Работа идёт последовательно, по одному тикету; агент не начинает следующий автоматически.

## Формат сообщения

```text
feat(DOM-003): реализовать проверку пересечения порога

Изменения:
- Добавлен предикат вверх/вниз с точной десятичной ценой.
- Проверены равенство и скачок через порог.

Проверки:
- Red: <команда и наблюдаемая причина падения>.
- Green: <команда и фактический результат>.
```

Это пример формата, а не отчёт о выполнении DOM-003. Типы: feat, fix, refactor, test, docs, chore, perf, build, ci. Заголовок — до 100 символов. Комментарий пишет агент по фактическому diff и проверкам. Для DEC и документации раздел проверок описывает проверенные примеры и документы, без выдуманного Red/Green.

## Порядок завершения

1. Выполнить критерии тикета и нужные тесты. Сетевые сбои, пропуски и провалы проверки не обозначать успехом.
2. Записать результат и передачу в карточке, выставить done, синхронизировать индекс и STATE. Для DEC добавить принятый ADR.
3. Просмотреть diff. Отделить относящиеся к тикету файлы от существующих изменений пользователя. Коммит завершения включает карточку, индекс, STATE и результат задачи; для DEC также ADR.
4. Создать файл описания в системной временной папке. Перечислить изменения и фактические проверки. Внутри коммита не нужно хранить его собственный SHA: это циклическая ссылка. SHA сообщается после commit; следующий агент найдёт его в Git log по ID.
5. Выполнить скрипт с точным списком файлов:

```sh
python3 scripts/git_ticket.py DOM-003 \
  --type feat \
  --summary 'реализовать проверку пересечения порога' \
  --body-file /tmp/DOM-003-commit.txt \
  --files path/to/changed.go path/to/changed_test.go \
    docs/backlog/tickets/DOM-003.md docs/backlog/README.md docs/STATE.md
```

Пути Go-файлов здесь условные: заменить на существующие файлы результата. Для DEC добавить `docs/decisions/DEC-xxx.md`, соответствующий ID и тип docs.

Скрипт проверяет done, наличие передачи, согласованность бэклога и сообщения. Он отказывается трогать уже заполненный индекс, не принимает каталоги вместо файлов, ставит в staging только явный список и требует изменённые метаданные. Он **не подтверждает корректность Go-кода и не заменяет тесты**. Технические проверки выполняет агент до вызова.

6. После commit проверить `git status --short` и `git show --stat HEAD`, сообщить ID, короткий SHA, описание результата и проверки. Оставшиеся пользовательские изменения перечислить без включения в коммит.

## Если работа не завершена

Не выставлять done и не создавать коммит, выдающий незавершённый результат за завершённый тикет. Сохранить фактический прогресс и причину остановки в файлах. Если нужна самостоятельная промежуточная поставка, сначала выделить её в отдельный тикет с собственными критериями. Новые исправления после закрытия можно оформить как `fix(ID): ...`, сохраняя историю.

Если commit/hook завершился ошибкой, проверить индекс и причину. Скрипт сохраняет выбранные изменения в staging для разбора. Не сбрасывать посторонние файлы. После исправления можно снять с индекса только свои перечисленные пути и повторить вызов, сохранив рабочие файлы.

## Границы автоматизации

Разрешены обычные локальные коммиты результата. Не переписывать историю через amend/reset/rebase и не отключать проверки ради успешного commit. Remote/push не являются частью закрытия локального тикета. При отсутствии Git identity использовать настройки автора пользователя, а не выдуманные имя и email.

Первый коммит и обслуживание процесса могут не иметь ID продуктового тикета: `chore: initialize project backlog and agent workflow`. Само создание репозитория не закрывает DEC или Go-задачи.

## Проверка инструмента

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s scripts/tests -v
```

Интеграционные проверки создают временные Git-репозитории. Они проверяют обычный commit, сохранение посторонней работы и staging, незавершённую карточку, рассинхронизацию индекса, обязательные метаданные, формат описания, отказ hook, удаление файла и буквальное понимание путей.
