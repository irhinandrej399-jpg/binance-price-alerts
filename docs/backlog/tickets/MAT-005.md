# MAT-005 — Восстановить обработку цены после частичного сбоя

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [MAT-004](MAT-004.md)

## Модель для сессии

- Модель: `gpt-6-astra` (GPT-6 Astra).
- Уровень размышления: `high` (High).
- Обоснование: После частичной обработки цены нужно возобновить оставшихся кандидатов, не потеряв работу и не создав вторых срабатываний.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Возобновление незавершённой обработки с сохранённого checkpoint.

## Критерии приёмки

- Сбой после части кандидатов не теряет остальных; повтор уже завершённых безопасен.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

При неизменной подходящей последней цене 100 кандидатов, сбой после 37: после рестарта 100 уникальных workflow без дублей. Если к рестарту последняя цена перестала подходить, оставшиеся кандидаты не создают исторические уведомления; durable результаты/ack не теряются.

## Не входит

Тесты нагрузки на миллион подписок.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).

## Сессионная проверка

- MAT-004 done подтверждён handler, SQL-тестами и mTLS интеграцией SUB-014; MAT-016 предоставляет Pending/Get и immutable результаты. Контракты DEC-004 и live.Current определены, PostgreSQL runner готов.
- Один результат: Recover обходит Pending, Resume восстанавливает запрос из Get, затем использует Handle с актуальной live view. Новых reader, миграций, RPC или распределённого владения не требуется.
- Перед восстановлением caller запускает MAT-008/009 с актуальной Latest; ErrNotReady сохраняет pending. Recover не подтверждает транспорт и не выводит префикс из порядка ключей; Resume принимает отдельно доказанный Prefix для повтора ack, включая terminal работу.
- Переход planned → ready после проверки; реализация далее in-progress.

## Ход работы

- 29 октября 2026: после сессионной проверки planned → ready → in-progress. Исходное дерево чистое, работа последовательная в main.
- `internal/matcher/pricehandler/recovery.go`: Recover перечисляет Pending и возобновляет сохранённый вход через Resume/Get/Handle. Resume также поддерживает terminal ключ после потери ack; неизвестный ключ не принимает новую работу. Старые owner/sub/version, Pair/Position, C/ProjectionID и исходы не пересобираются из нового поколения.
- Актуальная live view проверяется существующим Handle перед оставшимися RPC. Недоступная view/временный отказ останавливают проход; более новая цена явно supersede-ит старую работу. Recover не вычисляет транспортный Prefix из порядка ключей и не вызывает ack. Resume принимает отдельно доказанный префикс владельца и подтверждает после commit.
