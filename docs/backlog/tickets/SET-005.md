# SET-005 — Поднять локальный брокер

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [DEC-007](DEC-007.md), [DEC-008](DEC-008.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `medium` (Medium).
- Обоснование: Локальный брокер должен переживать рестарт и сохранять сообщение с выбранными retention/ack настройками.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Команда запуска брокера с постоянным локальным хранилищем.

## Критерии приёмки

- По [DEC-008](../../decisions/DEC-008.md): Kafka — 2 vCPU/4 GiB RAM, volume 40 GiB (24 обычная работа, 8 резерв завершения, 8 аварийный запас); партиции subscription-changes/prices/delivery-requests — 1/16/16. Закрепить digest образа; сохранены fsync и RF=1 без HA. Квалификация ёмкости и ограничители не входят в SET.

- По [DEC-007](../../decisions/DEC-007.md): Kafka KRaft, постоянный volume, RF=1/min ISR=1 для локального профиля; отдельные topics subscription-changes (1 партиция), prices (фиксированное число), delivery-requests. Проверить транзакционный producer/fencing, read_committed, рестарт после commit; internal topics настроены под один узел. Прикладные topics: flush.messages=1, cleanup.policy=delete, retention.ms=-1, retention.bytes=-1, без compaction. Зафиксировать ограничения диска и границу гарантии рестарта; consumer/cleaner приложения не входят.

- Версия закреплена; тестовые streams/topics изолированы от рабочих; параметры retention записаны.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Проверка / воспроизведение

Опубликовать сообщение, перезапустить брокер, прочитать сообщение с подтверждением.

## Не входит

Прикладные consumers и producers.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).
