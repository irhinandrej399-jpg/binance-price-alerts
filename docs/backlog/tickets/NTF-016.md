# NTF-016 — Сохранить временный отказ и обязанность отчёта

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [NTF-006](NTF-006.md), [NTF-009](NTF-009.md), [NTF-010](NTF-010.md), [NTF-007](NTF-007.md), [NTF-008](NTF-008.md)

Выделен при сессионной проверке [NTF-014](NTF-014.md) 3 ноября 2026: отсутствует durable исход доказанной временной ошибки, необходимый reporter.

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Атомарные outcome/report/расписание и однократный бюджет ошибок требуют fencing, защиты replay и проверки отказов commit.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Durable сохранение доказанного временного отказа Telegram вместе с pending report и рассчитанным NTF-006 планом в собственной БД notifications.

## Критерии приёмки

- Известный зарегистрированный attempt/claim/fence связывает immutable retryable-свидетельство и pending report одной транзакцией. Повтор того же исхода не сбрасывает ack, не меняет первый сохранённый план/jitter и не учитывает ошибку дважды; конфликт данных выявляется явно.
- Счётчик доказанных временных ошибок и next_attempt_at переживают restart и дубль intake. Unknown/wait_condition не увеличивают и не сбрасывают бюджет. Значения и границы соответствуют готовому retry.Plan; production defaults не выбираются.
- Только живой совпадающий lease изменяет текущую job и освобождает claim. Исторический отказ сохраняется для API, не меняя новую аренду, отмену или успех. Поздний success сохраняет приоритет и запрещает дальнейшие отправки.
- checkPreviousAttempt распознаёт retryable как доказанный исход, не восстанавливает его как uncertain и соблюдает сохранённое расписание до следующего Claim. Новый Claim не является разрешением HTTP: нужны лимитеры и новый API-допуск.
- При Exhausted автоматические попытки прекращаются через готовый blocked-протокол с attempts_exhausted; crash между локальными операциями не разрешает отправку сверх бюджета. Свидетельство/обязанность отчёта не теряется при ошибке commit.
- Готовый storage-интерфейс и схема документированы для NTF-014/012; выполнены общие [критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Реальный disposable PostgreSQL + fake clock: 429/5xx, повтор одного attempt и конкурентный replay, restart через другой pool, rollback outcome/report/плана при deferred commit failure, расписание без пересчёта jitter, восстановление после expiry, late refusal после takeover/отмены/успеха, достижение бюджета и crash перед блокировкой. Проверить отсутствие повторного учёта ошибки и сохранение ack после replay.

## Не входит

Reporter/gRPC-вызов API (NTF-014), новый Telegram adapter, application-handler NTF-012, бесконечный worker loop и runtime.

## Размер сессии

Кандидат на одну сессию; перед ready проверить существующие jobs/retry интерфейсы и PostgreSQL harness. Не выполнять reporter внутри этой задачи.
