## Модель для сессии

- Модель: `gpt-6.1-sol`.
- Уровень размышления: `high` (High).
- Обоснование: Проверка ABI, attach/loss/drain и происхождения kernel build;
  один инструментальный профиль без inode collector или owner ledger.

Это рекомендация, а не переключение модели. [Условия выбора](../MODELS.md).

## Один результат

Воспроизводимый Linux arm64 tracing toolchain/profile для OPS-043 с реальным
attach/delivery/detach smoke и установленной связью kernel build с исходниками.

## Вход и выход

Вход: [OPS-043 preflight](../../measurements/OPS-043/README.md), существующий
disposable Docker runner и OPS-040 FS helpers. LinuxKit 6.12.76 поддерживает
нужные config options и read-only tracefs; наличие hooks не доказывает attach.

Выход: закреплённые image/packages/tool versions и hashes; kernel config/BTF/
build ID и точные source/patch/build inputs либо проверяемая ссылка на них;
проверенные команды запуска и cleanup; контракт запуска collector для OPS-043.

## Критерии приёмки

- Подготовить минимальный закреплённый userspace для выбранного механизма
  (BPF/libbpf/bpftrace либо обоснованный tracefs/perf вариант). Проверить его
  на фактическом kernel/ABI, записать capabilities и ограничения, не считать
  наличие CONFIG_BPF или функции успешным attach.
- Связать running build ID/config/BTF с точными kernel sources/patches и build
  metadata. Upstream v6.12.76 или master config без связи с LinuxKit build
  не подставлять вместо фактических inputs. Если для текущего LinuxKit это
  недоступно, оставить задачу незавершённой с точным недостающим артефактом;
  смену платформы и подготовку новой VM не выполнять скрытно.
- Реальный ограниченный smoke: attach, вызов известного syscall/helper,
  наблюдённое событие/проверка полей ABI, loss counters, shutdown/drain и detach.
  Проверить отказ attach и потерю/неполный drain; явно blocked вместо PASS.
  Это проверка tooling, не birth/binding/retirement inode.
- Изолировать resources, уникальные probe/group/instance names; не менять
  чужие probes или глобальные tracing filters. Удалить только свои resources,
  сохранить raw commands/results/source hashes и проверку cleanup.
- Документировать интерфейс запуска OPS-043. Не запускать PG gate,
  reference reducer, inode token collector или общий новый phase harness.

## Проверка

Один disposable Linux tooling smoke с сохранёнными raw, отрицательными
проверками attach/loss/drain и cleanup. Искусственные unit-тесты наличия
бинарников не нужны; smoke не подтверждает lifetime coverage.

## Не входит

Incarnation capture OPS-043, owners/barrier/reducer OPS-034, PG workload,
численные bounds, новая VM/смена ядра и квалификация квот.
