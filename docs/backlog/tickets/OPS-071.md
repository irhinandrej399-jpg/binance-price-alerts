# OPS-071 — Подключить RPC notifications к процессу API

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [OPS-070](OPS-070.md), [SUB-018](SUB-018.md), [SUB-020](SUB-020.md), [SUB-027](SUB-027.md), [MKT-006](MKT-006.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high`.
- Обоснование: Композиция mTLS и конкурентного lifecycle с SQL/relay; нужна проверка отмены и освобождения ресурсов.

Это рекомендация пользователю, настройки текущей сессии не меняются. [Условия выбора](../MODELS.md).

## Один результат

Готовые PrepareRecipient/AdmitDelivery/SaveDeliveryResult доступны notifications через управляемый listener API.

## Критерии приёмки

- Расширена одна общая policy listener из OPS-070: notifications имеет только свои методы, matcher сохраняет только свои права.
- Admission использует готовый Latest mTLS client с явными address/DNS/credentials и закрытием connection; API читает только свою БД. Подключены готовые admissionrpc/resultrpc без смены CAS и идемпотентности.
- Конфигурационные ошибки, RPC cancellation и shutdown используют общий lifecycle API; SQL commit до ответа, повтор канонического request/attempt и pending report не подменяются новым исходом.

- Выполнены проверки ниже и [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

scripts/check_api_process.py --package ./cmd/api: executable с disposable API БД/Kafka и готовым loopback Quotes RPC; PrepareRecipient → AdmitDelivery → SaveDeliveryResult с SQL-наблюдением, повтор тех же ID, запрещённая identity, Latest failure/cancellation и shutdown/cleanup. Использовать существующие adapters и grpctest.
Сначала получить падение по отсутствующему runtime wiring; затем подключить готовые adapters и повторить проверки с race. Unit-проверка конфигурации не заменяет процессный тест.

## Не входит

Реальная отправка Telegram, новая политика retry/CAS, правки worker и полный E2E.

## Размер сессии

Кандидат на одну сессию, не ready. Перед реализацией проверить зависимости и достаточность существующего process harness. Если нужен независимый adapter/harness, выделить зависимость до кода.
