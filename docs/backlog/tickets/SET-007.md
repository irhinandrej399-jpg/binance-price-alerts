# SET-007 — Подготовить генерацию Protobuf и сетевые проверки unary gRPC

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [SET-001](SET-001.md), [SET-002](SET-002.md), [DEC-009](DEC-009.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `medium` (Medium).
- Обоснование: Один воспроизводимый путь генерации и сетевой проверки без прикладных методов.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Воспроизводимая основа разработки и проверки unary gRPC в Go.

## Критерии приёмки

- Закреплены версии Go-библиотек gRPC/Protobuf, компилятора и Go-генераторов; документирована одна команда генерации из чистого checkout без зависимости от глобальных случайных версий.
- На минимальном неприкладном probe-контракте проверены генерация Go-клиента/сервера, размещение версионированных схем и отсутствие diff после повторной генерации. Определена проверка актуальности generated-кода для CI.
- Переиспользуемый сетевой test helper запускает сервер на loopback с освобождением ресурсов через Cleanup; проверяются успешный unary RPC, конечный deadline, передача отмены серверному context и недоступный сервер. Проверки имеют ограниченное время и не требуют live сервисов.
- Документированы использование основы в MKT-006 и границы: probe не является публичным прикладным API, сервисные полномочия добавляются SET-008.
- Выполнены применимые [общие критерии готовности](../workflow.md).

## Проверка / воспроизведение

Выполнить генерацию дважды и проверку актуальности generated-кода; запустить сетевые тесты, общий go test -race ./..., go vet ./... и go build ./.... Для инфраструктурных артефактов не создавать искусственные unit-тесты; поведение deadline/cancellation проверять через Red → Green.

## Не входит

Сервисные credentials и права (SET-008), схема последней котировки, доступ к БД, прикладные retries и запуск runtime.

## Размер сессии

Кандидат на одну сессию после проверки зависимостей и доступности инструментов. Не включать продуктовый RPC или runtime четырёх сервисов.
