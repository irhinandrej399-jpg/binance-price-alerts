# NTF-009 — Выдать worker задание с ограниченной арендой

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [NTF-001](NTF-001.md), [NTF-006](NTF-006.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Claim и lease — конкурентный storage-протокол с истечением полномочий и запоздалым worker.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Атомарный claim готового задания и восстановление после истечения lease.

## Критерии приёмки

- По [ADR DEC-004](../../decisions/DEC-004.md): нет удержания lease при ожидании цены/лимитеров. Старый worker не меняет новую попытку; внешняя отправка после неопределённого исхода не объявляется exactly-once.
- Два worker одновременно не владеют одной действующей арендой; старый lease не может завершить новую попытку.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Интеграционные тесты двух worker, падения, истечения lease и запоздалого результата.

## Не входит

Многократная отправка как способ ускорения.

Сессионная проверка 2 ноября 2026 пройдена: NTF-001/006 и PostgreSQL harness готовы; один участок notifications storage. planned → ready → in-progress → done.
