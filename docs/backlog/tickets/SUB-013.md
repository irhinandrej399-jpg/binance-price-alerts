# SUB-013 — Сохранить атомарный запрос работы доставки

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [SUB-001](SUB-001.md), [DOM-003](DOM-003.md), [DOM-004](DOM-004.md), [CON-004](CON-004.md), [DEC-004](DEC-004.md), [SUB-021](SUB-021.md)

Разделённый исходный тикет: [SUB-008](SUB-008.md).

## Модель для сессии

- Модель: `gpt-6-astra` (GPT-6 Astra).
- Уровень размышления: `high` (High).
- Обоснование: Конкурентные кандидаты и отмена должны атомарно согласовать версию, один workflow и outbox без преждевременного освобождения слота.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Одна операция хранилища API: проверка состояния/версии, устойчивый workflow и outbox без освобождения слота.

## Критерии приёмки

- По [DEC-006](../../decisions/DEC-006.md): изменение видимого в снимке состояния и неизменяемое событие с номером C записываются через готовый SUB-021 в той же SQL-транзакции. Порядок блокировок: пользователь/привязка → подписка → workflow/attempt → журнал; сетевых вызовов под блокировкой нет. Ошибка outbox откатывает весь переход и слот, где он меняется.

- По [ADR DEC-004](../../decisions/DEC-004.md): при подходящей проверенной цене сохраняются pending_delivery, trigger_id и AlertTriggered одной транзакцией; слот остаётся занят.
- Одна подписка имеет один workflow ID; существующий возвращается без второго задания, terminal/blocked состояния не возрождаются. Проверяются канонический предикат и версия; отмена побеждает запоздавшего кандидата.
- Хранилище принимает корректную котировку от доверенного application-интерфейса; чтение последней цены готово в SUB-014.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Конкурентные кандидаты дают один workflow/outbox, rollback атомарен; отмена/неверная версия/ложное условие не создают работу; лимит остаётся занят при повторном кандидате.

## Не входит

Сетевой endpoint и межсервисная аутентификация.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).
