# MAT-016 — Сохранить durable результат обработки цены

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [SET-010](SET-010.md), [CON-003](CON-003.md), [MAT-014](MAT-014.md), [DEC-007](DEC-007.md)

Выделенная предпосылка [MAT-004](MAT-004.md) по сессионной проверке 29 октября 2026.

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Транзакционное сохранение незавершённых кандидатов и результата цены требует проверки rollback, повторов и независимых шкал checkpoint.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

SQL-хранилище продолжимой обработки цены в собственной БД matcher с явной границей durable завершения; без вызова API и без Kafka consumer.

## Критерии приёмки

- По [DEC-007](../../decisions/DEC-007.md): сохраняются идентичность/ревизия цены и все оставшиеся кандидаты (owner, subscription ID, ожидаемая версия). Чтение незавершённой работы после открытия второго pool не зависит от памяти прежнего процесса.
- Результат кандидата и продвижение его локального прогресса атомарны; существующий trigger_id сохраняется. Повтор не удаляет результат и не создаёт вторую работу. Ошибка или неопределённость commit требует чтения durable состояния/идемпотентного повтора.
- Завершение цены допускается только после всех durable исходов либо явного durable superseded с заменяющей ревизией. Superseded не удаляет уже принятые workflow. Внешний ack разрешён только после подтверждённого SQL commit.
- Ценовая ревизия, C проекции подписок и транспортная позиция prices различаются. Новая подписка при той же цене должна допускать новую проверку; дедупликации только по ревизии недостаточно. Начальная котировка Latest не получает выдуманный Kafka offset. Обработанный префикс prices не выводится из C или одного результата пары; будущий caller обязан доказать непрерывность транспортного префикса.
- Документированы вход/выход/ошибки операций и правила использования MAT-004/005. Пакет не меняет checkpoint subscription-changes MAT-001/014. Миграция и проверки используют готовый SET-010 без нового harness.
- Выполнены сценарии ниже и [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Реальный disposable PostgreSQL: атомарное принятие цены/кандидатов и rollback; повтор через два pool; сохранённые 37 из 100 результатов и доступные 63 оставшихся; отказ завершения при незавершённых кандидатах; rollback результата/checkpoint; superseded сохраняет существующие workflow; повтор после commit до ack; независимые пары/позиции и C; новая версия подписки при прежней ревизии; Latest без транспортной позиции.

## Не входит

## Размер сессии
