# OPS-062 — Подключить source binding к runtime и восстановлению matcher

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [OPS-060](OPS-060.md), [OPS-061](OPS-061.md), [OPS-053](OPS-053.md), [OPS-010](OPS-010.md)

Разделённый исходный тикет: [OPS-059](OPS-059.md).

## Модель для сессии

- Модель: `gpt-6-astra` (GPT-6 Astra).
- Уровень размышления: `high` (High).
- Обоснование: Интеграция двух проверенных входов с SQL recovery должна сохранить durable Pending, стабильный scope и отказ до readiness.

Это рекомендация, а не смена модели; см. [MODELS](../MODELS.md).

## Один результат

Минимальный cmd/matcher использует готовые source validation и SQL binding на bootstrap/resume/takeover с process-проверкой.

## Критерии приёмки

- Явно настроить ожидаемые Kafka identities changes/prices в cmd/matcher;
  проверить config и metadata до обработки/подтверждения позиции. Историческая
  identity читается из SQL OPS-061 и сравнивается с подтверждённой OPS-060;
  config не заменяет SQL binding. Разделить первый bootstrap и restart.
- Подключить готовые проверки к replica.prepare, Changes, live New/NewResume,
  projection и pricework. Recover mismatch/legacy не превращать в ErrRecovery
  с автоматическим новым snapshot; отказ явно диагностируется до readiness.
  При смене источника не выбирать другой scope и не удалять прежние данные.
- В том же источнике restart/takeover сохраняют scope, Pending, canonical
  trigger_id/исходы, SQL/broker Prefix; новый snapshot не переименовывает старый
  transport checkpoint. C остаётся независим от Kafka offset. Новые SQL и
  transport-протоколы здесь не разрабатываются, используются OPS-060/061.
- Ошибка source validation, metadata или SQL останавливает intake/обработку,
  возвращает явную terminal error, присоединяет readers и отзывает grants по
  готовому shutdown OPS-010. Нет fallback на latest или config bootstrap при
  неподтверждённой исторической строке.
- Обновить runtime README и существующую OPS-052 fixture/процессные сценарии
  для явной identity. Дать команды запуска после миграции, отказ legacy и
  ограничения источника. Read-only API OPS-061 готов для exporter OPS-056;
  нового RPC или регистрации consumers в этой задаче нет.
- Выполнены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Готовый check_matcher_process.py на disposable PostgreSQL/Kafka с race:
первый bootstrap/доказанный checkpoint; SIGKILL в Pending и restart/takeover
того же источника, прежние IDs/Prefix; новый snapshot; legacy и неверные IDs;
SQL/metadata fault. Пересоздать только свой topic с тем же именем/совпадающим
диапазоном offsets: работающий процесс и повторный старт отказывают без reset,
нового scope или удаления старого Pending. Проверить SQL/broker checkpoint,
readiness/exit и cleanup, а не только успешный запуск executable.

## Не входит

Новые transport/SQL adapters, exporter, cleaner/consumer registry, перенос источника, четыре процесса E2E и нагрузка.

## Размер сессии

Кандидат после сессионной проверки готовых интерфейсов и средств проверки.
Использовать существующие disposable runners; новый harness и независимое
поведение не добавлять скрытно. Контракт источника — в OPS-059; изменяющие
гарантии продуктовые решения сначала выделять в DEC.

## Передача от OPS-060

Transport завершён; `Config.Source` обязателен, `Position.Source` несёт identity
вместе с позицией. Group принимает PrepareSource с map[int32]pricefeed.Position,
проверяет Source/Topic/Partition до выдачи Assignment. Старое поле Prepare
оставлено только для компиляции нынешней replica: оно никогда не вызывается,
без нового callback NewGroup отказывает. При подключении SQL OPS-061 заменить
replica.prepare на source-bound callback и удалить это поле, обновить SQL resume
и все связанные fixtures, в том числе replayrpc и matcherprocess. Не присваивать
нынешнюю metadata старой позиции. Сейчас cmd/matcher явно отказывает;
предыдущие process smoke не подтверждают новый runtime. Транспортный Kafka/race
runner и общая Go race/vet/build прошли, PostgreSQL/process не запускались.
