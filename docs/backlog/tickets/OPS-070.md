# OPS-070 — Подключить RPC matcher к процессу API

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [OPS-004](OPS-004.md), [SUB-016](SUB-016.md), [SUB-022](SUB-022.md), [SUB-014](SUB-014.md), [SET-008](SET-008.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high`.
- Обоснование: Композиция mTLS и конкурентного lifecycle с SQL/relay; нужна проверка отмены и освобождения ресурсов.

Это рекомендация пользователю, настройки текущей сессии не меняются. [Условия выбора](../MODELS.md).

## Один результат

Один управляемый mTLS listener API для готовых snapshot/replay/RequestDelivery, вызываемых matcher.

## Критерии приёмки

- Явные listener/server credentials/CA и matcher URI. Общая policy ограничивает полные имена методов; чужие identities и публичный Bearer не дают прав.
- Зарегистрированы готовые snapshotrpc, replayrpc и deliveryrpc над собственным API pool. Pin owner берётся из проверенного сертификата, SQL/outbox протоколы не меняются.
- Startup ошибки bind/TLS/schema не оставляют HTTP/relay/RPC. Signal/terminal failure отменяет и присоединяет RPC до закрытия pool в общем пределе процесса; существующий HTTP drain сохраняется.

- Выполнены проверки ниже и [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

scripts/check_api_process.py --package ./cmd/api: executable, реальный API PostgreSQL/Kafka и mTLS matcher client; создать/прочитать snapshot, зарегистрировать/replay, RequestDelivery и наблюдение канонической записи/outbox; отказ чужой identity, SIGTERM во время RPC, рестарт и cleanup.
Сначала получить падение по отсутствующему runtime wiring; затем подключить готовые adapters и повторить проверки с race. Unit-проверка конфигурации не заменяет процессный тест.

## Не входит

RPC notifications, публичные маршруты создания/Telegram, новый бизнес-код и полный E2E.

## Размер сессии

Кандидат на одну сессию, не ready. Перед реализацией проверить зависимости и достаточность существующего process harness. Если нужен независимый adapter/harness, выделить зависимость до кода.
