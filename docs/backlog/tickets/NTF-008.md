# NTF-008 — Завершить задание при постоянной ошибке

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [NTF-001](NTF-001.md), [NTF-003](NTF-003.md), [NTF-006](NTF-006.md), [NTF-009](NTF-009.md), [NTF-010](NTF-010.md), [NTF-007](NTF-007.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `medium` (Medium).
- Обоснование: Один переход блокировки с классификацией причины; восстановление scheduler вынесено в NTF-015.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Состояние блокировки доставки с причиной и версией канала при постоянном отказе.

## Критерии приёмки

- По [ADR DEC-004](../../decisions/DEC-004.md): постоянный отказ/предел попыток блокирует автоматическую доставку, сообщает delivery_blocked API, подписка остаётся занимающей слот до отмены/успеха.
- Постоянная ошибка не вызывает бесконечные повторы; причина хранится без bot token и приватных данных.
- По [DEC-005](../../decisions/DEC-005.md) blocked из-за бота/chat хранит причину и версию привязки попытки, без отдельной цены блокировки. Job не удаляется; NTF-015 возобновляет проверки после исправления канала. Отсутствие привязки при допуске тоже паркует job без Telegram-вызова. Иные постоянные ошибки различаются и не снимаются перепривязкой.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

- Добавлены `jobs/blocked.go`, миграция `notifications/007_delivery_blocked.sql` и test-only deferred failures в существующем harness. SaveBlocked атомарно сохраняет immutable отказ и pending report, безопасную причину/версию; живой claim закрывается, next_attempt_at=infinity. Replay сохраняет ack, конфликт reason/version отвергается. Исторический отказ не меняет текущую job/аренду, отмену и успех. Claim учитывает блок текущего fence даже после освобождения lease через uncertain; старый fence не блокирует новый цикл. SaveUncertain не понижает durable blocked.
- ParkBlocked сохраняет уже заблокированный API-допуск без фиктивного attempt/HTTP/report и с immutable квитанцией claim для restart/replay. Каноническое API-состояние/слот принадлежат SUB-018/020; передача pending report — NTF-014, scheduler восстановления — NTF-015. Job/body/workflow не удаляются, отдельная цена блокировки не добавлена.
- PermanentReason использует типизированные безопасные ошибки: Forbidden и точно allowlisted sender InvalidChat → channel_unavailable, прочие Rejected → permanent_failure; Plan.Exhausted caller сохраняет как attempts_exhausted. Unknown/NotSent/429/5xx не классифицируются как постоянный отказ. Description/token/chat/text не сохраняются. Тест sender использует только loopback fixtures; реальных Telegram-сообщений нет.
- Первый запуск runner в sandbox не получил Docker socket. После разрешённого доступа начальный SQL/race прогон проверил основные сценарии блока, но общий результат FAIL: импорты intake-теста добавлены во время работы runner после построения Go-графа (could not import/open); это не считается успешным прогоном. Окончательный runner запущен повторно на неизменяемом наборе исходников и полной fixture.
