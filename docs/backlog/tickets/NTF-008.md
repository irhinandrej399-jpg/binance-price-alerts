# NTF-008 — Завершить задание при постоянной ошибке

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [NTF-001](NTF-001.md), [NTF-003](NTF-003.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `medium` (Medium).
- Обоснование: Один переход блокировки с классификацией причины; восстановление scheduler вынесено в NTF-015.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Состояние блокировки доставки с причиной и версией канала при постоянном отказе.

## Критерии приёмки

- По [ADR DEC-004](../../decisions/DEC-004.md): постоянный отказ/предел попыток блокирует автоматическую доставку, сообщает delivery_blocked API, подписка остаётся занимающей слот до отмены/успеха.
- Постоянная ошибка не вызывает бесконечные повторы; причина хранится без bot token и приватных данных.
- По [DEC-005](../../decisions/DEC-005.md) blocked из-за бота/chat хранит причину и версию привязки попытки, без отдельной цены блокировки. Job не удаляется; NTF-015 возобновляет проверки после исправления канала. Отсутствие привязки при допуске тоже паркует job без Telegram-вызова. Иные постоянные ошибки различаются и не снимаются перепривязкой.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Тесты bot blocked/невалидного chat и повторного получения того же события.

## Не входит

Автоматическая перепривязка Telegram.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).
