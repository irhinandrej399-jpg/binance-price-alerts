# SUB-018 — Открыть допуск доставки с проверкой последней цены

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [SUB-017](SUB-017.md), [MKT-006](MKT-006.md), [DEC-009](DEC-009.md)

Выделен при уточнении [DEC-004](DEC-004.md); не реализуется внутри задачи решения.

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Внутренний endpoint должен связать доверенного отправителя, последнюю котировку и готовую атомарную операцию без разрешения по старой цене задания.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Один защищённый интерфейс API для допуска попытки notifications.

## Критерии приёмки

- По [DEC-009](../../decisions/DEC-009.md): внутренний интерфейс реализуется как unary gRPC с Protocol Buffers, сервисными полномочиями и конечным deadline; изменяющие операции сохраняют идемпотентность. Контрактные проверки включают сетевой адаптер, deadline и недоступность зависимости. Перед ready проверить готовность генерации и test harness; отсутствующие общие предпосылки выделить отдельно.

- Проверены полномочия notifications/workflow; последняя цена/ревизия читается через MKT-006, затем вызывается SUB-017.
- Результаты: разрешение с проверенной котировкой/сроком, wait_condition, terminal, blocked, временная недоступность. Цена события не заменяет чтение.
- Повтор request ID не выдаёт вторую попытку; неопределённый исход восстанавливается по ID.
- По [DEC-005](../../decisions/DEC-005.md) ответ допуска содержит актуальные chat и версию канала. При blocked из-за канала та же версия/нет привязки возвращает blocked без отправки; новая версия запускает чтение последней цены и готовую операцию SUB-017. Недоступная цена/привязка даёт отложенный повтор, не потерю работы.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Сервисный/внешний клиент, последняя 99 при кандидате 101, последняя 101, quote unavailable, повтор после timeout и отмена; проверка точной котировки ответа.

Дополнительно: новая привязка при blocked и цена true/false/unavailable; котировка старого события не используется. Смена версии между чтением и commit требует повтора проверки.

## Не входит

Создание storage-протокола и Telegram worker.
