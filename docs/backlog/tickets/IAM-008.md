# IAM-008 — Поглотить код и привязать Telegram chat

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [IAM-006](IAM-006.md), [IAM-007](IAM-007.md), [DEC-005](DEC-005.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Атомарное поглощение кода и уникальность chat должны сохраняться при двух конкурентных запросах.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Атомарная привязка одного приватного chat к аккаунту по коду.

## Критерии приёмки

- Код одноразовый; конкурентное использование не привязывает два аккаунта; правило уникальности chat закреплено.
- По [DEC-005](../../decisions/DEC-005.md) успешная привязка/перепривязка атомарно увеличивает монотонную версию канала; привязка согласуется с созданием и допуском подписок в API. Chat уникален среди аккаунтов; чужая привязка не перехватывается. Возобновление подписок выполняется отдельно через SUB-018/NTF-015.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Тесты верного, истёкшего, повторного кода и двух конкурентных поглощений.

Дополнительно: перепривязка своего аккаунта меняет версию; повтор уже поглощённого кода не создаёт новую версию; чужой chat отклоняется.

## Не входит

Бот для CRUD подписок.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).
