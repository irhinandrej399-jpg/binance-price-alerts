# DOM-004 — Реализовать одноразовый жизненный цикл

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [SET-001](SET-001.md), [DEC-004](DEC-004.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `medium` (Medium).
- Обоснование: Конечный набор разрешённых переходов можно проверить изолированно; распределённая транзакция сюда не входит.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Модель допустимых переходов состояния одной подписки.

## Критерии приёмки

- По [ADR DEC-004](../../decisions/DEC-004.md): active, pending_delivery, sending и delivery_blocked незавершённые и занимают слот. Ложное условие возвращает к active; очередь слот не освобождает.
- delivered и cancelled terminal; слот освобождается один раз. Отмена после допуска останавливает следующие попытки, но не отзывает внешний запрос. Поздний успех отменённой подписки сохраняется в аудите без перевзвода.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Таблица разрешённых переходов, повтор результата/отмены, pending_delivery→active без нового слота, blocked с занятым слотом, поздний успех после отмены и запрет возрождения delivered/cancelled.

## Не входит

Транзакции БД и повторное взведение.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).
