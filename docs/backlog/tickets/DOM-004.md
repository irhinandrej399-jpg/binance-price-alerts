## Один результат

## Критерии приёмки

- По [ADR DEC-004](../../decisions/DEC-004.md): active, pending_delivery, sending и delivery_blocked незавершённые и занимают слот. Ложное условие возвращает к active; очередь слот не освобождает.
- delivered и cancelled terminal; слот освобождается один раз. Отмена после допуска останавливает следующие попытки, но не отзывает внешний запрос. Поздний успех отменённой подписки сохраняется в аудите без перевзвода.
- По [DEC-005](../../decisions/DEC-005.md) blocked из-за канала возобновляется при новой версии привязки с прежним порогом/workflow; без отдельной цены блокировки. Это продолжение незавершённой подписки, не перевзвод terminal.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

## Контракт результата

- `internal/domain/subscription`: нулевой `Lifecycle` — active. `State()`, `OccupiesSlot()` и `Blocked()` возвращают состояние, занятость слота и причину/версию канала. `Apply(Event)` возвращает новое значение и эффекты `ReleaseSlot`, `AuditSuccess`; исходное значение не мутируется. Ошибки `ErrEvent`/`ErrTransition` оставляют его неизменным, без эффектов.
- Candidate при true переводит active в pending_delivery, при false возвращает pending_delivery в active. Дубликат кандидата не сбрасывает sending/blocked. Admit из active/pending_delivery при true даёт sending, при false — active, при unavailable ничего не меняет. Это проверка уже существующего workflow, не создание ещё одного. Повтор Admit из sending запрещён: повтор команды должен возвращать сохранённый ответ API.
- Retry из sending даёт pending_delivery; повтор в pending_delivery ничего не меняет. Block сохраняет причину и версию канала и занимает слот. Resume допустим только для ChannelUnavailable при строго новой версии существующей привязки: true → pending_delivery, false → active, unavailable → отложенная проверка без изменения blocked. Фактическая отправка требует отдельного Admit с новой проверкой цены. AttemptsExhausted/PermanentFailure перепривязкой не снимаются; причины канала, включая исчерпание повторов из-за канала, классифицируются как ChannelUnavailable.
- Cancel завершает любое незавершённое состояние; повтор Cancel и Cancel после delivered не меняют terminal. Достоверный Success известной попытки завершает любое незавершённое состояние, включая ожидание после неоднозначного исхода. После cancelled он лишь требует аудита и оставляет cancelled. Повтор Success после delivered/cancelled не освобождает слот второй раз. Любые новые кандидаты, допуски, повторы и восстановления terminal запрещены.
- Модель не получает порог, исходный снимок или workflow ID: они остаются в содержащей подписке. Проверка композиции с DOM-002/003 подтверждает прежний процентный порог при восстановлении по текущей цене. Отдельной цены блокировки нет.
- `ReleaseSlot` применяется владельцем атомарно с новым состоянием; `AuditSuccess` — требование сохранить результат идемпотентно по workflow/attempt ID, включая поздний успех отменённой подписки. Это эффекты чистой модели, а не готовые счётчик БД и durable-аудит. Владелец проверяет идентичность попытки/workflow, версии, fencing/lease и дедупликацию команд; запоздалые отказы старой попытки отсекаются до Apply. Отмена не отзывает уже допущенный HTTP-запрос.
