# OPS-048 — Собрать минимальный процесс market-data

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [MKT-005](MKT-005.md), [MKT-017](MKT-017.md), [MKT-013](MKT-013.md), [MKT-014](MKT-014.md), [MKT-011](MKT-011.md), [OPS-006](OPS-006.md), [DEC-010](DEC-010.md), [OPS-049](OPS-049.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Один владелец feed/SQL/relay; поколения, ошибки startup и fencing
  требуют проверки на реальных SQL/Kafka и управляемом raw trade потоке.

Это рекомендация, а не смена модели; см. [MODELS](../MODELS.md).

## Один результат

Минимальный cmd/market-data с одним явно заданным raw trade потоком для
проверки остановки OPS-009. Это ещё не полный каталог runtime для E2E.

## Критерии приёмки

- Конфигурация HTTP_ADDR, собственной market_data БД, raw WS URL/пары,
  Kafka topic и stable transactional.id валидируется до готовности;
  credentials не выводятся, миграции применяются отдельно.
- Готовые Decode/Accept и Reconnect подключены к одному фиксированному
  raw trade потоку. Перед каждым новым соединением начинается durable
  поколение; прежние callbacks не меняют новое поколение. Разрыв сохраняется,
  source ID/revision и envelope следуют storage контракту. Если текущий
  Reconnect не предоставляет нужную границу подключения, сначала выделить
  недостающий узкий adapter, не обходить правило BeginGeneration.
- Readiness/health OPS-006 используют собственный Ping и согласованный
  snapshot единственного потока; live подтверждается явно по контракту,
  dial/одна сделка не заменяют подтверждение. Неподтверждённое состояние
  отображается честно. Ошибки SQL не считаются принятым событием.
- Готовый relay MKT-014 публикует durable bytes; terminal ошибка завершает
  владельца, startup failure освобождает открытые ресурсы.
- Через OPS-049 запускается настоящий executable: raw fixture принята
  durable, независимый read_committed consumer видит исходные key/value
  outbox; restart сохраняет source ID/работу. Проверены неверный config,
  startup failure и terminal relay failure. Есть инструкция запуска и
  явные ограничения минимального процесса.

## Сценарии TDD (Red → Green → Refactor)

Config/startup, fixture trade → durable Accept → Kafka, разрыв/reconnect
с новым поколением, terminal relay и restart с теми же durable bytes.
Использовать OPS-049; его реализацию не включать в wiring.

## Не входит

Graceful SIGTERM/drain (OPS-009), полный динамический каталог, внутренние
RPC и E2E четырёх сервисов, backfill, многорепличный feed, нагрузка/capacity.

## Размер сессии

Кандидат на одну сессию после проверки интерфейсов и средств проверки.
Отсутствующие adapters и независимое поведение выделять отдельно по
[workflow](../workflow.md). Локальный профиль — [DEC-010](../../decisions/DEC-010.md).
