# OPS-013 — Ограничить частоту входа и регистрации между репликами

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [IAM-003](IAM-003.md), [IAM-004](IAM-004.md), [DEC-003](DEC-003.md), [DEC-006](DEC-006.md)

Разделённый исходный тикет: [OPS-005](OPS-005.md).

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Общая квота входа между репликами требует атомарности, аккуратного выбора ключа и корректного окна времени.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Один лимитер публичной аутентификации с общей квотой двух реплик.

## Критерии приёмки

- По [ADR DEC-003](../../decisions/DEC-003.md): Общая квота регистрации и входа принадлежит API; реплики API используют собственную область состояния, а не хранилища matcher/notifications/market-data.
- Добавление реплики не умножает квоту; ключ и окно заданы до ready; секреты не участвуют в labels/логах.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Fake clock и два экземпляра проверяют исчерпание, новое окно и независимость ключей по выбранному контракту.

## Не входит

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).

## Согласованный контракт

- 6 ноября 2026 пользователь принял предложенную политику. Общая квота POST /v1/accounts и POST /v1/sessions: 20 допущенных попыток на канонический IP за фиксированную минуту UTC [начало, конец). Учитываются и успешные, и неуспешные запросы; отклонённые лимитером не увеличивают счётчик. 404/405 и отклонённые внешним bodylimit запросы квоту не расходуют.
- Источник IP — RemoteAddr, IPv4-mapped IPv6 приводится к IPv4; proxy headers игнорируются. Невалидный RemoteAddr возвращает 400 invalid_request. За общим proxy/NAT клиенты разделяют квоту.
- PostgreSQL API — единственный источник production-времени, получаемого после блокировки строки IP. При откате часов окно не откатывается. Fake clock используется только в тестах. Один постоянный row на IP переиспользуется в новом окне; автоматическая очистка не входит в этот результат и остаётся ограничением.
- 429 rate_limited с Retry-After (целые секунды вверх до конца окна), 503 auth_limit_unavailable при сбое/таймауте БД, без вызова handler credentials. SQL-допуск ограничен 1 с. JSON errors и Cache-Control: no-store, секреты/IP не логируются и не становятся labels.
- Middleware подключается к двум готовым handlers в cmd/api, внутри общего bodylimit, до JSON/password/account/session. Commit квоты предшествует handler; отмена/ошибка handler не возвращает попытку. Неоднозначный commit не разрешает обработку запроса, попытка может быть потрачена.
- Повторная сессионная проверка: зависимости и PostgreSQL harness готовы, один результат; planned → ready → in-progress. Несогласованная политика из предыдущей записи теперь согласована; её ожидание больше не блокирует работу.
