# SUB-014 — Открыть внутренний запрос работы доставки

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [SUB-013](SUB-013.md), [DEC-003](DEC-003.md), [MKT-006](MKT-006.md), [DEC-009](DEC-009.md)

Разделённый исходный тикет: [SUB-008](SUB-008.md).

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Внутренний вызов меняет каноническое состояние; важно отделить полномочия matcher от пользовательской сессии и сохранить ошибки CAS.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Один защищённый интерфейс вызова готовой атомарной операции.

## Критерии приёмки

- По [DEC-009](../../decisions/DEC-009.md): внутренний интерфейс реализуется как unary gRPC с Protocol Buffers, сервисными полномочиями и конечным deadline; изменяющие операции сохраняют идемпотентность. Контрактные проверки включают сетевой адаптер, deadline и недоступность зависимости. Перед ready проверить готовность генерации и test harness; отсутствующие общие предпосылки выделить отдельно.

- По [ADR DEC-004](../../decisions/DEC-004.md): API аутентифицирует matcher, читает последнюю корректную цену через MKT-006, проверяет каноническое условие и вызывает готовую SUB-013. Пользователь не может подставить цену.
- Ложное текущее условие не создаёт работу; недоступность цены/API имеет повторяемый результат. Дубликат возвращает существующий workflow. Защищённый интерфейс не читает чужие таблицы.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Авторизованный matcher, внешний клиент, stale версия и повтор; кандидат 101 при последней 99 не создаёт работу; последняя 101 создаёт один workflow; недоступная котировка оставляет подписку ждать.

## Не входит

Изменение транзакции срабатывания и выбор нового wire-протокола.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).
