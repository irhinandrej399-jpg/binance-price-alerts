# MAT-008 — Догнать изменения и переключить matcher в live

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [MAT-002](MAT-002.md), [MAT-007](MAT-007.md), [DEC-004](DEC-004.md), [DEC-007](DEC-007.md), [MAT-012](MAT-012.md), [SUB-022](SUB-022.md), [MAT-014](MAT-014.md), [MAT-015](MAT-015.md)

Разделённый исходный тикет: [MAT-003](MAT-003.md).

## Модель для сессии

- Модель: `gpt-6-astra` (GPT-6 Astra).
- Уровень размышления: `high` (High).
- Обоснование: Переход snapshot→replay→live требует доказать отсутствие окна между изменениями подписок и допустимыми ценами.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Один координатор replay от границы снимка до безопасного перехода в live, использующий готовые storage-контракт MAT-014 и Kafka-источник MAT-015.

## Критерии приёмки

- По [DEC-007](../../decisions/DEC-007.md): использовать SUB-022: SQL-replay после C до объявленной H; Kafka регистрируется до H, дубли до H безопасны, пропуски/отставание публикации закрывает SQL-replay. Периодическая проверка head продолжается в live. Durable проекция/checkpoint предшествуют подтверждению прогресса API и commit следующего Kafka offset; auto-commit выключен, read_committed включён.

- По [ADR DEC-004](../../decisions/DEC-004.md): replay касается изменений подписок после C; готовность требует MAT-012 для последних цен. Исторический ценовой true не является самостоятельным поводом отправки.
- Изменения во время чтения снимка применены; версии не откатываются; граница допуска цен соблюдена.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Создание и отмена во время snapshot/replay отражены в live-проекции; первое допустимое ценовое событие не потеряно.

## Не входит

Первичная загрузка снимка, реализация storage-контракта SQL-replay (MAT-014), Kafka-источника изменений (MAT-015) и возобновление с локального checkpoint.

## Размер сессии

Сессионная проверка 29 октября 2026 пройдена после MAT-014/015: storage, replay RPC, Kafka, индекс и ценовое подключение готовы, общий disposable PostgreSQL/Kafka runner существует. Один результат — координатор, без restart/runtime/consumer group. planned → ready → in-progress → done.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).
