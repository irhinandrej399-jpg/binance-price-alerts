# MKT-018 — Выдать каталог пар через внутренний gRPC

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [MKT-001](MKT-001.md), [DEC-003](DEC-003.md), [DEC-009](DEC-009.md), [SET-007](SET-007.md), [SET-008](SET-008.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `medium` (Medium).
- Обоснование: Один read-only RPC поверх готового каталога, генерации, mTLS и сетевого test harness.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Защищённый unary gRPC-интерфейс каталога market-data и Go-клиент для проверки пары при создании подписки в API.

## Критерии приёмки

- Версионированный `.proto`, generated Go-код, сервер и клиент возвращают полный `catalog.Snapshot`: точные symbol/base/quote и UpdatedAt. Фильтрация MKT-001 не дублируется в API. Источник сервера имеет контекстный интерфейс, совместимый с `catalog.Client.Fetch`.
- Успешный пустой каталог отличается от ошибки получения; ошибка источника не выдаётся за пустой успешный снимок. Доступность пары определяется присутствием точного symbol в успешном каталоге.
- Только доверенная идентичность API получает право на RPC через готовый serviceauth; пользовательский Bearer не даёт сервисных прав. Прямых обращений API к Binance или хранилищу market-data нет.
- Клиент и сервер задают конечный документированный бюджет, сохраняют более ранний deadline и передают отмену источнику; автоматических повторов нет. Ошибки безопасны и различают отказ полномочий и недоступность зависимости.
- Используются генератор SET-007, защищённый loopback helper и mTLS SET-008; документация описывает подключение клиента и семантику ошибок.
- Выполнены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Через реальный loopback gRPC проверить точную передачу пар и UpdatedAt, пустой каталог, ошибку источника, доступ API, отказ чужому сервису/без credentials, недоступность сервера, deadline и отмену с наблюдением context источника. Внешний Binance заменить готовым локальным fixture MKT-001, если проверяется композиция Fetch. Генерация `python3 scripts/generate_proto.py --check`, race-тесты затронутых пакетов, go vet и go build.

## Не входит

HTTP-создание подписки SUB-003, публичный endpoint каталога, refresh-loop, persistence/cache каталога, runtime, WebSocket, PKI и нагрузка.
