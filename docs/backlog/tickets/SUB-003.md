# SUB-003 — Создать подписку через HTTP

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [SUB-002](SUB-002.md), [IAM-005](IAM-005.md), [DOM-002](DOM-002.md), [DOM-005](DOM-005.md), [MKT-001](MKT-001.md), [MKT-006](MKT-006.md), [DEC-005](DEC-005.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `medium` (Medium).
- Обоснование: Один endpoint собирается из завершённых зависимостей; нужно проверить варианты ввода и отображение ошибок.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Один endpoint создания подписки по цене либо проценту.

## Критерии приёмки

- Пара проверяется по каталогу; владелец берётся из сессии; порог и исходная котировка сохраняются; stale quote и превышение лимита имеют ошибки.
- По [ADR DEC-002](../../decisions/DEC-002.md) для обоих видов подписок свежесть проверяется при использовании исходной котировки: возраст от времени сделки по UTC от 0 до 5 секунд включительно. При недоступной цене (missing/stale/invalid_time либо непроверенное значение после рестарта) — HTTP 503, код quote_unavailable; подписка не создаётся, слот не расходуется. Старый признак fresh не заменяет повторную проверку возраста.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

HTTP-тесты цены, процента, неизвестной пары, чужого user_id и 16-й подписки; для обоих видов — свежая цена на границе, отсутствующая, устаревшая, с будущим временем и непроверенная после рестарта. Проверить 503 quote_unavailable и отсутствие созданной подписки/расхода слота при отказе, включая старение котировки до её использования.

## Не входит

Список, отмена и редактирование подписок.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).
