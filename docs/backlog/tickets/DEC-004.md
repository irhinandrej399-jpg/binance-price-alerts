# DEC-004 — Определить границу активации подписки

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [DEC-001](DEC-001.md), [DEC-002](DEC-002.md), [DEC-003](DEC-003.md)

## Модель для сессии

- Модель: `gpt-6-astra` (GPT-6 Astra).
- Уровень размышления: `high` (High).
- Обоснование: Нужно связать активацию, задержку проекции и гонку отмены со срабатыванием, проверив несколько временных последовательностей.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Контракт момента, с которого цены могут вызвать срабатывание.

## Критерии приёмки

- По [ADR DEC-004](../../decisions/DEC-004.md) последняя цена проверяется при подключении/обработке и перед каждой попыткой Telegram; исчезнувшее условие не вызывает уведомления, подписка ждёт дальше.
- Учтены задержка проекции, цена между созданием и подключением, очередь Telegram и отмена одновременно с допуском отправки; есть три временные проверки и владелец канонических переходов API.
- Ранее согласованное безусловное срабатывание по исходной цене DEC-001/002 явно пересмотрено по новому согласию владельца. Возраст/предупреждения и фиксированный процентный порог сохранены.
- Очередь не завершает подписку и не освобождает слот; confirmed delivery/отмена освобождают его ровно один раз. Неоднозначный внешний исход не объявляется exactly-once.
- Обновлены требования, связанные ADR, зависимые карточки и очередь; новые storage/сетевые операции не спрятаны в прежних задачах. Выполнены общие проверки готовности.

## Проверка решения

Временные диаграммы трёх гонок; явно выбран владелец атомарного перехода состояния.

Тип: решение, исполняемых тестов не требуется. Решение записать в `docs/decisions/` и обновить требования и зависимые карточки.

## Не входит

Реализация распределённого протокола.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).

Рабочее дерево до начала чистое; прочитаны действующие ADR, требования, workflow, MODELS, GIT и относящиеся интерфейсы будущих задач. Рекомендация карточки — GPT-6 Astra · High; настройки клиента не менялись.
- Подготовлен [проект ADR DEC-004](../../decisions/DEC-004.md): сравнены активация по индексу, по часам commit и по согласованному снимку/позиции потока. Рекомендуется исходный снимок + все допустимые цены после B, включая интервал до commit создания. Уже выполненное исходное условие фиксируется атомарно при создании; отмену и кандидата разрешает первый commit API.
- Разобраны три временные последовательности: задержка проекции при выполненном исходном условии; краткий выход цены за порог до индексации; одновременная отмена/срабатывание. Дополнительно описаны повторы после timeout, удержание принятой работы, снимок подписок/C и ценовая граница B без смешения cursor разных потоков.

- Проверки проекта: `python3 scripts/backlog.py check` — успешно (3 done, 5 decision); `git diff --check` — успешно; проверка относительных Markdown-ссылок в трёх изменённых документах — все 30 целей существуют. Принятые ADR DEC-001/002/003 не изменялись.

Первоначальный проект replay цен от исходного снимка отклонён, ADR переписан. Требования и ранее принятые ADR пока не пересматриваются без уточнения исходного выполненного условия.

Проверка только при подключении недостаточна при очереди Telegram.
