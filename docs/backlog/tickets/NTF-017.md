Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [NTF-008](NTF-008.md), [NTF-016](NTF-016.md)

## Уточнение объёма — 8 ноября 2026

По [DEC-011](../../decisions/DEC-011.md) задача остаётся: это конкретный дефект
прав, поведения или обычной интеграционной проверки. Проверить причину и
узкое исправление на существующем fixture, выполнить относящиеся regression
тесты и штатный CI. Нагрузочные/длительные стресс-повторы, новый общий harness
и многократные полные suite не нужны. Защитные assertions и production guards
сохраняются; неизвестную причину не выдавать за «просто flaky».

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `medium` (Medium).
- Обоснование: Узкая новая миграция прав с готовым PostgreSQL harness; контракты неизменяемых свидетельств и mutable ack уже заданы.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

SQL-права runtime соответствуют append-only контракту ранее созданных таблиц известных попыток/исходов notifications.

## Воспроизведение

Обнаружено 3 ноября 2026 при NTF-016. `infra/postgres/init.sh:25` задаёт default
SELECT/INSERT/UPDATE/DELETE для runtime на новые таблицы migration-роли.
Миграции 005–007 добавляют SELECT/INSERT через GRANT, но не отзывают UPDATE/DELETE.
Под notifications_runtime после миграций выполнить:

```sql
SELECT has_table_privilege(current_user,'app.delivery_successes','UPDATE'),
       has_table_privilege(current_user,'app.delivery_successes','DELETE');
```

Ожидаемый контракт — false/false; фактическая комбинация init/default GRANT даёт
true/true. Аналогично проверить delivery_attempts, delivery_uncertainties,
delivery_blocks и delivery_block_parks. В NTF-016 это выявлено реальной проверкой
прав новых delivery_retryables; миграция 008 явно отзывает default-права только
на собственные новые таблицы. Старые таблицы в NTF-016 не изменялись.

## Критерии приёмки

- Новая миграция (без изменения применённых 005–008) явно отзывает UPDATE/DELETE/TRUNCATE у runtime на append-only attempt/outcome/block-park таблицы; SELECT/INSERT сохраняются.
- Reports оставляют UPDATE для ack, без права удаления свидетельств или обязанностей отчёта. Mutable jobs/claims/лимитеры продолжают работать.
- PostgreSQL/race тесты под реальной runtime-ролью проверяют запрет UPDATE/DELETE, сохранение INSERT/SELECT и ack, а также все текущие jobs сценарии.
- Документация прав исправлена по фактическим проверкам; выполнены общие [критерии готовности](../workflow.md).

## Не входит

Ревизия прав других сервисов, изменение исходов/worker/reporter, общая переделка default privileges.
