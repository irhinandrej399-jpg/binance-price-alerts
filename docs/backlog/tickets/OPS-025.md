# OPS-025 — Измерить продолжение API в matcher

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [OPS-024](OPS-024.md), [MAT-011](MAT-011.md)

Выделен из [OPS-021](OPS-021.md) при сессионной проверке 4 ноября 2026.

## Модель для сессии

- Модель: `gpt-6.1-sol`.
- Уровень размышления: `high` (High).
- Обоснование: Проекции, fencing и checkpoint должны быть связаны с исходными версиями и физическими дублями без смешения источников.

Это рекомендация, а не переключение модели. [Условия выбора](../MODELS.md).

## Один результат

Manifest и отчёт физических затрат matcher на продолжение событий API с сохранённой связью источника.

## Критерии приёмки

- Использовать runner OPS-023 и идентичности/bytes OPS-024; перечислить обязательные записи projection/snapshot/replay/live checkpoint, fencing и pricework/job по фактическим готовым adapters. Явно перечислить покрытые и непокрытые классы. Создание входных API событий/цен и bootstrap вынести в setup либо отдельные именованные окна.
- Под matcher_runtime вызывать готовые adapters, RPC к API через готовый loopback mTLS. Сохранить source/event/trigger ID, версии и offsets; измерить повторные версии, первое применение и обработку физического дубля. Durable checkpoint и изменения проекции подтвердить диагностическим чтением, не прикладным доступом к чужой БД.
- Входные размеры и максимальные batches брать из реальных контрактов/настроек, фиксировать ограничения и отсутствие конечных пределов. Отделить затраты market-data источника и API от затрат matcher; не создавать новые бизнес-переходы и протоколы.
- Сохранить empty, реальную запись, повтор на чистых volumes, manifest, raw двух collectors и отчёт с версиями/командами; проверить coverage/обязательные метрики/cleanup. Unsupported или отсутствующая фаза не qualified. Полный race suite и нагрузочный fixture не запускать.

## Проверка

Disposable PostgreSQL/Kafka; контрольные опыты и проверка raw/формата отчёта. Инфраструктурная проверка без искусственных unit-тестов. Недоступная проверка не считается успешной.

## Не входит

Новые runtime/collector/координатор, измерения API и notifications, market-data источник, квалификация стоимости и ledger.

## Размер сессии

Перед ready проверить прямые интерфейсы зависимостей и один измерительный проход по [workflow](../workflow.md). Новую независимую предпосылку выделить до реализации; при нескольких самостоятельных результатах уточнить разделение.
