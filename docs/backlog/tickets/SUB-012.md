# SUB-012 — Сохранить outbox при отмене подписки

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [SUB-005](SUB-005.md), [CON-002](CON-002.md), [SUB-021](SUB-021.md)

Разделённый исходный тикет: [SUB-006](SUB-006.md).

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Нужно сохранить согласованность отмены, версии, слота и события при сбое записи и конкурентном повторе.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Одна транзакция отмены подписки и события SubscriptionChanged.

## Критерии приёмки

- По [DEC-006](../../decisions/DEC-006.md): изменение видимого в снимке состояния и неизменяемое событие с номером C записываются через готовый SUB-021 в той же SQL-транзакции. Порядок блокировок: пользователь/привязка → подписка → workflow/attempt → журнал; сетевых вызовов под блокировкой нет. Ошибка outbox откатывает весь переход и слот, где он меняется.

- Слот, версия состояния и outbox изменяются атомарно; повторная отмена не создаёт новое изменение состояния.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Сбой записи события откатывает отмену; конкурентные отмены освобождают один слот и дают один переход версии.

## Не входит

Создание подписки и публикация outbox.

Сессионная проверка 28 октября 2026 пройдена: SUB-005, CON-002 и SUB-021 подтверждены кодом, контрактом и миграцией 007; PostgreSQL harness готов. Один результат — запись отмены и полного after-image в journal.Append перед commit; planned → ready → in-progress → done.

Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).
