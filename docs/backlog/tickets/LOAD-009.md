# LOAD-009 — Собрать команду воспроизводимого нагрузочного прогона

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [E2E-002](E2E-002.md), [LOAD-001](LOAD-001.md), [LOAD-002](LOAD-002.md), [OPS-002](OPS-002.md), [OPS-003](OPS-003.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Runner связывает параметры, процессы, ошибки и артефакты; неверная обработка завершения может создать ложный успешный отчёт.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Один runner готового профиля сохраняет входные параметры, сырые метрики и итоговые ID.

## Критерии приёмки

- Использует готовые генераторы и стенд; идентифицирует commit/seed/ресурсы; завершение по времени и ошибки имеют стабильный exit status.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Проверка / воспроизведение

Малый профиль проходит полный запуск и сохраняет артефакты; заданный отказ даёт неуспешный статус без ложного отчёта об успехе.

## Не входит

Доказательство целевой производительности, оптимизация и собственный фреймворк нагрузочного тестирования.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).
