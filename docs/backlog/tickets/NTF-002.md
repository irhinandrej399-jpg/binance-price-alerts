# NTF-002 — Сформировать текст Telegram-уведомления

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [CON-004](CON-004.md), [DOM-001](DOM-001.md)

## Модель для сессии

- Модель: `gpt-6-luna` (GPT-6 Luna).
- Уровень размышления: `high` (High).
- Обоснование: Одна чистая функция форматирования использует готовые значения; точность и escaping проверяются fixtures.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Чистая функция формирования одного сообщения.

## Критерии приёмки

- По [ADR DEC-004](../../decisions/DEC-004.md): передаваемая фактическая цена берётся из свежего допуска попытки, не из исторического AlertTriggered; при необходимости отображаются время сделки/предупреждения DEC-002.
- В тексте есть пара, порог, фактическая цена и направление; спецсимволы корректно обработаны.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Snapshot/табличные тесты двух направлений, точных дробей и экранирования.

## Не входит

Вызов API и локализация.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).
