# OPS-064 — Сохранить source binding intake notifications в SQL

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [NTF-001](NTF-001.md), [OPS-060](OPS-060.md)

## Модель для сессии

- Модель: `gpt-6.1-sol`.
- Уровень размышления: `high` (High).
- Обоснование: SQL provenance и защита старого writer требуют атомарности с job/checkpoint и сохранности всех исходов.

Это рекомендация, а не смена модели; см. [MODELS](../MODELS.md).

## Один результат

Атомарная привязка SQL intake к стабильному logical consumer, поколению bootstrap и Kafka source с read-only чтением provenance.

## Критерии приёмки

- Использовать общий kafkasource.Identity (ClusterID, ненулевой TopicID, topic), partition отдельно. Задокументировать стабильный logical intake ID и отдельную проверяемую identity поколения SQL bootstrap; group member/replica и рестарт их не меняют. Новый пустой SQL bootstrap требует новой identity, которую cleaner должен явно ожидать.
- Предусмотреть явный bootstrap нового пустого intake и атомарный binding/checkpoint; повтор того же bootstrap идемпотентен, несовпадение ID/source/generation даёт отказ. Проверить существующие legacy checkpoints/jobs до любой записи: не приписывать им источник из нынешней metadata/config, не сбрасывать и не backfill-ить автоматически.
- Source-bound Accept проверяет durable binding в одной транзакции с job+checkpoint, включая ветку duplicate ниже next. CAS сохраняет непрерывный префикс. Ошибка/mismatch не создаёт job и не разрешает ack.
- Миграция сохраняет bytes/jobs/attempts/reports/checkpoints. После binding старый SQL writer без identity не может продвинуть offset или добавить intake job в обход binding; доказать реальным SQL, не только Go-проверкой. Не блокировать законные обновления jobs worker.
- Read-only API возвращает согласованную MVCC view consumer/generation/source/topic/partition/next; отсутствие строки, legacy и mismatch — явный отказ без INSERT и synthetic 0. Согласовать интерфейс для OPS-065/066/057 до реализации.
- Документировать миграцию, права, ошибки и операторский bootstrap; выполнить общие критерии готовности.

## Сценарии TDD (Red → Green → Refactor)

Реальный PostgreSQL: новый bootstrap/повтор/конфликт, commit/rollback/deferred commit failure, duplicate/CAS, legacy без изменения bytes/исходов, старая SQL-запись после binding, неизвестный read без INSERT, отдельные consumer/generation/source, отмена SQL. Использовать scripts/check_postgres.py и существующие intake fixtures.

## Сессионная проверка и контракт — 7 ноября 2026

- NTF-001/OPS-060 подтверждены storage/Decode, SQL fixtures и kafkasource.Identity.
  Docker 29.5.2 доступен. Готовые check_postgres.py и notifications process runner
  позволяют проверить общий SQL и отдельно пустую БД; нового harness не нужно.
- Один logical intake на БД notifications, как в прежнем контракте NTF-001.
  Registry singleton: ConsumerID/Generation — непустые стабильные операторские
  идентификаторы, Source — kafkasource.Identity. Новая пустая БД требует нового
  Generation из внешнего операторского inventory; код не может доказать
  уникальность identity между уничтоженными БД. Cleaner ожидает оба ID явно.
- Bootstrap(ctx, Binding, partitions) явно регистрирует полный набор партиций
  с next=0 одной транзакцией; одинаковый повтор не меняет продвинутые offsets.
  Любые legacy jobs/checkpoints до binding запрещают bootstrap, включая next=0.
- AcceptBound(ctx, Binding, partition, expected, offset, key, body) проверяет
  binding до duplicate/CAS и коммитит job+next атомарно. ReadProgress(ctx,
  Binding, partition) — один read-only SELECT/MVCC, никакого bootstrap/INSERT.
  ErrUnbound/ErrMissing/kafkasource.ErrMismatch/ErrCheckpoint различают отказы.
- Immutable registry и SECURITY DEFINER функции, закрытые от PUBLIC; runtime
  имеет SELECT/EXECUTE. После binding прямые INSERT jobs и изменения checkpoint
  запрещены INVOKER guard, проверяющим current_user, без доверия к GUC.
  Job worker UPDATE сохраняется. Bootstrap/legacy writes сериализованы;
  legacy writes и bootstrap требуют READ COMMITTED.
- План проверок: отдельный testdata/binding пакет на пустой БД через существующий
  scripts/check_postgres.py --binding-only; общий check_postgres.py
  сохраняет прежние fixtures и проверяет совместимость legacy до bootstrap.
- Исходные изменения очереди/карточек сохранены. Реализация не включает transport,
  runtime или exporter. После readiness: ready → in-progress.
