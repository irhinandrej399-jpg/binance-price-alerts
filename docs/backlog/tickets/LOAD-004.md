# LOAD-004 — Проверить burst 10000 срабатываний/с

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [LOAD-003](LOAD-003.md), [OPS-003](OPS-003.md), [NTF-012](NTF-012.md), [NTF-013](NTF-013.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Burst и дренирование требуют раздельного учёта durable событий, памяти и внешнего лимита, без смешивания разных задержек.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Один отчёт всплеска и последующего дренирования очереди.

## Критерии приёмки

- По [ADR DEC-004](../../decisions/DEC-004.md): результат трактуется по DEC-004: запрос работы и delivered раздельны; при сохраняющейся контрольной цене durable работа восстанавливается, при исчезнувшем условии уведомление не требуется. Учитываются pending report и ожидающие/blocked подписки.
- Раздельно измерены создание trigger, приём durable jobs и фактическая отправка; нет потери заданий или неограниченного роста RAM.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Проверка / воспроизведение

Fake Telegram соблюдает настроенные квоты; после согласованного burst очередь дренируется, уникальные события сверяются.

## Не входит

Реальная массовая рассылка пользователям.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).
