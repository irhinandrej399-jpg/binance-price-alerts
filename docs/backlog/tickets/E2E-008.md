# E2E-008 — Расширить fake Binance для плана каталога

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [E2E-003](E2E-003.md), [MKT-016](MKT-016.md)

Выделен при сессионной проверке [MKT-019](MKT-019.md) 8 ноября 2026.

## Модель для сессии

- Модель: `gpt-6.1-sol`.
- Уровень размышления: `medium`.
- Обоснование: Узкое расширение готового сетевого fixture для динамических подписок.

Рекомендация, не переключение модели. [Условия выбора](../MODELS.md).

## Один результат

Существующий binancefake управляемо обслуживает reconciler на /ws и изменяемый
каталог для небольшого процессного сценария MKT-019.

## Критерии приёмки

- Сохранить фиксированные raw endpoints и существующих пользователей fake.
- Добавить bare /ws с SUBSCRIBE/UNSUBSCRIBE, точным id ACK result:null и
  наблюдаемым набором потоков. Доставлять явно заданную сделку только в
  соответствующую подписку, без автоматических цен или durable ревизий.
- Предоставить безопасную замену каталога родителем и отправку по выбранной
  паре на одном соединении; проверить добавление/удаление двух-трёх пар.
- Disconnect/Next, отмена и Close продолжают работать; Close присоединяет
  handlers, в том числе незабранные соединения. Изменения каталога/набора
  безопасны при конкурентном чтении процессом.

## Проверка

TDD через настоящие catalog.Client, stream.Reconciler и trade.Decode:
две различные цены, обновление каталога, SUBSCRIBE/UNSUBSCRIBE с ACK,
reconnect и cleanup. Целевой race и CI; без Docker для самого helper.

## Границы

Расширение internal/testutil/binancefake и его README/тестов. Без нового
универсального runner, нагрузочного генератора и изменений production runtime.
Процессный smoke с SQL/outbox выполняется только в MKT-019.
