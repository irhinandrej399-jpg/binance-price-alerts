# LOAD-008 — Проверить восстановление notifications под нагрузкой

Статус: `cancelled`. Приоритет определяется зависимостями, а не номером.

Зависимости: [LOAD-004](LOAD-004.md), [OPS-011](OPS-011.md)

## Снято с плана — 8 ноября 2026

По [DEC-011](../../decisions/DEC-011.md) задача отменена по поручению
пользователя: production ready для пет-проекта без тяжёлой квалификации.
Исходные критерии ниже — история, не требования к выпуску и не выполненная
работа. Не возобновлять через «некст тикет». Сохранённые raw и код не удалены.
Проверка восстановления на малом наборе перенесена в [E2E-007](E2E-007.md).

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: После аварии worker нужно отдельно учесть leases, сохранённые задания и допустимые внешние дубли после неоднозначной отправки.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Один отчёт аварийного отказа notification worker.

## Критерии приёмки

- По [DEC-008](../../decisions/DEC-008.md): отдельный burst на 300-й секунде; после durable приёма первых 100 контрольных jobs прервать worker во время принятого fake Telegram запроса до получения ответа. Затем перезапустить; фиксировать TTL lease, неоднозначную отправку/дубли и pending report. Цены сохраняются подходящими, deadline восстановления и дренирования — 600 с после рестарта; fake лимит 25/с.

- По [ADR DEC-004](../../decisions/DEC-004.md): результат трактуется по DEC-004: запрос работы и delivered раздельны; при сохраняющейся контрольной цене durable работа восстанавливается, при исчезнувшем условии уведомление не требуется. Учитываются pending report и ожидающие/blocked подписки.
- Lease освобождается по TTL; durable jobs не теряются; возможные внешние дубли после timeout учитываются отдельно.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Проверка / воспроизведение

Завершить worker во время принятого Telegram запроса; перезапустить и сверить состояния заданий и возможные повторные сообщения.

## Не входит

Exactly-once внешней доставки.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).
