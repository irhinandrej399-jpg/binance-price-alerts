# MKT-001 — Получить каталог доступных spot-пар USDT

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [SET-001](SET-001.md)

## Модель для сессии

- Модель: `gpt-6-luna` (GPT-6 Luna).
- Уровень размышления: `high` (High).
- Обоснование: Один внешний ответ фильтруется по явно заданным признакам; fixture-тесты ограничивают объём задачи.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Адаптер каталога торговых пар Binance.

## Критерии приёмки

- Отбираются доступные для торговли spot-пары с котируемой валютой USDT; результат имеет timestamp обновления.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Fixture-тесты подходящей пары, другой quote asset, остановленной торговли и ошибки API.

## Не входит

WebSocket-подписки и фьючерсы.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).

## Ход работы

- Дата: 27 октября 2026.
- Сессионная проверка: SET-001 done подтверждён go.mod, Go 1.26.3 и cmd/market-data; рабочее дерево исходно чистое. Требования и DEC-003 закрепляют каталог за market-data. Один результат — внешний REST-адаптер, готовый стандартный httptest; новых зависимостей и продуктовых решений нет. Выполнены planned → ready → in-progress → done.
- Поля GET /api/v3/exchangeInfo повторно сверены с официальным rest-api.md Binance. Локальная фильтрация: quoteAsset=USDT, status=TRADING, isSpotTradingAllowed=true. permissions не используется. Публичный origin и HTTP-клиент передаются извне.
- Добавлен пакет internal/marketdata/catalog: New/Fetch(ctx), Pair и Snapshot. UpdatedAt — UTC-время завершения успешного обновления по подставляемым часам, не serverTime Binance. Ошибки дают нулевой снимок, успешный пустой список получает timestamp. Лимит ответа — 16 MiB. Контракт и границы описаны в README пакета.
- Red: `GOCACHE=/tmp/binance-go-build GOTOOLCHAIN=local go test ./internal/marketdata/catalog` после добавления fixture-тестов — FAIL, no non-test Go files: адаптера ещё нет.
- Green: после реализации та же команда — PASS. Первая попытка была остановлена sandbox: httptest не смог открыть loopback-порт; повтор с разрешением запуска сервера прошёл.
- Fixture проверяет подходящие пары, другую quote asset, остановленную торговлю и запрет spot. Дополнительно проверены HTTP 429/503, API error envelope с HTTP 200, повреждённый/лишний JSON, missing/null symbols, некорректная подходящая пара, пустой каталог, отмена контекста, транспортный отказ и превышение размера ответа. Время обновления проверено с фиксированными часами и переводом в UTC.
- Refactor: стандартные net/http и encoding/json без стороннего SDK; DTO ответа локален Fetch, публичные структуры содержат только данные каталога; gofmt выполнен.
- Итог: `GOCACHE=/tmp/binance-go-build GOTOOLCHAIN=local go test -race ./...` — PASS всех пакетов (PostgreSQL opt-in проверки этим прогоном не включаются); `go vet ./...` — PASS; `go build ./...` — PASS с теми же GOCACHE/GOTOOLCHAIN. Первый sandbox build вернул код 0 с предупреждением о записи module stat cache; повтор с расширенными разрешениями завершился без предупреждений.
- `git diff --check`, `gofmt -l internal/marketdata/catalog` и `python3 scripts/backlog.py check` — PASS.
- Критерии приёмки выполнены; живой Binance не вызывался, проверка основана на контролируемых HTTP fixtures.
