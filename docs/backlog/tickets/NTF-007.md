# NTF-007 — Обработать неоднозначный timeout отправки

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [NTF-003](NTF-003.md), [NTF-006](NTF-006.md), [NTF-009](NTF-009.md), [NTF-010](NTF-010.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Нужно различить отсутствие ответа и доказанный отказ: сообщение могло уйти, поэтому состояние и повторы должны отражать неопределённость.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Явный durable переход задания в состояние возможной доставки с политикой новой проверки и pending report API.

## Критерии приёмки

- По [ADR DEC-004](../../decisions/DEC-004.md): неопределённость сохраняется durable и сообщается API; повтор только после новой проверки цены. Если условие исчезло, ожидание без отправки. Поздний подтверждённый успех не уничтожается из-за lease.
- Риск повторного Telegram-сообщения виден в состоянии и durable метрике; внутренний trigger_id не меняется. Экспорт метрики — OPS-003.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Fake server принимает запрос и обрывает ответ; повтор следует выбранной политике и не заявляет exactly-once.

## Не входит

Обещание отсутствия дублей у Telegram. Доставка pending report по сети — NTF-014;
новый API-допуск по цене/лимитеры и HTTP-повтор — NTF-012; экспорт метрики — OPS-003.
В этой сессии проверяется локальный outcome-протокол и контракт парковки; полная
интеграция этих компонентов не заявляется.

## Размер сессии

Сессионная проверка 3 ноября 2026 пройдена: NTF-003/006/009/010 и PostgreSQL harness готовы. Один участок notifications jobs, протокол Claim/RegisterAttempt/SaveSuccess известен. planned → ready → in-progress → done.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).

Живой lease паркуется в uncertain без удержания аренды. Исторический исход не меняет чужую/истёкшую аренду или cancelled. Успех той же попытки запрещает создание нового отрицательного исхода; поздний success остаётся через SaveSuccess и блокирует новые Claim/RegisterAttempt/Park.

Два прежних takeover-теста успеха обновлены: теперь сначала durable uncertain вместо скрытого пропуска незавершённой попытки.

Новый HTTP требует обоих лимитеров и нового API-допуска/attempt. Исчерпанный бюджет не разрешает отправку; blocked-протокол и его интеграция остаются NTF-008/014/012.
