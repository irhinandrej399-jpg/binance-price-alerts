# OPS-027 — Устранить гонку описи временных Kafka-файлов

Статус: `cancelled`. Приоритет определяется зависимостями, а не номером.

Зависимости: [OPS-020](OPS-020.md), [OPS-023](OPS-023.md)

Обнаружен при OPS-025; независимое исправление collector не включено в manifest matcher.

## Снято с плана — 8 ноября 2026

По [DEC-011](../../decisions/DEC-011.md) задача отменена по поручению
пользователя: production ready для пет-проекта без тяжёлой квалификации.
Исходные критерии ниже — история, не требования к выпуску и не выполненная
работа. Не возобновлять через «некст тикет». Сохранённые raw и код не удалены.

## Модель для сессии

- Модель: `gpt-6.1-sol`.
- Уровень размышления: `medium` (Medium).
- Обоснование: Один инфраструктурный путь find/stat с ограниченным повтором и проверкой полноты описи.

## Один результат

Опись Kafka-volume выдерживает конкурентное исчезновение временного файла,
сохраняя явную ошибку при невозможности получить полную подтверждённую опись.

## Критерии приёмки

- Воспроизвести гонку существующего collector: find/stat пересекается с заменой
  `logs/replication-offset-checkpoint.tmp` работающим Kafka.
- Устранить ложный отказ с ограниченным бюджетом, без молчаливого пропуска
  постоянных файлов, подстановки нулевых bytes и объявления неполного raw успешным.
- Проверить пустой/записывающий broker, отказ по исчерпанию бюджета, обязательные
  метрики и cleanup штатным disposable runner; сохранить raw и команды.

## Проверка

Инфраструктурная проверка реального Kafka-volume и формата collector report.
Не запускать полный функциональный/race suite параллельно физическим измерениям.

## Не входит

Бизнес-manifests, новая стоимость/ledger, новые collectors или изменение durability.

## Воспроизведение

5 ноября 2026: OPS-025/run-a2 остановился после work_results, при описи перед/после
work_results_repeat. [Kafka report](../../measurements/OPS-025/run-a2/kafka/report.json)
содержит точную команду `find . -type f -print0 | ... stat ...` и ошибку:
`find: ./logs/replication-offset-checkpoint.tmp: No such file or directory`.
Оба collector report имеют failed, cleanup PostgreSQL/Kafka подтверждён.
Один прогон OPS-025/run-a1 на том же collector прошёл; гонка недетерминирована.

Команда воспроизведения исходного опыта — в
[MATCHER.md](../../../infra/measure/MATCHER.md), с новым output на каждый запуск.
Сбой воспроизводится без изменения бизнес-adapters, при штатной активности broker.
