# NTF-001 — Создать durable задание из срабатывания

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [CON-004](CON-004.md), [SUB-009](SUB-009.md), [SET-004](SET-004.md), [DEC-003](DEC-003.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Создание задания и подтверждение события имеют разные точки сбоя; уникальность trigger_id должна работать при конкуренции.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Consumer AlertTriggered, атомарно создающий задание доставки.

## Критерии приёмки

- По [DEC-006](../../decisions/DEC-006.md): задание хранится в PostgreSQL notifications с UNIQUE/NOT NULL trigger_id; concurrent insert даёт одно задание. До commit ack запрещён; сервис не имеет прав к БД API.

- По [ADR DEC-004](../../decisions/DEC-004.md): событие запрашивает условную работу, не terminal-успех. Слот API остаётся занят; один trigger_id/workflow соответствует одному заданию, в том числе через ожидание цены. Дубликат не сбрасывает состояние.
- По [ADR DEC-003](../../decisions/DEC-003.md): Задание и дедупликация принадлежат notifications; AlertTriggered приходит из outbox API. Создание задания — собственная транзакция notifications, без записи в подписки или outbox API. Запрос работы слот не освобождал; результат сообщается API отдельно.
- Уникальность по trigger_id; ack только после commit; повтор не создаёт второго задания.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Тесты двух одинаковых событий, concurrent insert и сбоя между commit и ack.

## Не входит

HTTP-вызов Telegram.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).
