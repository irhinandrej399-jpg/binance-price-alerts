# DEC-006 — Выбрать постоянное хранилище

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [DEC-003](DEC-003.md), [DEC-004](DEC-004.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Выбор хранилища должен быть обоснован транзакциями, конкурентным лимитом и outbox, а не только знакомым названием СУБД.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

ADR с одним выбранным хранилищем и границами транзакций.

## Критерии приёмки

- По [ADR DEC-004](../../decisions/DEC-004.md): хранилище должно поддерживать один workflow, допуск attempt, идемпотентные результаты/слот и commit-согласованную границу снимка; поздняя доставка не требует общей транзакции API/notifications.
- По [ADR DEC-003](../../decisions/DEC-003.md): Собственные логические области и права сервисов изолированы, без прямого чтения/записи чужих таблиц. Один физический сервер допустим; локальные транзакции API объединяют подписку, лимит и outbox. Определить durable хранение принятой рыночной работы и служебного состояния других владельцев.
- Указаны проверяемые требования к уникальности, транзакциям, миграциям и изоляции данных сервисов.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Проверка решения

Проверка на сценариях конкурентного лимита 15 и атомарного сохранения состояния с outbox.

Тип: решение, исполняемых тестов не требуется. Решение записать в `docs/decisions/` и обновить требования и зависимые карточки.

## Не входит

Реализация схем и настройка production-кластера.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).
