# OPS-065 — Проверить поколение Kafka-источника на входе notifications

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [OPS-064](OPS-064.md), [OPS-060](OPS-060.md), [SET-009](SET-009.md)

## Модель для сессии

- Модель: `gpt-6.1-sol`.
- Уровень размышления: `high` (High).
- Обоснование: Проверки metadata и каждого fetch должны закрыть смену topic до SQL приёма и ack.

Это рекомендация, а не смена модели; см. [MODELS](../MODELS.md).

## Один результат

Source-bound intake consumer, который проверяет Kafka source до приёма и восстанавливает только связанную с ним SQL-позицию.

## Критерии приёмки

- Использовать готовые kafkasource.Identity/Verify/CheckFetches и source-bound Store OPS-064. Config/assignment/resume явно несут ожидаемые consumer/generation/source; broker committed offset не заменяет SQL.
- Проверять metadata без auto-create при назначении, вокруг выбора позиции и периодически при пустом потоке. Проверять каждый исходный fetch TopicID до Records/decode/Accept, включая control records. Ошибочная/нулевая identity, недоступная metadata или mismatch останавливают экземпляр до SQL/ack; нынешняя metadata не становится provenance старого cursor.
- Назначение читает bound SQL cursor; неизвестный intake проходит только явный bootstrap OPS-064, а не скрытый INSERT через Checkpoint. Legacy/mismatch/потерянная история дают отказ без reset/skip. При смене group member сохраняется тот же logical consumer/generation.
- Сохранить read_committed, последовательный prefix, CAS/duplicate, job до broker ack, лимиты буферов/deadline, Run/Step/Close и join. Старый путь без source не должен обходить проверки; документировать переход вызывающего кода для OPS-066.
- Использовать существующие Kafka/PostgreSQL runners и управляемую wire границу, без нового универсального harness. Выполнить общие критерии готовности.

## Сценарии TDD (Red → Green → Refactor)

Реальные PostgreSQL/Kafka: commit/потерянный ack/restart/rebalance того же источника; delete/recreate только уникального disposable topic с тем же именем и перекрывающимися offsets; отказ старого consumer до job/ack. Проверка fetch mismatch data/control до Accept, metadata error/отмена/пустой поток. Команда: KAFKA_RUN_POSTGRES=1 bash infra/kafka/verify-go.sh.

## Не входит

Новая схема binding, cmd runtime/process wiring, exporter, перенос источника, cleaner и нагрузка.
