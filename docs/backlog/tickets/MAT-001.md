# MAT-001 — Применить версионированное изменение подписки

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [CON-002](CON-002.md), [DEC-003](DEC-003.md), [SET-005](SET-005.md), [SET-004](SET-004.md), [SET-010](SET-010.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Версионированная проекция должна переживать повторную доставку и рестарт; ack не может опередить сохранение.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Consumer, обновляющий локальную проекцию подписок.

## Критерии приёмки

- По [DEC-006](../../decisions/DEC-006.md): durable проекция и checkpoint изменения фиксируются одной транзакцией в собственной БД matcher до ack. Реальный PostgreSQL проверяет rollback и сбой между commit/ack; создание test harness не скрывается внутри consumer.

- По [ADR DEC-004](../../decisions/DEC-004.md): в проекции сохранены active/pending/sending/blocked и workflow; повтор старого события не отменяет доставку/отмену. Подключение к цене выполняется отдельным MAT-012.
- По [ADR DEC-003](../../decisions/DEC-003.md): Проекция принадлежит matcher и не является канонической подпиской. Источник изменений — API; восстановление использует его интерфейс снимка, прямой доступ к API-хранилищу запрещён.
- Дубли и старые версии не откатывают состояние; подтверждение после сохранения.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).
