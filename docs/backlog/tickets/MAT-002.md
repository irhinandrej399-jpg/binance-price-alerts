# MAT-002 — Находить кандидатов в индексе порогов

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [MAT-001](MAT-001.md), [DOM-003](DOM-003.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Индекс диапазонов должен правильно обрабатывать одинаковые пороги, направления и удаление, сохраняя смысл без полного перебора.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Индекс по паре и направлению, возвращающий только подходящий диапазон.

## Критерии приёмки

- Отмена удаляет порог; сравнение точное; полный перебор всех подписок на каждую цену отсутствует.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Тесты границ диапазона, одинаковых порогов, двух направлений, удаления; benchmark распределённого и горячего набора.

## Не входит

Вызов операции фиксации срабатывания.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).

## Передача следующей сессии

- Статус: `done`; незавершённой работы MAT-002 нет.
- Основные файлы: `internal/matcher/thresholdindex/index.go`, `index_test.go`, `README.md`. Entry копирует ID, SubscriptionVersion, Pair, *Threshold, Direction из актуальной durable проекции. Caller вызывает Put только для active, Remove для отмены/доставки/выхода из active; возвращение в active с workflow снова индексируется. Put безусловно заменяет ID; MAT-001 арбитрирует версии, caller сохраняет порядок принятых изменений. Исходные события нельзя применять к индексу в обход проекции.
- Индекс не сохраняет состояние/ack, не восстанавливается сам, не проверяет ценовую готовность и не разрешает отправку. Снимок/replay/перестроение/связь с проекцией/ценами и runtime отдельно. Canonical API проверяет Version и последнюю цену после выборки; кандидат может устареть сразу после возврата.
- Следующее действие по ORDER — сессионная проверка MAT-012 по новому поручению; здесь не начат. Использовать Candidates(pair, current) без требования нового пересечения. Нагрузка всего сервиса не подтверждена, внешние PostgreSQL/Kafka этим тикетом не запускались.
