# OPS-049 — Подготовить disposable окружение процесса market-data

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [SET-009](SET-009.md), [MKT-017](MKT-017.md), [MKT-013](MKT-013.md), [OPS-047](OPS-047.md), [DEC-010](DEC-010.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Изоляция market_data credentials, PostgreSQL/Kafka и child
  cleanup при отказах; lifecycle уже реализован в OPS-047.

Это рекомендация, а не смена модели; см. [MODELS](../MODELS.md).

## Один результат

Воспроизводимое disposable окружение и fixture для проверки отдельного
market-data child без реализации продуктового cmd/market-data.

## Критерии приёмки

- Используются существующие Compose/init/migrate: уникальные проекты,
  случайные loopback порты, prefix prices topic с принятой конфигурацией;
  применяются market_data migrations. Go/child получают только DSN этого
  владельца, Kafka и явные настройки; secrets не попадают в argv/вывод.
- Lifecycle переиспользует apiprocess.With/Config и PID registry из OPS-047;
  новый независимый process harness не создаётся. Runner имеет deadlines,
  --package для будущих cmd/market-data tests и cleanup по точным labels.
- Fixture на готовых storage.BeginGeneration/Accept возвращает canonical
  outbox key/value/event_id для проверки восстановления publish. Реальный
  read_committed consumer сравнивает bytes/ID после готового producer.
- Для raw ввода переиспользуются fixture trade.json и приёмы loopback WS
  серверов stream tests; проверена доступность WS из child. Это узкий
  test endpoint одного потока, не полный fake Binance E2E-003.
- На тестовом child подтверждены startup/readiness/exit/timeout и отсутствие
  PID/containers/volumes/networks после штатного и аварийного выхода владельца.
  Проверены права собственной БД и отсутствие чужих DSN в child окружении.
- README содержит команды и интерфейс для OPS-048/009; opt-in без доступных
  зависимостей падает, отсутствие opt-in явно SKIP. Рабочий стенд не трогается.

## Сценарии TDD (Red → Green → Refactor)

Disposable fixture и read_committed bytes; child читает loopback raw trade;
startup failure, timeout и аварийный owner exit с cleanup. Готовые проверки
lifecycle OPS-047 повторно не реализовывать.

## Ход работы

- `scripts/check_api_process.py`: общий runner принимает api (прежний default)
  или market_data. Применяет только миграции выбранного владельца и извлекает
  только его runtime credential. Сохраняет deadlines, случайные loopback порты,
  prefix topics из штатного init, PID registry и cleanup по exact labels.
- `scripts/check_marketdata_process.py`: тонкая обёртка существующего runner;
  default package marketprocess, --package для OPS-048/009. Сначала повторно
  использует готовые lifecycle tests apiprocess, не копирует их.
- `internal/testutil/marketprocess/fixture.go`: raw Decode → BeginGeneration →
  Accept; canonical key/value/event_id читаются из outbox без Claim.
  `raw.go`: loopback WS одного btcusdt@trade, исходный fixture trade.json,
  явное закрытие hijacked sockets; каталог/полный Binance не моделируются.
- `integration_test.go`: отдельный child читает raw bytes и декодирует сделку
  до readiness. При реальном opt-in он проверяет свою market_data_runtime
  identity/CONNECT и запрет CONNECT чужих БД; foreign DSNs/parent secret
  отсутствуют в явном окружении. Новый Repository восстанавливает pending
  bytes; готовый producer публикует их, read_committed consumer сравнивает
  key/value/event_id, затем проверяется отсутствие pending работы.
- Ownerexit fixture OPS-047 теперь принимает market-data opt-in; второй
  process harness не добавлен. README описывают env, команды, интерфейсы,
  границы и ограничения. Продуктовый cmd/market-data не изменялся.
