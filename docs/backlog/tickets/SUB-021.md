Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [SET-004](SET-004.md), [CON-002](CON-002.md), [DEC-006](DEC-006.md)

Выделен при принятии [DEC-006](../../decisions/DEC-006.md); реализация не входит в DEC.

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Общий адаптер обязан сохранять порядок commit и атомарность с вызывающей транзакцией при rollback и конкуренции.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора](../MODELS.md).

## Один результат

Один storage-адаптер append/read журнала API с транзакционным счётчиком C.

## Критерии приёмки

- Схема счётчика и неизменяемого журнала находится в БД API; append принимает транзакцию вызывающего, не выполняет независимый commit.
- Счётчик блокируется после бизнес-строк до commit/rollback; при нескольких событиях одной транзакции C указывает на её конец. Event ID устойчив, уникален, журнал содержит данные replay.
- Чтение хвоста строго после C не теряет поздний commit с меньшим номером; MAX(sequence_id) не используется как доказательство границы. Publish и удаление журнала — отдельные операции.
- Выполнена проверка ниже и [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Реальный PostgreSQL: rollback append вместе со счётчиком; T1 задерживает commit и T2 ждёт выдачи следующего номера; после rollback/commit видны только целые транзакции; уникальность event_id и чтение после C.

## Не входит

Переходы подписки, snapshot-builder/retention cleaner, брокер и relay.

## Размер сессии

Кандидат на одну сессию после готовности зависимостей и PostgreSQL test harness. Перед ready проверить [workflow](../workflow.md); отсутствующий harness или независимый adapter выделить отдельно.
