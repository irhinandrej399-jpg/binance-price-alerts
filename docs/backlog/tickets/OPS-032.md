# OPS-032 — Подключить и проверить temp peak observer в фазовом runner

Статус: `cancelled`. Приоритет определяется зависимостями, а не номером.

Зависимости: [OPS-036](OPS-036.md), [OPS-023](OPS-023.md)

Выделен из [OPS-030](OPS-030.md) 5 ноября 2026; использует готовый observer OPS-036.

## Снято с плана — 8 ноября 2026

По [DEC-011](../../decisions/DEC-011.md) задача отменена по поручению
пользователя: production ready для пет-проекта без тяжёлой квалификации.
Исходные критерии ниже — история, не требования к выпуску и не выполненная
работа. Не возобновлять через «некст тикет». Сохранённые raw и код не удалены.

## Модель для сессии

- Модель: `gpt-6.1-sol`.
- Уровень размышления: `high` (High).
- Обоснование: Межфазовые границы, два чистых опыта и проверка отказов требуют согласования collector и observer без изменения workload.

Это рекомендация, а не переключение модели. [Условия выбора](../MODELS.md).

## Один результат

Опциональный temp peak observer в существующем фазовом runner OPS-023,
проверенный на двух чистых disposable PostgreSQL volumes и общем control manifest.

## Критерии приёмки

- Подключить только готовые start/begin/end/finish и raw verifier OPS-036,
  сохранив business manifest protocol, штатные snapshots и durability.
  По умолчанию observer выключен; его отсутствие/отказ/неполное окно или
  неподдержанная операция блокируют соответствующую квалификацию, не дают ноль.
- На двух чистых volumes выполнить empty, принудительный SQL spill с удалением
  до after и перекрывающиеся spill двух сессий. Сохранить независимые held
  dev/inode/size свидетельства и cumulative temp_bytes/temp_files; сопоставить
  их с raw границами. Exact peak только при доказанной полноте и равенстве границ;
  unknown контрольного случая не засчитывать как точное измерение.
- Проверить coverage backend/workers в фазовых границах, включая готовые shared
  fileset контроли OPS-036; custom tablespaces либо покрыты, либо блокируют опыт.
  Cluster total не суммирует один inode по процессам/БД. Work-file apparent peak
  не объявляется allocated/device IO, cumulative bytes или SQL temp relations.
- Выполнить общий runner OPS-023 с control manifest и observer. Отказ observer,
  обрыв процесса и timeout adapter сохраняют failed/unknown report и raw;
  verifier отвергает неполную фазу/подменённые свидетельства. Cleanup containers,
  networks и volumes проверяется при успехе/отказе.
- Сохранить воспроизведение, версии/настройки/hash sources, raw и точные границы
  применимости/overhead. Старые raw не переписываются и не переквалифицируются.
  Уточнить документацию collector и ссылку на результат для OPS-018.

## Проверка

Два чистых PG опыта empty/spill/overlap, реальный совместный control manifest,
raw replay, отрицательные контроли и cleanup. Полный functional/race suite
не подменяет измерение; искусственные infrastructure unit-тесты не нужны.

## Не входит

Новый механизм capture/reconstruction (OPS-031), device IO, finite bounds,
максимальные бизнес-варианты, price downstream, ledger, полный DEC-008 fixture,
таблица стоимости/квоты и изменение ADR.
