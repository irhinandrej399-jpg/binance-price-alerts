# OPS-080 — Исследовать ранний выход matcher в source process fixture

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [OPS-062](OPS-062.md), [OPS-067](OPS-067.md)

## Модель для сессии

- Модель: `gpt-6.1-sol`.
- Уровень размышления: `high`.
- Обоснование: Локализовать отказ source-bound startup в готовом process fixture,
  сохраняя guards и различая загрязнение dataset, окружение и product defect.

Рекомендация, не переключение модели. [Условия выбора](../MODELS.md).

## Один результат

Безопасная диагностика раннего выхода `TestMatcherSourceProcess` на
существующем disposable стенде и успешная целевая регрессия. Историческая
причина E2E-007 остаётся неизвестной; исправление этой причины не заявляется.

## Воспроизведение

9 ноября 2026, E2E-007:

```sh
GOCACHE=/tmp/binance-go-build python3 scripts/check_matcher_process.py --package ./cmd/matcher
```

`TestMatcherProcess` PASS (94.88 s), включая SIGKILL/recovery и graceful;
следующий `TestMatcherSourceProcess` FAIL (19.76 s):
`cmd/matcher/source_process_test.go:90: process harness: exited before readiness`,
`exit status 1`. Это первый старт стабильной projection, до legacy fixture,
recreate topic и проверок mismatch. Общий runner exit 1; PID registry,
temporary credentials и оба Compose projects/volumes/networks удалены.
Локальный лог `/tmp/E2E-007-matcher.log`; его наличие в другой сессии не гарантировано.
Одновременно шли отдельные disposable Compose/notifications/E2E проверки;
влияние конкуренции, часов, порядка тестов и SQL истории не установлено.
Child diagnostic в текущем сообщении harness отсутствует. Обычный race suite
этот opt-in сценарий пропускает и не заменяет его успешный запуск.

## Критерии приёмки

- Добавить безопасные категории раннего выхода без DSN/секретов и проверить
  их на управляемом отказе; выполнить отдельный source и полный runner после
  recovery. Историческую причину разрешено оставить неизвестной.
- Для подтверждённого пробела диагностики выполнить Red → Green; сохранить
  source identity, legacy/mismatch/recreate и readiness assertions.
- Целевой и полный matcher process пакет проходят с race; cleanup подтверждён.
- Выполнены обычные CI и правила передачи/коммита. Без нового harness,
  нагрузки и увеличения TTL/timeout ради зелёного результата.

## Согласованное изменение критериев — 9 ноября 2026

Пользователь согласовал завершение по безопасной диагностике и успешной
регрессии с явно неизвестной исторической причиной. Требование обязательно
воспроизвести исходный случай снято: повторные зелёные прогоны без новой
гипотезы не дают новых фактов. При новом отказе штатной проверки расследовать
его по сохранённой категории в отдельном узком тикете с воспроизведением.
Это изменение объёма тикета, а не подтверждение исправления исходного сбоя.
