# MKT-019 — Подключить каталог торговых пар к runtime market-data

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [DEC-011](DEC-011.md), [MKT-016](MKT-016.md), [MKT-017](MKT-017.md), [OPS-069](OPS-069.md), [MKT-020](MKT-020.md), [E2E-008](E2E-008.md)

## Модель для сессии

- Модель: `gpt-6.1-sol`.
- Уровень размышления: `high`.
- Обоснование: Подключение готового reconciler к durable поколениям без ложного подтверждения feed.

Рекомендация, не переключение модели. [Условия выбора](../MODELS.md).

## Один результат

Runtime принимает цены поддерживаемых каталогом USDT-пар, а не только одной RAW_TRADE_PAIR.

## Критерии приёмки

- Использовать существующие catalog, streamplan и stream reconciler через их интерфейсы. Согласовать поддерживаемый набор между Catalog API и фактическими потоками: пользователь не создаёт подписку на пару, которая никогда не обслуживается.
- Подключить refresh каталога, сохранение latest/outbox для каждой пары, reconnect и graceful shutdown. Удалённые из каталога пары обрабатываются явно, сохранённые подписки и данные не удаляются молча.
- Сохранить fencing поколений, дедупликацию, время сделки, sticky gap и предупреждения. Не устанавливать live по одному dial/первой сделке и не править SQL в тесте ради readyz=200; документировать операционную готовность при unconfirmed.
- На существующем fake Binance: две пары получают разные цены, добавление/удаление пары отражается в плане, reconnect и остановка не теряют уже принятый outbox. Один небольшой процессный прогон; без всего каталога под нагрузкой.

## Проверка

Только относящиеся к изменению unit/integration проверки, один небольшой smoke
на имеющихся средствах и обязательные проверки CI. Для поведения Red → Green;
для deployment/docs — проверка команд и фактического запуска, без искусственных
unit-тестов. Отсутствующую предпосылку не разрабатывать скрытно.

## Границы и сессионная проверка

Изменения в cmd/market-data и связанных настройках; если отсутствует независимый adapter, выделить предпосылку до реализации. Новые collectors и нагрузка не входят.

Перед ready сверить фактические интерфейсы и размер по [workflow](../workflow.md).
При независимых результатах разделить; новая рекомендация модели объём не заменяет.

## Ход работы

- 8 ноября 2026: выбран через `backlog.py next`, прочитаны skill, STATE,
  WORKING, workflow, MODELS, прямые зависимости и фактические интерфейсы.
  Рекомендация Sol / High сообщена. Существующие untracked measurement и
  infra artifacts сохранены; tracked diff до проверки отсутствовал.
- Сессионная проверка не пройдена; planned → ready не выполнялся.
  `storage.BeginGeneration` обязателен до каждого нового соединения.
  `stream.NewReconciler` принимает общий handle и observer без context;
  `planGroup.attempt` вызывает readWithCommands без PrepareAttempt.
  При reconnect невозможно привязать callbacks к durable поколению попытки
  через существующий публичный интерфейс. В отличие от него, фиксированный
  runtime использует ReconnectPrepared и attempt-bound callbacks.
- Второй недостающий результат: `binancefake.serve` принимает только
  /ws/btcusdt@trade и /ws/solusdt@trade; /ws возвращает 404, входящие
  сообщения игнорируются. Каталог встроенный и неизменяемый. Private fixture
  из reconcile_test.go не является доступным процессному smoke helper.
- По границам карточки выделены MKT-020 (lifecycle reconciler) и E2E-008
  (расширение существующего fake), зависимости и ORDER синхронизированы.
  Новая архитектура, runtime и новый универсальный harness не реализовывались.
- Проверки: `backlog.py show MKT-019` подтвердил done исходных зависимостей;
  артефакты MKT-016/017/OPS-069 и DEC-011 прочитаны. Итоговые проверки
  `python3 scripts/backlog.py check` — PASS (173 done, 9 planned, 22 cancelled,
  18 split); `git diff --check` — PASS; `backlog.py next --limit 3` подтвердил
  MKT-020 → E2E-008 → MKT-019 и ожидание двух зависимостей. Go/Docker не запускались:
  изменены только план и передача, Red/Green реализации ещё не выполнялись.

  reconnect, durable gap и остановка. Не объявлять ACK или первую сделку live.
- Проверять на расширенном binancefake: две разные цены, добавление/удаление,
