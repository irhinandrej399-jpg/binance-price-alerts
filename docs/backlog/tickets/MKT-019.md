# MKT-019 — Подключить каталог торговых пар к runtime market-data

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [DEC-011](DEC-011.md), [MKT-016](MKT-016.md), [MKT-017](MKT-017.md), [OPS-069](OPS-069.md), [MKT-020](MKT-020.md), [E2E-008](E2E-008.md)

## Модель для сессии

- Модель: `gpt-6.1-sol`.
- Уровень размышления: `high`.
- Обоснование: Подключение готового reconciler к durable поколениям без ложного подтверждения feed.

Рекомендация, не переключение модели. [Условия выбора](../MODELS.md).

## Один результат

Runtime принимает цены поддерживаемых каталогом USDT-пар, а не только одной RAW_TRADE_PAIR.

## Критерии приёмки

- Использовать существующие catalog, streamplan и stream reconciler через их интерфейсы. Согласовать поддерживаемый набор между Catalog API и фактическими потоками: пользователь не создаёт подписку на пару, которая никогда не обслуживается.
- Подключить refresh каталога, сохранение latest/outbox для каждой пары, reconnect и graceful shutdown. Удалённые из каталога пары обрабатываются явно, сохранённые подписки и данные не удаляются молча.
- Сохранить fencing поколений, дедупликацию, время сделки, sticky gap и предупреждения. Не устанавливать live по одному dial/первой сделке и не править SQL в тесте ради readyz=200; документировать операционную готовность при unconfirmed.
- На существующем fake Binance: две пары получают разные цены, добавление/удаление пары отражается в плане, reconnect и остановка не теряют уже принятый outbox. Один небольшой процессный прогон; без всего каталога под нагрузкой.

## Проверка

Только относящиеся к изменению unit/integration проверки, один небольшой smoke
на имеющихся средствах и обязательные проверки CI. Для поведения Red → Green;
для deployment/docs — проверка команд и фактического запуска, без искусственных
unit-тестов. Отсутствующую предпосылку не разрабатывать скрытно.

### Реализация — 8 ноября 2026

- Повторная сессионная проверка пройдена: MKT-020 даёт
  NewPreparedReconciler/Wait и immutable callbacks, E2E-008 — bare /ws,
  управляемый каталог и TradePair. Артефакты остальных done зависимостей
  и DEC-011 сверены с кодом; отсутствующих adapters нет. planned → ready →
  in-progress → done. Рекомендация Sol / High сообщена, модель не переключалась.
- `main.go`, `catalog_runtime.go`: bare RAW_TRADE_URL=/ws, фиксированная пара
  убрана. Catalog RPC и streamplan/reconciler используют общий snapshot.
  Поддерживаются только `^[A-Z0-9]+USDT$` по существующему ASCII контракту
  storage/PriceObserved; Unicode и прочие неподдерживаемые символы исключаются
  из обоих интерфейсов. Дубли объединяются. SQL/контракты не менялись.
- Refresh по умолчанию 1m, CATALOG_REFRESH_INTERVAL=100ms..1h; первый Fetch
  обязателен. HTTP-ошибка сохраняет последний план и UpdatedAt. Новые пары
  видны после ACK, удалённые снимаются с RPC до отписки. Пустой snapshot
  снимает все потоки. Reconciler управляет группами до 1024 и reconnect.
- До Latest RPC fence-ятся все сохранённые пары, включая удалённые за downtime;
  перед каждым dial готовятся поколения каждой пары группы. Retired callbacks
  отмечают gap до новых владельцев. Shutdown присоединяет все компоненты,
  сохраняет fenced gap для всех известных поколений; latest/outbox/подписки
  удалённых пар не удаляются. Revision, source дедупликация и времена сохранены.
- Обнаруженная внутри результата ошибка SIGTERM: Wait возвращает точный
  context.Cause от signal.NotifyContext (`signal.signalError`), а прежний
  владелец распознавал только context.Canceled. Теперь только точная причина
  отмены родителя считается штатной; независимые terminal errors сохраняют
  exit failure. Диагностика называет компонент без remote error/payload.
- `catalog_runtime_test.go`: ASCII фильтр, владение snapshot/withdrawal,
  cancelled Fetch, настоящий loopback refresh 503 с сохранением snapshot и
  успешный пустой каталог. `zcatalog_process_test.go`: один малый race executable
  на binancefake, 2 → 3 → 2 пары, разные точные цены, Catalog RPC, время сделки,
  removed quote/gap, reconnect, duplicate source и неизменные четыре outbox
  после exit 0. Сценарий идёт после прежних fixtures общего disposable dataset.
- Прежние cmd process tests переведены на готовый subscription-aware fake
  (`feed_test.go`), shutdown fixture подтверждает SUBSCRIBE перед сделкой.
  RPC проверяет доступность применённого snapshot во время held refresh и
  отмену HTTP при SIGTERM. E2E stack/scenario конфигурация переведена на /ws,
  ожидание ACK и TradePair; отдельный полный четырёхпроцессный E2E не повторялся.
- README описывает настройки, поддерживаемый набор, удаление/возврат пары,
  сохранение данных и операционное ожидание /healthz=200 + Catalog/Latest при
  /readyz=503/unconfirmed. ACK/сделка не устанавливают live.
