# SUB-016 — Открыть внутренний интерфейс страниц снимка

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [SUB-015](SUB-015.md), [SUB-023](SUB-023.md), [DEC-003](DEC-003.md), [DEC-009](DEC-009.md)

Разделённый исходный тикет: [SUB-010](SUB-010.md).

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `medium` (Medium).
- Обоснование: Сетевая выдача использует готовый storage-снимок; остаются аутентификация, cursor и стабильные ошибки контракта.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Один защищённый интерфейс выдачи страниц готового снимка.

## Критерии приёмки

- По [DEC-009](../../decisions/DEC-009.md): внутренний интерфейс реализуется как unary gRPC с Protocol Buffers, сервисными полномочиями и конечным deadline; изменяющие операции сохраняют идемпотентность. Контрактные проверки включают сетевой адаптер, deadline и недоступность зависимости. Перед ready проверить готовность генерации и test harness; отсутствующие общие предпосылки выделить отдельно.

- По [ADR DEC-004](../../decisions/DEC-004.md): истечение явно отличимо от пустой страницы; страницы имеют одну границу C и snapshot_id, объявленный expires_at; cursor цен не смешивается с журналом подписок.
- По [ADR DEC-003](../../decisions/DEC-003.md): Снимок выдаёт API как владелец подписок; matcher строит собственную проекцию, не читая таблицы API напрямую.
- Cursor и идентификатор снимка сохраняются в ответах; невалидный или истёкший cursor отклоняется; прямого доступа matcher к БД нет.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Contract-тесты первой и следующей страницы, неверного cursor и неавторизованного клиента.

## Не входит

Консистентность storage-снимка и восстановление matcher.

## Размер сессии

Сессионная проверка 28 октября 2026 не пройдена: для первого сетевого запроса нужен идемпотентный builder. Выделена storage-предпосылка SUB-023; до её завершения статус planned.

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).
