# E2E-005 — Подготовить общее disposable окружение четырёх сервисов

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [OPS-047](OPS-047.md), [OPS-049](OPS-049.md), [OPS-052](OPS-052.md), [OPS-054](OPS-054.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `medium` (Medium).
- Обоснование: Расширение готового disposable runner на четыре владельца с проверкой изоляции и cleanup; новый lifecycle и бизнес-логика не требуются.

Это рекомендация, а не смена модели; см. [MODELS](../MODELS.md).

## Один результат

Одна команда disposable PostgreSQL/Kafka окружения для общего Go-пакета проверки четырёх сервисов, с четырьмя parent-only DSN и штатными миграциями.

## Критерии приёмки

- Переиспользованы Compose/init/migrate и lifecycle/PID registry OPS-047. Уникальные проекты, loopback порты и topic prefix; рабочие проекты/данные не адресуются. Нынешние runner-режимы сохраняют свои контракты.
- Применены только штатные миграции api, market_data, matcher, notifications. Test-only SQL для fault/reset registry общего E2E не требуется и не устанавливается.
- Родитель получает DATABASE_URL, MARKET_DATA_DATABASE_URL, MATCHER_DATABASE_URL, NOTIFICATIONS_DATABASE_URL, KAFKA_TEST_BROKER, KAFKA_TEST_PREFIX и явный opt-in общего окружения. Унаследованные настройки приложения удалены, secrets не попадают в argv/вывод; child Env по-прежнему задаётся allowlist со своим единственным DSN.
- Qualification-пакет подключается каждой runtime ролью к своей БД, проверяет имя БД/роли и запрет CONNECT к трём чужим БД. Настоящая Kafka содержит три штатных topics; Metadata подтверждает ClusterID/TopicID и 16/1/16 partitions prices/changes/delivery. Discovery относится только к новым пустым topics, старые offsets им не связываются.
- Deadlines и cleanup после успеха, ошибки и аварийного Go owner exit подтверждены: зарегистрированные child groups, containers, volumes, networks и временные credentials удалены. Использовать существующий ownerexit/lifecycle, без второго process supervisor.
- Без opt-in integration test явно SKIP; с opt-in отсутствие DB/Kafka — FAIL. README фиксирует точную команду и интерфейс для E2E-002; реальный race-прогон и повторный запуск подтверждают изоляцию/cleanup.
- Выполнены [общие критерии готовности](../workflow.md).

## Проверка / воспроизведение

Общая команда runner дважды с новой disposable инфраструктурой; проверки четырёх runtime ролей и трёх topics, затем намеренно аварийный Go owner exit с проверкой cleanup. Для поведения runner/helper соблюдать Red → Green → Refactor; инфраструктуру проверять реальным запуском.

## Не входит

Сборка/оркестрация четырёх продуктовых executable, fake Binance/Telegram, общая PKI/конфигурация процессов, SQL bootstrap notifications и prices vector matcher, пользовательский сценарий, продуктовые обработчики и нагрузка. Эти настройки и вызовы готовых provisioning-интерфейсов остаются в E2E-002; пользовательский сценарий — E2E-001.

## Размер сессии

Кандидат на одну сессию после проверки кода runner и готовых lifecycle helpers. Один результат — общая инфраструктурная предпосылка; готовность четырёх процессов здесь не объявляется.
