# SUB-024 — Исследовать нестабильный expiry в SQL snapshot RPC тестах

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [SUB-016](SUB-016.md), [SET-006](SET-006.md)

## Уточнение объёма — 8 ноября 2026

По [DEC-011](../../decisions/DEC-011.md) задача остаётся: это конкретный дефект
прав, поведения или обычной интеграционной проверки. Проверить причину и
узкое исправление на существующем fixture, выполнить относящиеся regression
тесты и штатный CI. Нагрузочные/длительные стресс-повторы, новый общий harness
и многократные полные suite не нужны. Защитные assertions и production guards
сохраняются; неизвестную причину не выдавать за «просто flaky».

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Нужно локализовать нерегулярный отказ expiry между SQL и RPC, сохранив реальные проверки срока и отмены.

## Один результат

Воспроизводимая диагностика и узкое исправление причины нестабильных SQL snapshot RPC проверок; без изменения продуктовой политики срока снимка.

## Наблюдение и воспроизведение

29 октября 2026 при MAT-016: `python3 scripts/check_postgres.py` (disposable PostgreSQL,
`-p=1 -race -count=1`) в первом прогоне успешно выполнил snapshot RPC тесты,
во втором получил `rpc error: code = FailedPrecondition desc = snapshot unavailable;
restart bootstrap with new request ID` в
`internal/api/snapshotrpc/postgres_test.go:80` (TestPostgresSnapshotRecoveryOverTLS)
и `:208` (TestPostgresCanceledBuildOverTLS). Тесты MAT-016 прошли.
Изменения MAT-016 касаются отдельной matcher БД, API-код/миграции не менялись.
Причина не установлена; expiry/часы/окружение — гипотезы. Одно последующее
измерение UTC epoch на хосте и в disposable контейнере совпало в пределах секунды,
но это не доказывает состояние часов в момент отказа.

## Критерии приёмки

- Локализована проверка, возвращающая отказ: SQL BuildRequest/Page или RPC expires_at; сохранены безопасные диагностические времена и последовательность операций без DSN/паролей.
- Есть управляемое воспроизведение причины и Red → Green узкого исправления либо доказанное ограничение окружения с воспроизводимой проверкой предусловий.
- Сохраняются проверки реального expiry, потерянного ответа после commit и отменённого SQL-lock. Не маскировать проблему удалением проверок или безусловным увеличением TTL.
- Целевые SQL-тесты на disposable PostgreSQL с race detector проходят; описан фактический результат и cleanup.
- Выполнены [общие критерии готовности](../workflow.md).

## Не входит

Хранилище matcher MAT-016, новая snapshot-архитектура, runtime, нагрузка и изменение продуктовых TTL.

## Размер сессии

Один сбой в существующем SQL/RPC harness. Перед ready проверить локализацию;
если требуется отдельное исправление окружения, уточнить границу до реализации.

## Передача следующей сессии

- Статус: done. Результат — воспроизводимая диагностика SQL/RPC expiry и проверка
  часовых предусловий. В объёме этой диагностической ветки действий не осталось.

  expires_at; успешный Page и отказ RPC локализуют финальную Go-проверку,
  ErrSnapshotLost до неё локализует SQL. Не отключать guards и не увеличивать TTL.

  Если clock prerequisite FAIL — проверить часы host/Docker VM и задержку замера;
  это не успешный expiry-тест и не основание менять продуктовую политику.
