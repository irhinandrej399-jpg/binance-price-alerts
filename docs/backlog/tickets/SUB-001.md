# SUB-001 — Сохранить подписку с версией состояния

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [SET-004](SET-004.md), [DOM-001](DOM-001.md), [DOM-004](DOM-004.md), [DEC-003](DEC-003.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `medium` (Medium).
- Обоснование: Один persistence-контракт использует готовые доменные типы; важны round-trip точности и фильтр владельца.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Схема подписки, примитив вставки полного after-image и операция чтения по ID владельца.

## Критерии приёмки

- По [DEC-006](../../decisions/DEC-006.md): точные десятичные пороги и версии сохраняются в PostgreSQL API; ограничения workflow/attempt и ключи идемпотентности не допускают дублей. На этом шаге PK подписки и UNIQUE ссылки workflow защищают их идентичность; таблицы workflow/attempt и идемпотентность команд реализуются в SUB-013/017/019. Общий журнал реализуется отдельно в SUB-021, не внутри round-trip подписки.

- По [ADR DEC-004](../../decisions/DEC-004.md): канонические состояния/ссылки на workflow соответствуют DEC-004; запись сохраняет все незавершённые состояния и ссылку workflow для будущего снимка SUB-015, а цена создания не служит TTL/разрешением отправки.
- По [ADR DEC-003](../../decisions/DEC-003.md): Каноническая подписка и её версия хранятся в области API; matcher получает данные через события/интерфейс снимка, без прямого чтения таблиц.
- Хранятся пара, порог, направление, исходная цена/процент при наличии, состояние, версия и граница активации.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

SUB-001: три верхнеуровневых теста, шесть состояний, 21 сценарий ограничений. Проверены 18-й дробный знак/максимальный порог/минимальная цена, оба направления, nil и знаковый процент, workflow и blocked, версия MaxInt64, предупреждения, чужой/отсутствующий ID, duplicate, commit/rollback, отмена и безопасная ошибка invalid UUID. Прямой SQL отклоняет лишнюю точность без округления, переполнение/отрицательный порог/NaN, некорректные поля, NULL, отсутствующий workflow/данные blocked и бесконечное время.

Предварительная попытка пустого GOPATH в /tmp не прошла: зависимости там отсутствовали при GOPROXY=off; итоговые проверки использовали существующий cache без скачивания.
