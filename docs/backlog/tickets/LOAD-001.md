# LOAD-001 — Сгенерировать воспроизводимые данные нагрузки

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [DEC-008](DEC-008.md), [SUB-001](SUB-001.md), [IAM-001](IAM-001.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `medium` (Medium).
- Обоснование: Генератор должен воспроизводить seed, объём и лимит 15, а также загружать данные без подмены модели нагрузки.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Генератор синтетических аккаунтов и подписок с фиксированным seed.

## Критерии приёмки

- По [DEC-008](../../decisions/DEC-008.md): seed 8008, 100 000 аккаунтов по 10 подписок; отдельный набор по 15. Каталог 100 пар, 50% подписок на горячей паре, баланс направлений/типов порога и отдельный API-churn пул; сохранить алгоритм PRNG и checksum fixture. Контрольные подписки помечены для эталона; загрузка учитывает будущую ёмкость и не входит в измеряемую фазу.

- Есть профиль 100000 аккаунтов/1000000 активных подписок; у каждого ≤15; отдельный worst-case профиль до 1500000.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Проверка / воспроизведение

На малом наборе проверить число, владельцев и пороги; большой набор создаётся только в выделенном стенде.

## Не входит

Измерение пропускной способности.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).
