# OPS-021 — Измерить manifest продолжения API в matcher и notifications

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [OPS-019](OPS-019.md), [OPS-020](OPS-020.md), [SUB-009](SUB-009.md), [SUB-020](SUB-020.md), [NTF-013](NTF-013.md)

Выделен из [OPS-017](OPS-017.md) при проверке размера 4 ноября 2026.

## Модель для сессии

- Модель: `gpt-6.1-sol`.
- Уровень размышления: `high` (High).
- Обоснование: Связанные идентичности и отказные продолжения требуют контроля транзакций и измерительных границ.

Это рекомендация, а не переключение модели. [Условия выбора](../MODELS.md).

## Один результат

Воспроизводимый manifest и runner измерения цепочки обязательств API через готовые adapters с отчётом обоих collectors.

## Критерии приёмки

- Определить версионированный manifest входных размеров и максимальных batch существующих adapters. Зафиксировать ID источника, event_id/trigger_id/attempt_id и последовательность create, первого workflow, отмены, admission/исходов, journal/outbox, matcher checkpoint/job и notifications служебных переходов. Полноту покрытия отразить явно; неизмеренный класс блокирует OPS-018.
- Вызывать реальные adapters под собственными runtime-ролями; готовые loopback mTLS/HTTP и fault helpers переиспользовать без runtime четырёх процессов и внешних Binance/Telegram. SQL другой БД доступен только диагностическому runner.
- Использовать OPS-019/020 вокруг отдельных фаз: повторные версии, первая публикация, потерянный commit-ответ и физический дубль. Устойчивые ID связывают затраты источника с продолжением, фоновые записи и setup отделены. Измерительная фаза не запускает полный функциональный race suite.
- Сохранить manifest, версии схем/контрактов/образов, команды, сырые снимки, отчёт и ограничения. Проверить пустой контроль, реальную запись и повтор с чистого состояния; валидировать формат отчёта и полноту обязательных метрик. Unsupported или непокрытая фаза не получает статус qualified.

## Проверка

Disposable стенд; контрольные опыты и проверка сырых данных/формата отчёта по критериям выше. Для инфраструктуры искусственные unit-тесты не нужны. Функциональный race runner не заменяет измерений.

## Не входит

Сборщики метрик, market-data источник, квоты/таблица стоимости, ledger и полный нагрузочный fixture.

## Размер сессии

Перед ready проверить интерфейсы зависимостей и один измерительный проход. Если нужен новый независимый механизм, сначала уточнить границу, не скрывать его в опыте.
