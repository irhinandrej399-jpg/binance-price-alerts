Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [MAT-013](MAT-013.md), [SET-009](SET-009.md), [DEC-007](DEC-007.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Жизненный цикл Kafka group, ограниченный поток и отмена требуют проверки конкурентности и порядка.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Kafka consumer group распределяет фиксированные ценовые партиции и выдаёт ограниченный read_committed поток с явным жизненным циклом назначения. SQL fencing подключается caller через интерфейс MAT-017 в MAT-010.

## Критерии приёмки

- Используется выбранный franz-go и реальный Kafka group protocol, auto-commit отключён. Назначение/отзыв/потеря наблюдаемы; при отзыве прекращаются выдача старой работы и подтверждение от прежнего назначения. Ошибка подготовки назначения не разрешает работу.
- Два живых клиента одной группы после стабилизации получают непересекающееся полное множество 16 партиций prices; отображение пары совпадает с producer и не меняется от rebalance. Конфигурация/метаданные с другим числом партиций отклоняются явно.
- Групповой источник совместим с Register → LSO barrier → Latest MAT-012. Один управляемый путь чтения/dispatch; независимый бесконтрольный direct reader не считается групповым владением. Старые регистрации инвалидируются при отзыве назначения.
- Caller получает исходные позиции и все read_committed записи назначенных партиций, включая пары без регистрации, чтобы позднее доказать общий Prefix. Очереди ограничены; переполнение/потеря позиции/невалидный контракт дают явный отказ без skip/ack. Сохраняются ограничения MAT-013.
- Явное подтверждение принимает только разрешённую позицию текущего назначения после сигнала caller о durable SQL commit. Broker committed offset не подменяет SQL-checkpoint; предоставлен способ начать с позиции caller без автоматического reset на latest при утрате доступного диапазона.
- Точки установки/отзыва полномочий не блокируют group polling/heartbeat бесконечно, учитывают context; отмена/Close завершают reader и регистрации. SQL-выдача token, полнота бизнес-результата и recovery остаются в MAT-017/010/011.
- Выполнены проверки и [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

На существующем disposable Kafka (`bash infra/kafka/verify-go.sh`, добавить пакет в существующий Go-прогон): две живые реплики, 16 партиций и контролируемые пары/offsets, полный непересекающийся assignment и порядок пары; запрет работы не своей партиции, Register/Latest barrier, revoke/Close/cancellation, read_committed commit/abort, ограничение буфера, ошибочная позиция и явный commit только актуального назначения. Это проверка транспорта, не доказательство SQL fencing или failover matcher.
