# MAT-009 — Возобновить проекцию с сохранённого cursor

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [MAT-008](MAT-008.md)

Разделённый исходный тикет: [MAT-003](MAT-003.md).

## Модель для сессии

- Модель: `gpt-6-astra` (GPT-6 Astra).
- Уровень размышления: `high` (High).
- Обоснование: Cursor должен соответствовать durable проекции при сбое в любой точке; нужны безопасные replay и fallback на bootstrap.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Один restart-путь согласованной проекции и cursor.

## Критерии приёмки

- По [DEC-006](../../decisions/DEC-006.md): cursor восстанавливается вместе с durable поколением проекции из БД matcher; индекс в памяти перестраивается. Сбой до/после commit не создаёт cursor впереди применённых данных; используется готовый storage-контракт MAT-001/MAT-007.

- По [ADR DEC-004](../../decisions/DEC-004.md): после восстановления последняя цена проверяется заново; durable workflow не теряется, но прошлые исчезнувшие условия не восстанавливаются.
- Cursor не опережает сохранённое состояние; при невалидном cursor используется определённый bootstrap; replay дублей безопасен.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Падение до и после сохранения cursor, повтор последнего события и истёкший cursor дают согласованную проекцию.

## Не входит

Выбор нового протокола snapshot/replay и владение партициями.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).
