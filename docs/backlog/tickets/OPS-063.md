# OPS-063 — Проверить provenance prices scope до первого transport checkpoint

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [OPS-061](OPS-061.md)

Выделен при сессионной проверке [OPS-062](OPS-062.md).

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Read-only MVCC-проверка SQL provenance должна отличить пустой scope от legacy и чужого binding, сохраняя независимость cursor и Pending.

Это рекомендация, а не смена модели; см. [MODELS](../MODELS.md).

## Один результат

Read-only API pricework для проверки происхождения всего стабильного prices
scope перед выбором bootstrap, в том числе когда transport cursor ещё не создан.

## Критерии приёмки

- Различать доказанно пустой scope, bound scope без cursor, bound checkpoint
  и legacy state. Учитывать любой исторический work (pending/completed/superseded,
  включая Latest без Position), checkpoint и source ledger в одной SQL-view.
- Сверять expected Source/Topic/Partition с durable binding до возврата позиции
  либо разрешения явного caller bootstrap. Другой source — ErrMismatch,
  исторический unbound work/checkpoint — ErrUnbound, SQL fault — явная ошибка.
  Не присваивать expected identity старым строкам, не записывать binding при
  чтении, не выдумывать Kafka offset из Latest, C или самого наличия binding.
- Сохранить стабильный scope, grant/fencing, все bytes/состояния/исходы и текущий
  контракт ReadCheckpoint (без transport cursor подтверждённого offset нет).
  Bootstrap остаётся выбором caller; новое чтение даёт необходимые факты.
- Проверить два pool/takeover и взаимодействие с готовыми source/legacy guards:
  read-only проверка не заменяет атомарную проверку при Accept/Complete.
  Учитывать legacy work до миграции; существующий disposable runner достаточен.
- Описать публичный API и точное применение в replica.prepare для OPS-062.
  Выполнены [общие критерии готовности](../workflow.md).
