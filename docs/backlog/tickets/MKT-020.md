# MKT-020 — Добавить lifecycle попытки в stream reconciler

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [MKT-016](MKT-016.md), [OPS-050](OPS-050.md)

Выделен при сессионной проверке [MKT-019](MKT-019.md) 8 ноября 2026.

## Модель для сессии

- Модель: `gpt-6.1-sol`.
- Уровень размышления: `high`.
- Обоснование: Контекст попытки, fencing callbacks и конкурентные изменения плана.

Рекомендация, не переключение модели. [Условия выбора](../MODELS.md).

## Один результат

Публичный lifecycle reconciler позволяет runtime подготовить durable поколение
до открытия соединения и связать обработку данных/разрыва с этой попыткой.

## Критерии приёмки

- Использовать существующий PrepareAttempt либо совместимый узкий интерфейс;
  подготовка выполняется до dial при первом запуске, reconnect и ротации.
- Учитывать изменение набора пар на действующем соединении: caller получает
  достаточно информации для подготовки добавляемых пар до их допуска,
  удаления/перемещения не оставляют callbacks старого владельца действующими.
- Ошибка подготовки не допускает dial/подписку/приём без fencing token;
  observer имеет отменяемый context, ошибки durable записи не теряются.
- Close/отмена присоединяют callbacks и workers; terminal failure наблюдаем
  владельцем runtime, включая после завершения очередного Reconcile.
- Сохранить совместимость текущих пользователей, ACK/retry/лимитер и запрет
  интерпретировать успешную подготовку или ACK как live.

## Проверка

TDD на существующем loopback fixture stream/reconcile_test.go: подготовка до
первого dial, новая попытка после disconnect, ошибка подготовки, изменение
плана и Close с ожидающим callback. Проверить привязку данных/разрыва к
попытке, а не чтение текущего token из общей переменной. Целевой race и CI.
