# CON-001 — Определить общий конверт события

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [DEC-007](DEC-007.md), [SET-001](SET-001.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `medium` (Medium).
- Обоснование: Требуется компактный версионированный конверт и проверка ошибочных метаданных, без проектирования всех событий сразу.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Версионированный формат метаданных события.

## Критерии приёмки

- По [DEC-007](../../decisions/DEC-007.md): устойчивый event_id не меняется при повторе SQL-outbox; ключ пары, ревизия/поколение цены и C/конец транзакции API — разные поля и шкалы, Kafka offset не заменяет C. Конкретные payload остаются CON-002/003/004.

- Есть event_id, тип, версия, время, correlation_id и ключ порядка; неизвестная версия отклоняется явно.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Contract-тесты корректного сообщения, отсутствующего ID и неизвестной версии.

## Не входит

Схемы payload всех событий сразу.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).
