# OPS-050 — Открыть границу каждой попытки WebSocket reconnect

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [MKT-011](MKT-011.md), [MKT-012](MKT-012.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Граница попытки должна сериализовать callbacks, ошибки и отмену
  без регрессии reconnect/rotation и без смешивания поколений.

Это рекомендация, а не смена модели; см. [MODELS](../MODELS.md).

## Один результат

Узкое расширение stream.Reconnect: вызывающий код подготавливает отдельные
callbacks каждой попытки до dial, чтобы runtime мог выполнить durable
BeginGeneration и привязать обработку к возвращённому поколению.

## Критерии приёмки

- Синхронная подготовка вызывается до первого и каждого повторного dial,
  в том числе после dial failure, transport loss, serverShutdown и rotation.
  Она получает context и может вернуть ошибку: тогда dial не выполняется,
  ошибка сохраняет errors.Is и завершает владельца без сетевых повторов.
- Подготовка возвращает callbacks обработки/разрыва конкретной попытки.
  Предыдущая попытка, её writer и callbacks завершены до подготовки следующей;
  payload новой попытки никогда не получает callbacks прежней. Callback разрыва
  должен позволять передать ошибку durable SetStatus владельцу без проглатывания.
- Уже отменённый context не вызывает подготовку/dial; отмена во время
  подготовки учитывается до dial. Callback обязан соблюдать context.
- Существующий API Reconnect и его семантика сохраняются; новый API использует
  те же retry/backoff/jitter, rotation, scheduler и очистку соединения,
  без второго независимого цикла переподключения.
- Контракт documented в stream/README.md, unit/fake-clock и loopback WS tests
  подтверждают границу/порядок и ошибочные пути; существующие stream tests проходят.

## Сценарии TDD (Red → Green → Refactor)

Подготовка до наблюдаемого server handshake; failure подготовки без dial;
первый dial failure → новая подготовка; обрыв/rotation/serverShutdown → новая
попытка со своими callbacks; terminal handle/disconnect error; отмена перед
стартом и во время подготовки; прежний handler завершён до нового поколения.
Проверка: `GOCACHE=/tmp/binance-go-build GOTOOLCHAIN=local go test -race
-count=1 ./internal/marketdata/stream` с доступом к loopback.

## Не входит

SQL/BeginGeneration внутри транспорта, политика live, cmd/market-data,
новый process harness, backfill, динамический каталог и graceful OPS-009.
