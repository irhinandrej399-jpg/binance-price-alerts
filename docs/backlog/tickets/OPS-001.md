# OPS-001 — Добавить health и readiness API

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [SET-001](SET-001.md), [DEC-003](DEC-003.md)

## Модель для сессии

- Модель: `gpt-6-luna` (GPT-6 Luna).
- Уровень размышления: `high` (High).
- Обоснование: Health/readiness одного API опирается на готовые сигналы зависимостей и несколько ограниченных сценариев.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Проверки жизнеспособности и готовности API.

## Критерии приёмки

- По [ADR DEC-003](../../decisions/DEC-003.md): API владеет аккаунтами, подписками и outbox; readiness использует сигналы собственных зависимостей, без проверки чужих таблиц. Точный обязательный набор определяется готовыми контрактами и инфраструктурой.
- Liveness не зависит от краткого сбоя внешнего API; readiness учитывает обязательные зависимости API.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Тесты доступного и недоступного хранилища и запуска до завершения инициализации.

## Не входит

Healthchecks остальных процессов.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).
