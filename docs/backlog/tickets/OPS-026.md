# OPS-026 — Измерить продолжение API в notifications и свести цепочку

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [OPS-025](OPS-025.md), [NTF-013](NTF-013.md), [NTF-014](NTF-014.md), [NTF-015](NTF-015.md)

Выделен из [OPS-021](OPS-021.md) при сессионной проверке 4 ноября 2026.

## Модель для сессии

- Модель: `gpt-6.1-sol`.
- Уровень размышления: `high` (High).
- Обоснование: Durable outcomes, recovery и replay отчётов требуют связать попытки с источником и проверить полноту цепочки.

Это рекомендация, а не переключение модели. [Условия выбора](../MODELS.md).

## Один результат

Manifest затрат notifications и единый отчёт покрытия цепочки API → matcher/notifications.

## Критерии приёмки

- Через runner OPS-023 и готовые intake/jobs/handler/report/worker adapters под notifications_runtime измерить intake/checkpoint/job, claim/lease, prepare/лимитеры/admission, success/uncertain/blocked/retryable, pending report/ack, recovery и служебные переходы. Матрица перечисляет все обязательные записи, ограничения входных размеров и максимальные batches; отсутствие конечного предела блокирует верхнюю оценку.
- Переиспользовать экспортированные source/event/trigger/attempt ID OPS-024/025 и реальные bytes. Вызовы API — готовый loopback mTLS, Telegram — управляемый локальный HTTP. Измерить первое применение/повтор/физический дубль intake, потерю commit-ответа и replay отчёта готовыми helpers; setup и затраты API изолировать отдельными фазами. Реальные внешние сообщения не отправлять.
- Проверить empty, реальную запись и повтор на чистых volumes; сохранить manifest/raw двух collectors/версии/команды и cleanup. Валидатор проверяет обязательные метрики и связи устойчивых ID, unknown/unsupported не становится нулём.
- Свести покрытие OPS-024/025/026 по исходным критериям OPS-021: каждому классу/фазе соответствуют raw и отчёт либо явный блокирующий пробел. Служебные записи и физические дубли учтены отдельно. Передать OPS-022 проверяемый отчёт продолжений; непокрытое/unsupported блокирует положительную квалификацию OPS-018.

## Проверка

Disposable PostgreSQL/Kafka; контрольные опыты и проверка raw/формата отчёта. Инфраструктурная проверка без искусственных unit-тестов. Недоступная проверка не считается успешной.

## Не входит

Новый runner/collector, runtime четырёх процессов, новые бизнес-переходы, market-data manifest, таблица стоимости/квоты и ledger.
