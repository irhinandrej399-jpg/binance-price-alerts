# CON-004 — Определить событие срабатывания

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [CON-001](CON-001.md), [CON-002](CON-002.md), [CON-003](CON-003.md), [DEC-004](DEC-004.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `medium` (Medium).
- Обоснование: Один формат срабатывания должен сохранять устойчивый trigger_id при повторной передаче.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Одна схема AlertTriggered.

## Критерии приёмки

- По [ADR DEC-004](../../decisions/DEC-004.md): AlertTriggered — запрос работы доставки, не terminal-успех. Есть устойчивый trigger_id/workflow ID, версия, пользователь, подписка, порог/направление и диагностическая котировка кандидата.
- Цена события не разрешает отправку. Допуск возвращает новую проверенную котировку; один workflow ID сохраняется через ожидание и повторы.
- По [DEC-005](../../decisions/DEC-005.md) chat из события не является актуальным адресатом; получатель определяется API при допуске. Возобновление после перепривязки сохраняет workflow ID.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Точная сериализация, повтор с тем же ID, явная семантика delivery_requested; старое событие не содержит безусловного разрешения отправки.

## Не входит

Рендеринг Telegram-сообщения.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).
