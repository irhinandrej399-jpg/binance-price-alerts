# OPS-016 — Остановить приём рынка при исчерпании бюджета

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [MKT-017](MKT-017.md), [MKT-014](MKT-014.md), [DEC-008](DEC-008.md)

Выделен при принятии [DEC-007](../../decisions/DEC-007.md); реализация не входит в DEC.

## Модель для сессии

- Модель: `gpt-6.1-sol`.
- Уровень размышления: `high` (High).
- Обоснование: Остановка должна точно отделять durable принятые цены от разрыва upstream и не терять SQL-outbox.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора](../MODELS.md).

## Один результат

Один ограничитель durable приёма market-data по согласованному бюджету.

## Критерии приёмки

- Используется точный контракт учёта ёмкости и резерва из DEC-008; до ready контракт должен быть согласован.
- При достижении бюджета новые цены не объявляются принятыми без commit MKT-017; upstream приём останавливается с наблюдаемым разрывом. Ограничены in-flight/память, бесконечная очередь в RAM не допускается.
- Принятые SQL-outbox записи остаются и публикуются после восстановления; место для их служебных переходов зарезервировано. Возобновление не выдумывает историю отсутствовавших сделок.
- Причина остановки и состояние ограничителя доступны readiness/метрикам; после освобождения ёмкости восстановление использует существующий reconnect и сохраняет монотонность ревизии.
- Выполнены проверки ниже и [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Реальный PostgreSQL, управляемые broker/upstream: заполнение бюджета при недоступном Kafka, рестарт, восстановление публикации принятых записей, наблюдаемый разрыв и отсутствие заявления о приёме незафиксированной цены. Проверить верхнюю границу памяти и место для завершения публикации.

## Не входит

Новый WebSocket adapter, readiness endpoint, восстановление внешней истории и подбор профиля.

## Размер сессии

Кандидат на одну сессию после готовности зависимостей и соответствующего test harness. Перед ready проверить фактические интерфейсы по workflow. Отсутствующие adapters, экспорт прогресса или harness сначала выделить отдельными предпосылками; не реализовывать скрытно.
