# SET-006 — Подготовить подключение и интеграционные проверки Go с PostgreSQL

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [SET-001](SET-001.md), [SET-003](SET-003.md), [SET-004](SET-004.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `medium` (Medium).
- Обоснование: Один воспроизводимый путь подключения Go к готовому PostgreSQL и проверки транзакций без продуктовых таблиц.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Готовая основа для интеграционных тестов Go-хранилищ с реальным PostgreSQL, использующая стенд и runner из SET-003/004.

## Критерии приёмки

- Выбран и закреплён поддерживаемый Go-драйвер PostgreSQL; документированы создание и закрытие подключения, context timeout и передача конфигурации без логирования credentials.
- Одна команда поднимает отдельный функциональный Compose-проект, применяет миграции существующим `scripts/migrate.py` и запускает Go-проверку под runtime-ролью API. Рабочий `binance-storage` и его данные не изменяются.
- На реальном PostgreSQL проверены подключение, commit/rollback тестовой записи и работа двух независимых соединений; fixture не создаёт аккаунты или другую продуктовую схему. Очистка безопасна при сбое; credentials не выводятся.
- Обычный `go test ./...` явно пропускает opt-in интеграционные проверки без настроенного стенда; команда opt-in завершается ошибкой при недоступной БД, а не успешным пропуском.
- Описан способ использовать основу для тестов IAM-001; выполнены применимые [общие критерии готовности](../workflow.md).

## Проверка / воспроизведение

На отдельном проекте выполнить описанную команду; подтвердить commit/rollback и два соединения, затем повторить запуск. Проверить обычный `go test ./...` и ненулевой результат opt-in при недоступной БД.

## Не входит

Схема аккаунта, репозиторий аккаунтов, хеширование паролей, HTTP, runtime четырёх сервисов и универсальный framework хранилищ.

## Размер сессии

Кандидат на одну сессию после проверки готовых артефактов SET-001/003/004. Использовать существующий Compose и migration runner; отдельный SQL runner не разрабатывать.
