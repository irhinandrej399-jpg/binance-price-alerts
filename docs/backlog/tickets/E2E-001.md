## Один результат

Один пользовательский тест на уже готовом стенде E2E-002 с fake Binance и Telegram.

## Критерии приёмки

- По [ADR DEC-004](../../decisions/DEC-004.md): слот освобождается после сохранённого API подтверждения Telegram. Отдельный сценарий 101→99 до отправки: сообщение не уходит, слот занят; затем 102 даёт одну подтверждённую доставку. Отмена до допуска запрещает отправку.
- Аккаунт создаётся, Telegram привязывается, подписка срабатывает один раз, слот освобождается, сообщение отправлено.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Red→Green сценарий через реальные процессы, хранилище и брокер; без вызовов публичных API.

## Не входит

Создание стенда/fake интеграций, новый бизнес-код и массовая нагрузка.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).
