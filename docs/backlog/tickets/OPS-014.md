# OPS-014 — Удалить безопасный префикс журнала Kafka

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [SET-005](SET-005.md), [SUB-022](SUB-022.md), [MAT-011](MAT-011.md), [NTF-001](NTF-001.md), [DEC-007](DEC-007.md), [OPS-056](OPS-056.md), [OPS-057](OPS-057.md), [OPS-058](OPS-058.md)

Выделен при принятии [DEC-007](../../decisions/DEC-007.md); реализация не входит в DEC.

## Модель для сессии

- Модель: `gpt-6.1-sol`.
- Уровень размышления: `high` (High).
- Обоснование: Удаление необратимо; граница должна учитывать durable прогресс всех зарегистрированных потребителей и гонки.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора](../MODELS.md).

## Один результат

Один cleaner безопасного префикса партиции Kafka по подтверждённым durable checkpoints.

## Критерии приёмки

- Cleanup по возрасту/объёму и compaction остаются выключенными. Cleaner не сбрасывает consumer на latest и не снимает SQL replay-pins.
- Реестр обязательных потребителей и их авторитетные durable checkpoints заданы явно; Kafka committed offset без проверки происхождения не считается доказательством. До ready проверить наличие интерфейсов экспорта прогресса владельцами, при отсутствии выделить prerequisite.
- Удаляется только префикс строго до минимального next-offset подтверждённых SQL-checkpoints; неизвестный потребитель/поколение, неподтверждённый прогресс или ошибка запрещают удаление.
- Регистрация нового потребителя и вывод старого из эксплуатации согласованы с очисткой; новый consumer не может требовать уже удалённую историю без явного bootstrap. Рестарт не равен выводу из эксплуатации.
- Команда повторяема, ограничена по объёму, показывает проверенную границу и результат DeleteRecords. Не удаляет целый topic и не обещает немедленного освобождения всех байтов.
- Выполнены проверки ниже и [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Реальные Kafka и PostgreSQL: два потребителя с разным прогрессом, отстающий/неизвестный потребитель, потерянный ответ commit offset, конкурентная регистрация/вывод, отказ DeleteRecords и повтор. Необработанное сообщение остаётся читаемым после очистки; durable задания notifications сохраняются.

## Не входит

SQL cleaner журнала API, сброс/пересоздание topics, экспорт checkpoints всех сервисов и подбор размеров нагрузочного стенда.

## Размер сессии

Кандидат на одну сессию после готовности зависимостей и соответствующего test harness. Перед ready проверить фактические интерфейсы по workflow. Отсутствующие adapters, экспорт прогресса или harness сначала выделить отдельными предпосылками; не реализовывать скрытно.
