# OPS-018 — Квалифицировать таблицу стоимости и квоты durable приёма

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [OPS-022](OPS-022.md), [DEC-008](DEC-008.md), [OPS-029](OPS-029.md)

Явная предпосылка OPS-015/016 по DEC-008, выделенная при сессионной проверке OPS-015.

## Модель для сессии

- Модель: `gpt-6.1-sol`.
- Уровень размышления: `high` (High).
- Обоснование: Верхние затраты и непересекающиеся резервы должны учитывать физические дубли, будущие шаги и ограничения полного fixture.

Это рекомендация, а не переключение модели. [Условия выбора](../MODELS.md).

## Один результат

Версионированная квалифицированная таблица векторных затрат и непересекающихся квот для OPS-015/016 с воспроизводимым отчётом.

## Критерии приёмки

- Через collectors OPS-019/020 и manifests OPS-023–026/OPS-022 измерены максимальные допустимые размеры/пакеты реальных adapters: create, первый workflow, отмена, допуск и исходы, journal/outbox, relay и повтор publish, приём цены; учтены обязательные будущие записи matcher/notifications. Для каждого класса указаны SQL heap/index/TOAST, WAL/временные страницы, Kafka overhead и резерв следующих шагов. Неограниченные повторы не объявляются конечным разовым резервом.
- Для верхних оценок сохранены исходные измерения, версии схем/контрактов/образов, границы применимости и запас 2×; неизвестная стоимость блокирует квалификацию. Учтены будущие служебные записи ledger: до его реализации задаётся проверяемый консервативный предел, который OPS-015/016 обязаны перепроверить на конечной схеме.
- Квоты владельцев источника и диапазоны межсервисного продолжения не пересекаются; суммы укладываются в SQL 80/24 GiB и Kafka 24/8 GiB. Учтены начальные 1 000 000 и граничные 1 500 000 подписок, аккаунты и прочие части fixture DEC-008; расчёт не подменяет будущий LOAD-001. Скорость cleaner равна нулю. Если профиль не помещается, сохранить отрицательный результат и вынести изменение согласованных параметров владельцу, не менять ADR молча.
- Контракт таблицы задаёт версию стоимости, идентификатор обязательства, отдельную цену каждой publish-попытки, in-flight/max batch, правила списания и подтверждённого освобождения, закрытие при неизвестных данных и нижние пороги SQL 72/Kafka 20 GiB. Новое продуктовое решение согласовать до ready ограничителей.
- Отчёт перечисляет оставшиеся проверки OPS-015/016: атомарный ledger, 200/100 конкурентов, rollback/restart, завершение при закрытом обычном приёме, дубли и возобновление после освобождения. Измерение не объявляется реализацией gate.

## Проверка

Команды OPS-019/020, OPS-023–026 и OPS-022, сырые результаты и проверка арифметики таблицы/квот. Отрицательный результат сохраняется; недоказанные оценки не считаются квалифицированными.

## Не входит

Измерительный harness, реализация ledger/admission, очистка, readiness, изменение бюджета/профиля без согласования, полный нагрузочный прогон.

## Размер сессии

Один отчёт по готовому OPS-022. До ready проверить полноту сценариев/артефактов harness; недостающее средство измерения не создавать внутри квалификации.
