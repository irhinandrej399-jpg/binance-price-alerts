# SUB-015 — Прочитать согласованный снимок из хранилища

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [SUB-001](SUB-001.md), [SUB-011](SUB-011.md), [SUB-012](SUB-012.md), [DEC-004](DEC-004.md), [SUB-021](SUB-021.md)

Разделённый исходный тикет: [SUB-010](SUB-010.md).

## Модель для сессии

- Модель: `gpt-6-astra` (GPT-6 Astra).
- Уровень размышления: `high` (High).
- Обоснование: Согласованный снимок страниц и граница replay связывают состояние БД с потоком; ошибка создаёт незаметное окно потери изменений.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Один storage-интерфейс страниц снимка и границы replay по готовому протоколу DEC-004.

## Критерии приёмки

- По [DEC-007](../../decisions/DEC-007.md): durable replay-pins имеют владельца и объявленный срок ресурса; снимок передаёт pin в replay без окна очистки. Подтверждение прогресса монотонно, только на границе целой транзакции; потеря/истечение pin отличимы от пустого хвоста. Storage-проверки pin/progress используются SUB-022; публикация в Kafka не снимает pins.

- По [DEC-006](../../decisions/DEC-006.md): одна REPEATABLE READ транзакция материализует S и C; страницы читают неизменяемый snapshot_id после commit builder. Retention-pin публикуется с ресурсом снимка; session-level shared retention-lock builder берётся до BEGIN REPEATABLE READ, исключительный lock очистки — до чтения актуальных pins. Это исключает гонку удаления и преждевременный MVCC-снимок. Проверить T1/T2 с задержанным commit, изменение между страницами, повтор/истечение и cleaner vs builder на реальном PostgreSQL. Журнал/счётчик берутся из SUB-021, новый протокол не выбирается.

- По [ADR DEC-004](../../decisions/DEC-004.md): S соответствует одной границе C commit-согласованного журнала; replay строго после C, без пропущенных конкурентных commit. Есть snapshot_id/expires_at; истечение требует нового снимка. Все незавершённые состояния/workflow включены.
- Страницы относятся к одной логической границе; cursor имеет определённую связь с потоком; срок жизни ресурсов следует DEC-004.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).
