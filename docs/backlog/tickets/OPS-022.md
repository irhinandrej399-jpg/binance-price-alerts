# OPS-022 — Измерить manifest источника market-data и свести покрытие затрат

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [OPS-019](OPS-019.md), [OPS-020](OPS-020.md), [OPS-021](OPS-021.md), [MKT-014](MKT-014.md)

Выделен из [OPS-017](OPS-017.md) при проверке размера 4 ноября 2026.

## Модель для сессии

- Модель: `gpt-6.1-sol`.
- Уровень размышления: `high` (High).
- Обоснование: Поколения, повторы relay и отделение источника от продолжения требуют транзакционных контрольных опытов.

Это рекомендация, а не переключение модели. [Условия выбора](../MODELS.md).

## Один результат

Manifest физических затрат market-data и единый проверяемый отчёт покрытия для квалификации OPS-018.

## Критерии приёмки

- Переиспользовать manifest/runner и формат OPS-021, collectors OPS-019/020. Через реальные storage/relay/producer измерить BeginGeneration, status/gap, Accept на границах размера, повторные версии, claim/mark и максимальный batch. Новых бизнес-переходов не создавать.
- Отдельные ID и фазы отделяют стоимость источника market-data от обязательного matcher/notifications продолжения API. Первая публикация и дубль после потерянного commit-ответа измеряются отдельно; использовать существующий fault helper.
- Сохранить пустой контроль, реальную запись и повтор с чистыми disposable volumes, сырые результаты, manifest, версии и команды. Рабочие/load volumes не затрагиваются; cleanup проверить.
- Свести отчёты API и market-data в перечень всех требуемых OPS-018 классов/компонентов: heap/index/TOAST, WAL/temp, Kafka log/index/segment/transaction, fsync отдельно. Для каждого есть ссылка на фазу и сырой снимок либо явный блокирующий пробел. Подтвердить проверкой формата отчёта, что unknown/unsupported не превращается в ноль.
- Описать воспроизведение полного измерительного прохода и границы применимости; коэффициент запаса и квоты не выбирать. Неподдержанное измерение явно запрещает положительную квалификацию в OPS-018.

## Проверка

Disposable стенд; контрольные опыты и проверка сырых данных/формата отчёта по критериям выше. Для инфраструктуры искусственные unit-тесты не нужны. Функциональный race runner не заменяет измерений.

## Не входит

Новые collectors, таблица стоимости/квоты, ledger/admission, изменение DEC-008 и большой нагрузочный прогон.

## Размер сессии

Перед ready проверить интерфейсы зависимостей и один измерительный проход. Если нужен новый независимый механизм, сначала уточнить границу, не скрывать его в опыте.
