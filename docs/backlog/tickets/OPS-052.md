# OPS-052 — Подготовить disposable окружение процесса matcher

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [OPS-047](OPS-047.md), [MAT-011](MAT-011.md), [SUB-016](SUB-016.md), [MKT-006](MKT-006.md), [DEC-010](DEC-010.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Нужны изолированные credentials, mTLS fixture и наблюдение durable результатов при рестарте child; lifecycle уже готов в OPS-047.

Это рекомендация, а не смена модели; см. [MODELS](../MODELS.md).

## Один результат

Воспроизводимое окружение отдельного matcher child с PostgreSQL/Kafka и управляемыми внутренними RPC для OPS-053/010, без продуктового runtime.

## Критерии приёмки

- Переиспользованы Compose/init/migrate и apiprocess.With/Config/PID registry.
  Уникальные disposable проекты, случайные loopback порты, prefix topics,
  deadlines и cleanup по точным labels; рабочие стенды не затрагиваются.
- Родительская fixture применяет API и matcher migrations. API credential
  доступен только fixture API-владельца; child получает только matcher DSN,
  Kafka, RPC endpoints и явные сервисные credentials. Чужие DSN/parent env
  не наследуются, секреты не выводятся. Права child на чужие БД запрещены.
- Переиспользованы приёмы matcher_failover_test.go: реальные Snapshot/Replay/
  Delivery servers над API fixture и mTLS, управляемый Latest endpoint по
  готовому wire-контракту, канонические API workflow/outbox. Общий E2E fake
  сервисов не строится. Управляемая задержка Delivery позволяет остановить
  child после части durable кандидатов и отпустить уже принятый API ответ.
- Fixture даёт согласованные subscription-changes и prices (16 partitions),
  полный явный bootstrap next offsets до публикации цен; replay/feed без
  скрытого reset. Родитель может наблюдать Pending/результаты/Prefix matcher,
  canonical trigger_id/outbox API и broker offsets через независимые clients.
- Тестовый child подтверждает доступность RPC/Kafka/своей БД и startup/exit;
  штатный и аварийный owner exit не оставляют child/containers/volumes/networks.
  Готовые lifecycle tests не дублируются. Runner поддерживает --package для
  cmd/matcher, README описывает fixture, команды и ограничения.
- Без opt-in интеграция явно SKIP, с opt-in отсутствующая зависимость — FAIL.

## Сценарии TDD (Red → Green → Refactor)

Fixture → mTLS/SQL/Kafka доступ из child; canonical workflow и наблюдение частичной работы; startup failure, owner exit и cleanup. Проверка SIGTERM продуктового matcher остаётся OPS-010.

cmd/matcher, graceful shutdown OPS-010, wiring остальных сервисов, полный E2E, нагрузка и kernel исследования.

## Ход работы

- `internal/testutil/matcherprocess`: New над grpctest и настоящими
  Snapshot/Replay/Delivery servers; управляемый Latest с неизменными временами
  через production adapter, в том числе mTLS-вызов из Delivery. Ephemeral CA
  и ключ сервера остаются в родителе; matcher cert/key/CA — файлы 0600 в TempDir.
  ChildEnv — явный allowlist без API/market-data/notifications DSN и parent env.
- Seed использует account, binding test SQL, LockQuota/Create и один journal.Append:
  три active кандидата и canonical journal по сохранённым after-image. PublishChanges — готовый API relay целыми
  транзакциями; Changes — настоящий Kafka feed с точным RegisterAt на resume,
  Close присоединяет Source. Bootstrap — полный явный read_committed LSO
  vector 16 prices partitions до публикации; на restart не переснимается.
  PublishPrice — канонический PriceObserved/транзакция/правильная pair partition.
- PauseDelivery удерживает ответ только после API commit/workflow/outbox;
  Committed/Release дают управляемую границу, release идемпотентен. Пауза
  ограничена 20 с/context; cleanup освобождает её перед остановкой сервера.
- `scripts/check_matcher_process.py` переиспользует общий runner, который
  применяет только API+matcher migrations, даёт API runtime credential только
  родительской fixture. Child получает только matcher DSN и RPC/Kafka/PKI.
  Существующий ownerexit принимает matcher opt-in; новый lifecycle не написан.
  Уникальные проекты, loopback ports/topics, deadline/PID registry и exact-label
  cleanup сохранены. `--package ./cmd/matcher` доступен для OPS-053/010.
- Тестовый child проверяет SQL role/database, запрет CONNECT ко всем чужим БД,
  отсутствие чужих DSN/parent secret, Snapshot/Replay/Latest/Kafka (16 partitions)
  до HTTP 200. Неверный DSN даёт early exit; штатный child убирает apiprocess.
- Реальная replica запускается только в родительском qualification test:
  готовая full view, пауза после одного matcher результата и второго API commit,
  отдельный matcher reader и независимый Kafka offset observer. Broker ack не
  опережает pending. После отмены/join и нового Latest=99/sequence=3 successor
  помечает историческую работу superseded, освобождает Pending, сохраняет SQL
  Prefix и broker next; canonical повтор Delivery возвращает тот же trigger_id.
  Третий кандидат не получает ложный исторический workflow, outbox не дублируется.
- README описывает fixture/env/PKI, bootstrap/точный resume, команды, наблюдение
  и ограничения. Продуктовые cmd/matcher и SIGTERM не добавлялись.
