# OPS-069 — Подключить Catalog и Latest RPC к процессу market-data

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [OPS-009](OPS-009.md), [MKT-006](MKT-006.md), [MKT-018](MKT-018.md), [SET-008](SET-008.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high`.
- Обоснование: Композиция mTLS и конкурентного lifecycle с SQL/relay; нужна проверка отмены и освобождения ресурсов.

Это рекомендация пользователю, настройки текущей сессии не меняются. [Условия выбора](../MODELS.md).

## Один результат

Один mTLS listener market-data с готовыми Catalog/Fetch и Quotes/Latest рядом с существующим raw ingest и relay.

## Критерии приёмки

- Явные RPC bind, server credentials, CA, API/matcher URI и URL каталога в конфигурации; тестовый URL задаётся стендом, публичный Binance в тестах не вызывается.
- Одна общая serviceauth policy: API имеет Fetch/Latest, matcher — только Latest. Catalog использует catalog.Client, Latest — собственный storage.Repository; поколения и предупреждения сохраняются.
- RPC обслуживается после startup; bind/TLS/schema failures закрывают все ресурсы. SIGTERM/terminal failure снимает готовность, отменяет и присоединяет RPC до pool.Close в существующем shutdown budget.
- Raw feed остаётся unconfirmed: первая сделка/ACK не превращаются в live. README задаёт проверяемое ожидание готовности локального профиля без фиктивного readyz=200.

- Выполнены проверки ниже и [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Настоящий executable на marketprocess disposable PostgreSQL/Kafka, loopback catalog fixture и mTLS clients: Fetch, принятая raw цена через Latest, чужая identity, bind/credential failure, SIGTERM и повторный запуск. Использовать scripts/check_marketdata_process.py; зафиксировать cleanup.
Сначала получить падение по отсутствующему runtime wiring; затем подключить готовые adapters и повторить проверки с race. Unit-проверка конфигурации не заменяет процессный тест.

## Не входит

Динамический каталог потоков, новый ingest, смена политики freshness/readiness и полный E2E.

## Размер сессии

Кандидат на одну сессию, не ready. Перед реализацией проверить зависимости и достаточность существующего process harness. Если нужен независимый adapter/harness, выделить зависимость до кода.
