# MKT-013 — Опубликовать одну цену с подтверждением брокера

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [MKT-005](MKT-005.md), [SET-005](SET-005.md), [CON-003](CON-003.md), [DEC-007](DEC-007.md), [SET-009](SET-009.md)

Разделённый исходный тикет: [MKT-007](MKT-007.md).

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `medium` (Medium).
- Обоснование: Один подтверждённый publish имеет ограниченный интерфейс; буфер и длительные повторы вынесены отдельно.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Один producer PriceObserved, возвращающий результат publish/ack.

## Критерии приёмки

- По [DEC-007](../../decisions/DEC-007.md): один подтверждённый publish выполняется транзакционным идемпотентным Kafka producer (acks=all, retries, max.in.flight<=5); commit/timeout/producer fenced различимы. Стабильный transactional.id задаёт вызывающий relay-шард. Ключ пары, event_id, source ID, поколение/ревизия сохраняются; конфигурация не обещает exactly-once между SQL и Kafka.

- Ключ порядка — пара; повтор сохраняет event_id и source ID; ошибка брокера не считается успехом.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Fake/fault broker проверяет ack, отказ и потерянный ack с повтором того же сообщения.

## Не входит

Буферизация, длительные повторы и управление давлением.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).
