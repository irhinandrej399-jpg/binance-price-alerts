# OPS-051 — Настроить стартовую HTTP-пробу process harness

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [OPS-047](OPS-047.md), [OPS-049](OPS-049.md), [OPS-006](OPS-006.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `medium` (Medium).
- Обоснование: Узкая настройка готового lifecycle без нового runner;
  проверить выбранную HTTP-пробу, совместимость и cleanup на test child.

Это рекомендация, а не смена модели; см. [MODELS](../MODELS.md).

## Один результат

Существующий `apiprocess.With/Config` позволяет выбрать путь стартовой HTTP-пробы,
чтобы процесс с честным unconfirmed feed можно было проверить без готовности
к обслуживанию. Ожидание пробы означает доступность выбранного HTTP endpoint,
а не автоматически readiness приложения.

## Критерии приёмки

- Config принимает необязательный локальный путь стартовой HTTP-пробы.
  Пустое значение сохраняет прежний `/readyz`; успех — только HTTP 200.
  Невалидное значение отклоняется до запуска child с безопасным ErrConfig.
  Разрешён только абсолютный путь внутри выданного harness origin, без
  scheme/host, query/fragment, управляющих символов и redirect-following.
- Тестовый child с `/healthz = 200` и `/readyz = 503` допускается к check
  при явном выборе `/healthz`. Callback независимо подтверждает 503 и тело
  unconfirmed; default `/readyz` для такого child завершается timeout,
  callback не вызывается. Это не меняет продуктовый health/readiness.
- Старые API/marketprocess consumers без настройки работают как прежде.
  Сохраняются deadline/cancel, early-exit, TERM/KILL/Wait, PID registry и
  очистка child при ошибке startup/callback; новый lifecycle не создаётся.
- README apiprocess/marketprocess описывают настройку для OPS-048 и отличие
  стартовой пробы от продуктовой readiness. Проверки используют существующий
  test child и loopback; новый fake Binance, Docker runner или runtime не нужны.

## Сценарии TDD (Red → Green → Refactor)

Default /readyz=200; /healthz=200 при /readyz=503; default timeout при 503;
неверный путь до запуска child; non-200 и redirect не допускают check;
exit/cancel/cleanup с явно выбранной пробой. Использовать готовые lifecycle
assertions и test child в `internal/testutil/apiprocess`, без второго harness.

Проверка: `GOCACHE=/tmp/binance-go-build GOTOOLCHAIN=local go test -race
-count=1 ./internal/testutil/apiprocess ./internal/testutil/marketprocess`.
Integration opt-in без Docker явно SKIP, не считать его реальным DB/Kafka прогоном.

## Не входит

cmd/market-data, политика live и изменение HTTP health, полный fake Binance,
новые Compose/runner/fixtures, graceful shutdown продукта и E2E четырёх сервисов.
