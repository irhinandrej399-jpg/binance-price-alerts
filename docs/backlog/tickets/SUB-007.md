# SUB-007 — Опубликовать subscription outbox

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [SUB-011](SUB-011.md), [SUB-012](SUB-012.md), [SET-005](SET-005.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Relay должен правильно вести себя между publish, ack и локальной отметкой; тесты намеренно разрывают эти шаги.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Один relay изменений подписок в брокер.

## Критерии приёмки

- По [DEC-007](../../decisions/DEC-007.md): последовательный relay целых транзакций C в subscription-changes; стабильный transactional.id, Kafka fencing, read_committed у потребителя. Отметка SQL только после commit Kafka; потерянный ответ commit даёт повтор того же event_id, без снятия replay-pin.

- По [DEC-006](../../decisions/DEC-006.md): relay сохраняет C и event_id из SQL-журнала API; отметка publish не разрешает удалять данные replay, удерживаемые snapshot-pin или прогрессом потребителя. Связь порядка C с брокером и очистка следуют DEC-007.

- Запись помечается отправленной только после подтверждения; повторная публикация сохраняет event_id.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Брокер недоступен; сбой после publish до отметки; после восстановления событие опубликовано, возможный дубль имеет тот же ID.

## Не входит

Exactly-once транспорт и outbox других сервисов.

Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).
