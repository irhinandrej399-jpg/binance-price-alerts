# MAT-007 — Загрузить исходный снимок в проекцию matcher

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [MAT-001](MAT-001.md), [SUB-016](SUB-016.md), [DEC-004](DEC-004.md)

Разделённый исходный тикет: [MAT-003](MAT-003.md).

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Загрузка нескольких страниц должна быть повторяемой и не выставлять готовность до последующего replay.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Одна стадия bootstrap читает все страницы готового снимка.

## Критерии приёмки

- По [DEC-006](../../decisions/DEC-006.md): bootstrap пишет отдельное поколение durable проекции matcher; частичная загрузка не заменяет рабочее поколение и не двигает live checkpoint.

- По [ADR DEC-004](../../decisions/DEC-004.md): снимок переносит все незавершённые состояния/workflow; bootstrap не готов до replay и подключения к последним ценам, историю исчезнувших условий не догоняет.
- Проекция соответствует одной границе; процесс остаётся неготовым до replay; повтор загрузки идемпотентен по протоколу.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Две страницы, пустой снимок и прерывание загрузки не выставляют готовность; загруженная проекция совпадает с эталоном.

## Не входит

Догоняющий поток, переключение в live и сохранённый restart cursor.

## Размер сессии

Сессионная проверка 29 октября 2026 пройдена: MAT-001/SUB-016 подтверждены кодом и схемами, PostgreSQL/RPC harness готовы. Один результат загрузки: planned → ready → in-progress → done.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).

## Передача следующей сессии

- Статус: `done`; в объёме MAT-007 ничего не осталось.
- Артефакты: `internal/matcher/snapshotload/README.md`, `load.go`, `load_test.go`, `migrations/matcher/002_snapshot_generations.sql`, SQL fixture snapshot failure. `Load(ctx, BuildSnapshotRequest)` принимает готовый SUB-016 Client с mTLS, возвращает полное поколение либо ошибку/нулевой результат. Request ID/TTL сохраняет caller до вызова. Повтор начинает чтение заново; restart cursor не сохраняется.
- `Generation.Complete` — только окончание загрузки снимка. `Info` диагностический; `Get` возвращает полные protobuf after-images только полного поколения. Это отдельные staging-таблицы, не live checkpoint/активная проекция MAT-001. MAT-008 должен использовать эти данные, выполнить handoff/replay после C, подключить последние цены и обеспечить переключение рабочего поколения/readiness. Действительность pin проверяется через API; Complete не заменяет эту проверку.
- При FailedPrecondition/потере/истечении ресурса отбросить частичное поколение логически и начать с новым request ID; staging строки остаются изолированными до отдельной очистки. Immutable строки не перезаписываются. История цен, workflow creation, cleanup и runtime не реализованы; нагрузка не измерялась.
- Следующий по ORDER — MAT-008, только по новому поручению и после сессионной проверки; в этой сессии не начинался.
