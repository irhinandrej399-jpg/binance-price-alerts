# DEC-008 — Зафиксировать воспроизводимый профиль нагрузки

Статус: `decision`. Приоритет определяется зависимостями, а не номером.

Зависимости: Нет.

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Важно согласовать измеряемый профиль, длительность burst и ресурсы, не смешав аудиторию, входные цены и скорость доставки.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Паспорт одного нагрузочного стенда.

## Критерии приёмки

- По [DEC-007](../../decisions/DEC-007.md): учесть принятый Kafka-профиль DEC-007: стоимость fsync, фиксированные партиции, ограниченный диск и длительность burst; RF=1 не называть HA. Согласовать точный контракт учёта/атомарного резервирования ёмкости для будущих OPS-015/016, включая консервативный запас под конкурентные записи и завершение работы. Задать бюджеты/запас для завершения принятой работы, пороги остановки нового приёма и воспроизводимый сценарий переполнения; скорость cleaner не считать уже измеренной.

- По [ADR DEC-004](../../decisions/DEC-004.md): считать запросы работы отдельно от подтверждённых доставок, ожидания цены и пропущенных исчезнувших условий. Для p99/восстановления задать неизменно подходящие контрольные цены; не требовать исторических уведомлений.
- Указаны CPU/RAM/диск, число экземпляров, входные цены/с, пары, распределение подписок, API RPS и длительность тестов.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Проверка решения

Различаются 100000 аккаунтов и одновременные запросы; 1000000 подписок и предел 1500000; предложенный burst 10000 событий за 1 с согласован явно.

Тип: решение, исполняемых тестов не требуется. Решение записать в `docs/decisions/` и обновить требования и зависимые карточки.

## Не входит

Утверждение достигнутой производительности без измерений.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).
