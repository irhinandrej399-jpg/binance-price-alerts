# CON-003 — Определить событие рыночной цены

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [CON-001](CON-001.md), [DEC-002](DEC-002.md), [DEC-004](DEC-004.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `medium` (Medium).
- Обоснование: Нужно сохранить идентичность сделки, точность цены и временные метки в одном явном контракте.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Одна схема PriceObserved.

## Критерии приёмки

- По [ADR DEC-004](../../decisions/DEC-004.md): котировка содержит монотонную ревизию с идентичностью потока по паре; старое событие не откатывает последнюю цену.
- Есть пара, цена, source ID, время биржи и приёма; способ обозначения разрыва описан.
- По [ADR DEC-002](../../decisions/DEC-002.md) время сделки Binance `T` явно отделено от времени приёма и времени события `E` (если оно передаётся); единицы нормализованы с сохранением точности. Поздний приём и replay не меняют время сделки.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Contract-тесты валидного события, точности цены, отсутствующего source ID, временных меток и нормализации единиц с сохранением точности.

## Не входит

WebSocket-клиент и matcher.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).

- 27 октября 2026: сессионная проверка выполнена. CON-001 подтверждён пакетом event и contract-тестами, DEC-002/004 — принятыми ADR. Доменный Price готов; внешний adapter/harness не нужен. Рабочее дерево на старте чистое. Один результат — схема PriceObserved; карточка прошла planned → ready → in-progress → done. Рекомендация карточки: GPT-6.1 Sol · Medium; настройки модели не менялись.
- Добавлены `internal/contracts/priceobserved/observed.go`, `observed_test.go`, `README.md`: payload v1, точная положительная цена, source ID, T/received_at/необязательное E, обязательное состояние потока и явный boolean разрыва. Encode/Decode связаны с общим конвертом и ключом пары; неизвестные версии и повреждённые данные отклоняются, неуспешный decode сохраняет получатель.
- Ревизия конкретизирует DEC-004/007: стабильный stream_id, durable монотонное generation и sequence; сравнение лексикографическое в одной паре/потоке. Старое поколение, старая цена и повтор не считаются обновлением. Разные пары/потоки несравнимы. Правило предоставлено контрактом, состояние потребителя здесь не реализуется.
- Нормализация явных миллисекунд/микросекунд сохраняет точность без float и переполнения при умножении полной Unix-метки. Времена сделки, события источника, приёма и конверта независимы; replay не меняет T. Исторический gap не стирается reconnect/сменой поколения, текущее состояние отсутствующего потока выдаёт будущий market-data интерфейс.
- Red: `GOTOOLCHAIN=local go test ./internal/contracts/priceobserved` — ожидаемое падение `no non-test Go files`: отсутствовала реализация проверяемого контракта.
