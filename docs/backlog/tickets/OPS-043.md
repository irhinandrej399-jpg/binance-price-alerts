## Модель для сессии

- Модель: `gpt-6.1-sol`.
- Уровень размышления: `high` (High).
- Обоснование: Один capture механизм должен различать reuse kernel object и связать terminal witness с incarnation; объём не расширяется до owner ledger или classifier.

Это рекомендация, а не переключение модели. [Условия выбора](../MODELS.md).

## Один результат

Версионированный capture поток incarnation binding → terminal retirement для
одного закрытого disposable FS домена, проверенный независимым реальным helper.

## Вход и выход

Вход: proof obligations P1/P5 [OPS-042](../../measurements/OPS-042/README.md),
Linux arm64 kernel/ABI выбранного disposable стенда, existing runner и helpers
OPS-040/041. До реализации проверить доступность инструментирования и достаточность
семантики на этом kernel. Конкретный hook сейчас не объявлен готовым интерфейсом.

Выход: raw run-local tokens с epoch, dev/ino, binding к FD/path/map observation,
причинными границами birth/terminal, kernel/build/source hashes, loss counters,
отдельным unsupported и cleanup. Epoch нельзя получать только из dev/ino,
pathname/FD, pointer без защиты reuse или времени tracer.
Token относится к filesystem incarnation: eviction/reload ещё linked inode
не новая incarnation и не retirement; bridge между cache objects нужно доказать
либо блокировать случай. Generic cache-object destruction не terminal witness.
Retirement не равен
last close; exact last-reference без полного release proof не заявляется.

## Критерии приёмки

- Обосновать и проверить на фактическом kernel один механизм наблюдения allocation,
  привязки и terminal retirement inode. Документировать coverage, задержку между
  последним reference и terminal, возможность missed hooks/loss и поведение при
  reuse адреса; недоступный механизм не выдавать за работающий.
- Использовать свежую изолированную FS, capture до её первых объектов; сохранить
  domain/namespace/mount/внешний доступ assumptions. Потеря событий, поздний старт,
  неизвестный binding и непокрытый reference route блокируют опыт. Общую полноту
  all-owner domain этот тикет не сертифицирует.
- Реальный existing helper различает held → absent views → reused: queue-only
  после sender close, mapping-only после close/unlink, receive/drop и munmap,
  повтор имени/FD и фактический numeric reuse (либо явный unsupported reuse).
  Терминальное событие held incarnation недопустимо; новый create получает
  другой token даже при одинаковом dev/ino. Helper fstat/maps/socket stages
  независимы от нового механизма, а не только выводятся из его же reducer.
- Verifier связывает обязательные birth/binding/terminal и независимые stages;
  rehashed controls удаления binding/terminal, слияния epochs, перестановки
  retirement перед held, ложный terminal ещё linked inode, loss и неверного domain
  отвергаются или blocked.
  Terminal после последнего held задаёт интервал, отсутствие FD его не заменяет.
- Сохранить воспроизводимые команды/raw/source hashes/cleanup и вход OPS-034.
  Составить mapping P0–P5: покрыто/неизвестно. Если guarded ownership или kernel
  coverage остаются неизвестны, OPS-034 остаётся planned; capture PASS не lifetime
  PASS. Не запускать PG gate или разработку нового harness скрытно.

## Проверка

Один disposable Linux capture существующих FS reference controls, independent
helper witnesses и полный replay/negative controls нового потока. В этой
карточке не реализуется reference reducer OPS-034.

## Не входит

All-task scheduler/barrier, полный owner/reference ledger, PG workload gate,
общий syscall/size classifier, фазовый runner, bounds и квалификация квот.
Если capture требует независимо принимаемого нового механизма сверх указанного
потока, сначала разделить задачу и обновить зависимости/ORDER.
