# E2E-009 — Разрешить явный listener существующих vendor fake

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [E2E-008](E2E-008.md), [E2E-004](E2E-004.md)

Выделен при сессионной проверке [OPS-074](OPS-074.md) 8 ноября 2026.

## Модель для сессии

- Модель: `gpt-6.1-sol`.
- Уровень размышления: `medium`.
- Обоснование: Узкое расширение сетевого интерфейса двух готовых test fixtures.

Рекомендация, не переключение модели. [Условия выбора](../MODELS.md).

## Один результат

Родитель малого Compose smoke может передать существующим Binance/Telegram fake
собственный listener, доступный из тестовой Docker-сети, и сохранить Go-управление.

## Критерии приёмки

- Добавить явный opt-in интерфейс listener для binancefake и telegramfake;
  существующие New остаются loopback-only и совместимыми со всеми пользователями.
  Адрес для клиента/контейнера задаёт владелец сценария; wildcard bind не выдаётся
  за маршрутизируемый URL. Описать сетевой контракт для OPS-074 без привязки к
  host.docker.internal или host networking как единственной платформе.
- Сохранить готовые каталог, bare /ws, ACK, TradePair/Next и Telegram Next/Reply/
  Requests, без автоматических цен и ответов. Новые vendor handlers не создавать.
- Явно определить передачу владения listener, ошибки запуска и Close: закрытие
  listener/активных WS/HTTP и присоединение handlers, включая незабранные запросы;
  отмена Next продолжает работать. Ошибка не оставляет listener или goroutine.
- Явный non-loopback bind разрешён только тестовым сценарием в изолированной сети.
  Fake token/secret остаются тестовыми; публичные endpoints/реальные credentials
  не используются. Контракт loopback-only telegramfake.Link не ослаблять.

## Проверка

TDD через явно переданный net.Listener, настоящий catalog/stream/telegram client:
raw trade и ACK, управляемая Telegram-доставка, отмена и cleanup. Сохранить прежние
loopback сценарии; целевой race и штатный CI. Проверку маршрута именно из Compose
контейнера выполнить в OPS-074 вместе с deployment, не строить новый runner здесь.

## Границы

Только существующие `internal/testutil/binancefake`, `telegramfake` и их README/
тесты. Без отдельного CLI/control API, универсального harness, fault proxy,
production runtime, Docker deployment и нагрузки. Перед ready выполнить
сессионную проверку по [workflow](../workflow.md).

## Ход работы

- 8 ноября 2026: зависимости E2E-008/E2E-004 подтверждены реализацией и тестами.
  Сессионная проверка пройдена: готовые handlers и клиенты, один opt-in сетевой
  интерфейс, без нового runner. planned → ready → in-progress.

- Добавлены `NewWithListener(net.Listener, origin)` в обоих fake. Ненулевой
  listener передаётся во владение при входе; неверный origin закрывает его до
  запуска goroutine. Ошибки bind/listen остаются у родителя, который передаёт
  исправный открытый listener; HTTP Serve асинхронный, проверка маршрута — у
  сценария. URL задаётся отдельно, wildcard origin отклоняется. Старые New и
  handlers сохранены; Binance Close теперь также закрывает HTTP connections.
- Red: `GOCACHE=/tmp/binance-go-build GOTOOLCHAIN=local go test
  ./internal/testutil/binancefake ./internal/testutil/telegramfake` — FAIL:
  отсутствуют оба NewWithListener. Существующие сценарии параметризованы для
  обоих конструкторов, без копирования vendor handlers.
- Green: `GOCACHE=/tmp/binance-go-build GOTOOLCHAIN=local go test -race
  ./internal/testutil/binancefake ./internal/testutil/telegramfake` — PASS после
  разрешения локальных listeners. Первая sandbox-попытка с реализацией упала
  на bind operation not permitted и успехом не считалась.
- Настоящие catalog.Client/stream.Reconciler/stream.Read/trade.Decode проверили
  raw trade, точные ACK, динамический каталог и reconnect через переданный
  listener. Настоящий telegram.Client проверил ручные ответы, журнал, отмену,
  held/unclaimed sends и неполное HTTP-тело. Дополнительно проверены nil/invalid
  origin, закрытие listener при ошибке, освобождение порта после Close,
  незабранные WS и неполный HTTP-запрос Binance. Loopback Link не менялся.
  Финальные тесты используют loopback socket и wrapper с wildcard Addr: это
  проверяет независимость origin без открытия тестового порта в LAN.
- Refactor: прежние сценарии выполняются через общий helper выбора конструктора;
  публичный origin хранится отдельно от фактического bind. README обоих fake
  описывают владение, ошибки, ограничения и сетевой контракт для OPS-074.
- Итоговые `GOCACHE=/tmp/binance-go-build GOTOOLCHAIN=local go test -race ./...`,
  `go vet ./...`, `go build ./...` — PASS. Сборка повторена вне sandbox после
  предупреждения о metadata cache permission. `python3 scripts/generate_proto.py
  --check` — PASS после разрешения загрузки protoc (sandbox DNS недоступен).
  `gofmt -l internal/testutil/binancefake internal/testutil/telegramfake` и

  пакетов; opt-in PostgreSQL/Kafka и Compose не запускались.
- Все критерии E2E-009 выполнены; in-progress → done, индекс и STATE обновлены.
  Финальная целостность проверена `python3 scripts/backlog.py check`.
