# SUB-019 — Сохранить исход попытки в подписке

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [SUB-017](SUB-017.md), [DOM-004](DOM-004.md)

Выделен при уточнении [DEC-004](DEC-004.md); не реализуется внутри задачи решения.

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Результаты, отмена и запоздалый успех должны согласовать один слот и канонический результат без потери подтверждённой отправки.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Одна идемпотентная storage-операция сохранения исхода известной попытки.

## Критерии приёмки

- Подтверждённый успех атомарно сохраняет delivered/message_id, изменение outbox и освобождает слот один раз.
- Отказ/неопределённость/blocked сохраняют требуемое DEC-004 состояние и слот; поздний успех известной попытки обрабатывается даже после lease, но отмену не возрождает.
- Повтор/устаревший отрицательный результат не откатывает новый успех; неизвестный attempt ID не принимается.
- По [DEC-005](../../decisions/DEC-005.md) отказ канала связан с версией привязки известной попытки; старый отказ не откатывает восстановление на новой версии. Если перепривязка опередила запись blocked, сохранённая старая версия позволяет последующее восстановление. Отдельная цена блокировки не сохраняется.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Реальная БД: повтор успеха, rollback, cancel vs success, поздний успех после timeout/новой попытки, устаревший отказ, blocked, слот ровно один раз.

## Не входит

HTTP endpoint, фактическая отправка и локальная запись notifications.

## Размер сессии

Кандидат на одну сессию после закрытия зависимостей. Перед ready проверить готовность адаптеров, транзакций и test harness по [workflow](../workflow.md). Недостающие предпосылки не реализовывать скрытно.
