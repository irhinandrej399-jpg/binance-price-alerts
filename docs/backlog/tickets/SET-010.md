# SET-010 — Подготовить PostgreSQL harness matcher

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [SET-006](SET-006.md), [SET-004](SET-004.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `medium` (Medium).
- Обоснование: Узкое расширение готового disposable PostgreSQL runner на ещё одного владельца с проверкой изоляции и отката.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Готовый opt-in Go harness собственной БД matcher в существующем disposable PostgreSQL-прогоне.

## Критерии приёмки

- `python3 scripts/check_postgres.py` применяет миграции matcher через существующий runner и передаёт MATCHER_DATABASE_URL для runtime-роли matcher; секреты не выводятся и не передаются в argv.
- `postgrestest.OpenWithDSN(t, "MATCHER_DATABASE_URL")` используется для проверки реальной БД matcher: commit виден из другого pool, rollback не сохраняет запись; runtime не получает доступ к чужой БД и истории миграций.
- Тестовые таблицы создаются fixture-миграциями отдельно от прикладной схемы matcher. Существующие API fixtures не применяются к matcher; прикладная проекция/checkpoint остаются MAT-001.
- Без POSTGRES_TEST тесты штатно пропускаются, при opt-in ошибка DSN/прав/подключения приводит к провалу. Используются имеющиеся helper и runner, новый независимый стенд не создаётся.
- Полный disposable PostgreSQL-прогон с race detector успешен; тестовый volume удалён, рабочий binance-storage не изменён.
- Выполнены [общие критерии готовности](../workflow.md).

## Проверка / воспроизведение

`python3 scripts/check_postgres.py`; обычный Go-прогон без opt-in; `python3 scripts/backlog.py check`. Для нового проверяемого поведения runner/helper использовать Red → Green → Refactor; инфраструктуру проверять реальными транзакциями.

## Не входит

Consumer Kafka, схема проекции и checkpoint, snapshot/replay bootstrap, runtime matcher и подготовка БД notifications.

## Размер сессии

Кандидат на одну сессию после проверки готовых интерфейсов SET-006/004; перед ready повторить сессионную проверку.
