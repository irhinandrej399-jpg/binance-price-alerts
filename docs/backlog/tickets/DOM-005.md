# DOM-005 — Реализовать проверку свежести котировки

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [SET-001](SET-001.md), [DEC-002](DEC-002.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `medium` (Medium).
- Обоснование: Проверка возраста цены ограничена одним контрактом и подставными часами с тестами вокруг границы.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Чистая проверка свежести с подставными часами.

## Критерии приёмки

- По [ADR DEC-002](../../decisions/DEC-002.md) возраст определяется как `now_utc - traded_at` без округления; часы подставляются, traded_at — время сделки. При возрасте от 0 до 5 секунд включительно — fresh, больше 5 секунд — stale. Stale служит для предупреждения и не запрещает использование цены. Другие результаты: missing при отсутствии цены; invalid_time для будущего, отсутствующего или некорректного времени. Состояние потока оценивается отдельно от чистой функции возраста.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Тесты возраста 0, 4,999, 5,000, 5,001 и −0,001 секунды, отсутствующей цены и некорректного/отсутствующего времени; системное время в тестах не используется. Поздний приём не меняет возраст; повторная проверка после границы даёт stale.

## Не входит

Обновление цены и сетевые повторы.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).
