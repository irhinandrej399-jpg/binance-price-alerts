# MKT-010 — Ограничить управляющие команды WebSocket

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [MKT-009](MKT-009.md)

Разделённый исходный тикет: [MKT-003](MKT-003.md).

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Управляющие команды делят бюджет со служебными сообщениями, а входные цены не должны блокироваться лимитером.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Планировщик отправки команд одного соединения с соблюдением лимита Binance.

## Критерии приёмки

- Учитывается общий бюджет команд и служебных сообщений; чтение цен не блокируется; параметры заданы конфигурацией.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Fake clock проверяет всплеск SUBSCRIBE, служебные сообщения и отсутствие превышения выбранного бюджета.

## Не входит

Новый коннектор и восстановление соединений.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).

## Ход работы

- 27 октября 2026: сессионная проверка пройдена: MKT-009 подтверждён transport-кодом, тестами и контрактом; дерево чистое. Planned → ready. Один результат — общий планировщик исходящих команд и pong одного соединения; fake clock и локальный WS harness доступны. Рекомендация GPT-6.1 Sol · High сообщена. Ограничения повторно сверены по официальному Binance websocket-streams.md: 5 сообщений клиента/с включая ping/pong и JSON.

- Ready → in-progress → done. Добавлен `internal/marketdata/stream/scheduler.go`: конфигурируемый общий бюджет JSON-команд и pong, равномерная отправка без накопления burst, приоритет и FIFO pong. По умолчанию 5 сообщений/с; значения выше лимита отвергаются до dial. Интервал округляется вверх, отсчитывается после завершения записи; после простоя catch-up отсутствует.
- `ReadWithCommands` использует существующий transport: один writer обслуживает канал команд и ограниченную очередь pong; цикл чтения не ждёт слота или записи. Закрытый/nil канал отключает только команды. Переполнение pong возвращает `ErrControlQueueFull` и закрывает соединение. Ошибка writer сохраняет причину, прерывает чтение; любой выход отменяет и дожидается writer. Старый `Read` использует тот же бюджет. Контракт, ACK/raw сообщения и пример — `internal/marketdata/stream/README.md`.
- Red: `GOCACHE=/tmp/binance-go-build GOMODCACHE=/tmp/binance-go-mod GOTOOLCHAIN=local go test ./internal/marketdata/stream` — FAIL по ожидаемой причине: undefined runWriter, Config, DefaultConfig; планировщика ещё не было.
- Green: та же команда с `-run 'TestScheduler|TestConfig'` — PASS. Дополнительный fake-clock race-прогон с `-run 'TestScheduler|TestConfig|TestPongBurst'` — PASS. Проверены SUBSCRIBE burst, общий бюджет в скользящих полуоткрытых окнах, граница интервала, приоритет/payload и FIFO нескольких pong, продолжение команд, pong после закрытия канала команд, отсутствие catch-up, отмена ожидания, ошибка записи и невалидная конфигурация.
- Первый WS-прогон в sandbox остановлен с `bind: operation not permitted`, успехом не считается. После разрешённого выхода из sandbox `go test -race ./internal/marketdata/stream` — PASS: цена читается в течение ожидания исходящего pong; pong отправляется перед второй командой; overflow и отмена ожидающей команды закрывают соединение и завершают writer. Сохранены все тесты MKT-009.
- Итог: `GOCACHE=/tmp/binance-go-build GOMODCACHE=/tmp/binance-go-mod GOTOOLCHAIN=local go test -race ./...` — PASS (локальные listener разрешены); `go vet ./...`, `go build ./...` с теми же переменными — PASS. Opt-in PostgreSQL integration штатно не запускались; изменений хранения нет.
- Refactor: бюджет изолирован от транспорта через clock/write interfaces; gofmt, описание конфигурации, ограниченной очереди и ответственности вызывающего кода. Критерии приёмки выполнены. Live Binance и runtime не запускались.
