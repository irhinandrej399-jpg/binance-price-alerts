# NTF-014 — Надёжно передать исход попытки владельцу подписки

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [NTF-010](NTF-010.md), [SUB-020](SUB-020.md), [NTF-007](NTF-007.md), [NTF-008](NTF-008.md)

Выделен при уточнении [DEC-004](DEC-004.md); не реализуется внутри задачи решения.

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Разрыв между локальным исходом Telegram и commit API требует durable обязанности и идемпотентного повтора без нового sendMessage.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Один адаптер durable сохранения/передачи результата API и восстановления после сбоя.

## Критерии приёмки

- По [DEC-006](../../decisions/DEC-006.md): исход попытки и pending report — одна транзакция собственной БД notifications; уникальный attempt/result ID и fencing защищают повторы. Никакой SQL-транзакции с API или Telegram нет.

- Локальный результат и pending report сохраняются атомарно; перезапуск повторяет SUB-020 по workflow/attempt ID до подтверждения.
- Потеря ответа API не повторяет Telegram; подтверждённый успех, временный/постоянный отказ и неопределённость различаются.
- Поздний успех известной попытки передаётся, stale отрицательный результат не перезаписывает новый успех; cancelled не возрождается.
- По [DEC-005](../../decisions/DEC-005.md) отказ канала передаёт причину и версию привязки конкретной попытки; повтор отчёта старой версии не блокирует возобновлённое задание.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Реальная БД notifications + управляемый API: сбой до/после local commit, timeout после commit API, перезапуск pending report, поздний успех и повтор результата; HTTP Telegram не вызывается reconciliation-путём.

## Не входит

Новый Telegram adapter, новый storage/API контракт и бесконечный worker loop.

## Размер сессии

Кандидат на одну сессию после закрытия зависимостей. Перед ready проверить готовность адаптеров, транзакций и test harness по [workflow](../workflow.md). Недостающие предпосылки не реализовывать скрытно.
