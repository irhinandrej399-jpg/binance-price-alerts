# CON-002 — Определить событие изменения подписки

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [CON-001](CON-001.md), [DEC-004](DEC-004.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `medium` (Medium).
- Обоснование: Схема уже опирается на принятый протокол активации; главное — точные поля, версия и round-trip цены.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Одна схема SubscriptionChanged.

## Критерии приёмки

- По [DEC-007](../../decisions/DEC-007.md): изменение сохраняет позицию и конец целой транзакции C, версию подписки и event_id. Полнота replay/маркеры границ позволяют отличить пропуск от не влияющей на проекцию записи.

- По [ADR DEC-004](../../decisions/DEC-004.md): передаются незавершённые состояния и workflow ID/версия; исходный снимок — для порога/аудита, не разрешение отправки. Граница подключения — latest-price, не replay от создания.
- Есть ID подписки, версия, состояние, пара, порог, направление и согласованная граница активации.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Contract-тесты создания и отключения; round-trip точной цены без float64.

## Не входит

Изменение БД и доставка события.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).
