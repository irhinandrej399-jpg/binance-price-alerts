# SET-008 — Подготовить сервисные полномочия внутренних gRPC-вызовов

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [SET-007](SET-007.md), [DEC-009](DEC-009.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Аутентификация и авторизация требуют отказных сетевых проверок и защиты credentials.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Переиспользуемая проверка сервисной идентичности и прав на unary RPC по DEC-009.

## Критерии приёмки

- Описаны и реализованы способ передачи и проверки сервисных credentials, защищённый транспорт и соответствие доверенной идентичности разрешённым полным именам RPC. Не вводить пользовательский вход или выдачу новых пользовательских сессий.
- Политика запрещает вызов при отсутствии/неверных credentials и при отсутствии права на метод; публичный пользовательский Bearer-токен сам по себе не даёт сервисных прав. Неизвестные методы запрещены по умолчанию.
- Конфигурация и ошибки не раскрывают credentials; тестовые credentials изолированы от рабочих. Документированы конфигурация клиента/сервера и подключение политики будущими сервисами.
- На сетевой основе SET-007 проверены разрешённый вызов, отсутствие/неверные credentials, доверенный сервис без права на метод и отказ защищённого соединения с недоверенным peer. При отказе прикладной handler не исполняется.
- Выбранный механизм совместим с конечным deadline и отменой; конкретные права и бюджет MKT-006 задаются в MKT-006. Если обнаружится несогласованное продуктовое/архитектурное решение, зафиксировать его до реализации.
- Выполнены применимые [общие критерии готовности](../workflow.md).

## Проверка / воспроизведение

Red → Green → Refactor для разрешённого и запрещённых unary-вызовов через сетевой helper SET-007; go test -race ./..., go vet ./..., go build ./.... Проверить документацию конфигурации без рабочих секретов.

## Не входит

Продуктовые RPC, развёртывание PKI/secret manager, выдача пользовательских сессий, runtime и автоматические повторы операций.

## Размер сессии

Кандидат на одну сессию после проверки зависимостей и доступности инструментов. Не включать продуктовый RPC или runtime четырёх сервисов.
