# MAT-011 — Передать партицию после отказа matcher

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [MAT-010](MAT-010.md)

Разделённый исходный тикет: [MAT-006](MAT-006.md).

## Модель для сессии

- Модель: `gpt-6-astra` (GPT-6 Astra).
- Уровень размышления: `high` (High).
- Обоснование: Failover и запоздалые действия старого владельца требуют проверки fencing и продолжения с безопасного checkpoint.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Failover-путь с продолжением от безопасного checkpoint.

## Критерии приёмки

- По [DEC-007](../../decisions/DEC-007.md): после revoke старый владелец прекращает работу; новый повышает durable fencing token и восстанавливает SQL-checkpoint/незавершённых кандидатов и последние цены до ready. Запоздалый SQL-update старого token отклоняется даже если Kafka rebalance уже завершён; запросы API идемпотентны. Ack не обгоняет durable результат.

- Старый владелец после потери полномочий не продвигает checkpoint; новый продолжает незавершённую работу.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Остановить владельца в середине цены и проверить итоговые trigger_id; запоздалый результат старого владельца безопасен.

## Не входит

Первичное распределение и нагрузочное исследование.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).
