# MKT-014 — Ограничить буфер принятых цен

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [MKT-013](MKT-013.md), [DEC-007](DEC-007.md), [MKT-017](MKT-017.md)

Разделённый исходный тикет: [MKT-007](MKT-007.md).

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Нужно ограничить ресурсы и точно определить принятую работу при отказе брокера, не потеряв порядок и данные молча.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Очередь публикации с ограниченной ёмкостью и согласованной политикой backpressure.

## Критерии приёмки

- По [DEC-008](../../decisions/DEC-008.md): in-flight ограничены одновременно 1 024 записями и 16 MiB на процесс; событие ≤4 KiB. Учитываются клиентские буферы и фактическая RAM. Закрытие нового durable приёма по дисковому ledger остаётся отдельной OPS-016.

- По [DEC-007](../../decisions/DEC-007.md): один действующий relay на фиксированный publish-шард, новый producer fences прежний до продолжения outbox; ревизии пары публикуются последовательно, SQL-отметка только после Kafka commit. Ограничение памяти/in-flight и backoff не удаляют принятые записи. Нельзя менять число партиций без миграции.

- По [DEC-006](../../decisions/DEC-006.md): очередь использует готовый SQL-outbox MKT-017 и producer MKT-013: claim/повтор/подтверждение публикации переживают рестарт. Отметка отправки только после ack, повтор сохраняет event_id; ошибка/переполнение не удаляют принятую работу молча. Новая схема хранения не входит в эту задачу.

- Предел памяти/ёмкости задан; отказ брокера и переполнение наблюдаемы; соблюдено определение принятой durable работы.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Недоступный брокер и заполненный буфер не дают неограниченного роста; после восстановления принятые сообщения доходят по контракту.

## Не входит

Новый broker adapter и восстановление внешних сделок во время disconnect.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).
