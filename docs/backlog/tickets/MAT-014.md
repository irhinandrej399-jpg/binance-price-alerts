# MAT-014 — Подготовить durable проекцию снимка для SQL-replay

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [MAT-001](MAT-001.md), [MAT-007](MAT-007.md), [SUB-022](SUB-022.md), [DEC-007](DEC-007.md)

Выделен при сессионной проверке [MAT-008](MAT-008.md) 29 октября 2026.

## Модель для сессии

- Модель: `gpt-6-astra` (GPT-6 Astra).
- Уровень размышления: `high` (High).
- Обоснование: Инициализация на C и независимые SQL/Kafka checkpoints требуют проверить атомарность и отсутствие отката при повторе.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Правила выбора](../MODELS.md).

## Один результат

Один storage-контракт matcher: полное поколение MAT-007 становится изолированной версионированной проекцией на C, принимающей целые SQL-транзакции после C без выдуманных Kafka offsets.

## Критерии приёмки

- Инициализация использует только полное durable поколение MAT-007; сохраняет все поля after-image, optional/workflow/blocked, точные цены/времена и исходную C (uint64). Пустой снимок поддержан. Повтор не сбрасывает уже применённый replay и не заменяет рабочую проекцию.
- Целые CON-002 транзакции из SUB-022 применяются строго после durable C; after-images и C фиксируются одной SQL-транзакцией. Пропуск, частичная транзакция и неверный контракт отклоняются без продвижения; terminal tombstones и версии не откатываются.
- SQL-replay не создаёт и не продвигает Kafka offset. Kafka-путь MAT-001 сохраняет свою семантику: дубли до durable C безопасны, NextOffset относится только к реально обработанному непрерывному префиксу. Синтетические Topic/NextOffset для SQL запрещены.
- Повторы после потери ответа/commit и конкурентные повторы сериализованы; durable checkpoint читается для последующего AcknowledgeReplay в MAT-008. Сам storage не подтверждает API и не объявляет readiness.
- Имеется чтение/обход полного поколения для сборки индекса и подключения пар в MAT-008; чтение не смешивает поколения. Интерфейс и ошибки документированы.
- Проверки выполнены на готовом disposable PostgreSQL harness с race detector, включая rollback после after-image до checkpoint, повтор через другой pool и C выше 2^53; выполнены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Неполный/пустой/многостраничный снимок; инициализация и повтор после replay; create/cancel после C; workflow и terminal tombstone; дубли/старые версии; пропуск/частичная транзакция; rollback и потеря ответа после commit; конкурентные повторы. SQL-replay не меняет Kafka NextOffset, а Kafka-дубль после SQL-replay может продвинуть только транспортную позицию.

## Не входит

RPC-цикл handoff/pages/ack, Kafka polling, активация рабочего поколения, readiness/цены, restart-координатор MAT-009, consumer group/fencing и runtime.
