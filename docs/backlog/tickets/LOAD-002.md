# LOAD-002 — Создать источник цен для нагрузочного стенда

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [DEC-008](DEC-008.md), [CON-003](CON-003.md), [MKT-013](MKT-013.md), [MKT-014](MKT-014.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Источник должен контролировать реальную скорость и давать независимый эталон срабатываний, иначе результаты нагрузки будут недостоверны.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Детерминированный генератор входных цен с заданной скоростью.

## Критерии приёмки

- По [DEC-008](../../decisions/DEC-008.md): 1 000 цен/с по 100 парам; обычный поток по 10/с, hot-pair — 500/с на горячую пару. Фиксировать source ID/ревизии, manifest пары→партиции, темп attempted/accepted и задержку источника. Поддержать 100 новых сохраняющихся условий/с для обычного опыта и отдельный burst 10 000 разных подписок за 1 с; поздняя ревизия не сбрасывает контрольное t0.

- Воспроизводятся обычный поток и горячая пара; известно ожидаемое множество trigger_id.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Проверка / воспроизведение

На малом наборе сопоставить выдаваемые цены эталонным срабатываниям; скорость измеряется, не предполагается.

## Не входит

Генерация миллионов Telegram-запросов.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).
