# OPS-024 — Измерить manifest операций владельца API

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [OPS-023](OPS-023.md), [SUB-009](SUB-009.md), [SUB-020](SUB-020.md), [SUB-027](SUB-027.md)

Выделен из [OPS-021](OPS-021.md) при сессионной проверке 4 ноября 2026.

## Модель для сессии

- Модель: `gpt-6.1-sol`.
- Уровень размышления: `high` (High).
- Обоснование: Транзакционные переходы API и потерянный ответ публикации требуют связи исходных ID с физическими дублями.

Это рекомендация, а не переключение модели. [Условия выбора](../MODELS.md).

## Один результат

Версионированный manifest и отчёт физических затрат API с экспортом устойчивых идентичностей для продолжений.

## Критерии приёмки

- Через готовые adapters под api_runtime измерить create, первый workflow, отмену, prepare/admission и исходы, journal/outbox/claim/mark. Для каждой операции перечислить входные размеры, контрактные ограничения и максимальный batch; параметризованные пределы фиксировать явно, отсутствие конечного предела считать блокирующим пробелом. Не вводить новые продуктовые лимиты.
- Использовать runner OPS-023 и готовые loopback mTLS/HTTP helpers. Setup аккаунтов/канала/котировок и соединений отделить от измерений; чужой SQL доступен только диагностике. Без runtime четырёх процессов и реальных Binance/Telegram.
- Измерить отдельные фазы повторных версий, первой публикации обоих API relay, потерянного commit-ответа через существующий kafkafault и повторной публикации с физическим дублем. Зафиксировать фактический исход неизвестного commit; read_committed проверяет bytes/event_id и разные offsets, каждая попытка имеет отдельное окно затрат.
- Экспортировать source ID, subscription/event/trigger/attempt ID, journal position, исходные bytes и порядок переходов для OPS-025/026. Связать затраты с каждой фазой, не включать в них setup. Формат и coverage явно отмечают ещё не измеренные продолжения.
- Сохранить manifest, raw обоих collectors, версии/хэши/команды, empty, реальную запись и повтор с чистого состояния. Проверить формат, обязательные метрики и cleanup. Unsupported и непокрытый класс блокируют квалификацию OPS-018; функциональный race suite не заменяет измерений.

## Проверка

Disposable PostgreSQL/Kafka; контрольные опыты и проверка raw/формата отчёта. Инфраструктурная проверка без искусственных unit-тестов. Недоступная проверка не считается успешной.

## Не входит

Измерения SQL matcher/notifications, новый общий runner/collector, market-data источник, квоты и ledger.

## Размер сессии

Перед ready проверить прямые интерфейсы зависимостей и один измерительный проход по [workflow](../workflow.md). Новую независимую предпосылку выделить до реализации; при нескольких самостоятельных результатах уточнить разделение.
