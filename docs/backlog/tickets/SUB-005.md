## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Отмена одновременно меняет версию и доступный слот; повторы и конкурирующие отмены не должны освобождать его дважды.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Один endpoint идемпотентного отключения подписки. Canonical отмена готова здесь; journal/outbox отмены — SUB-012/021, допуск/результаты попыток — SUB-017/019/020, runtime — отдельные задачи.

## Критерии приёмки

- По [ADR DEC-004](../../decisions/DEC-004.md): отмена до допуска запрещает отправку; после допуска отмена запрещает новые попытки и явно возвращает возможность сообщения в полёте. Все незавершённые состояния отменяемы; поздний результат слот повторно не освобождает.
- Обновление проверяет владельца и версию; повтор не освобождает слот дважды.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Контракт результата

- `subscription.NewCancelHandler(Beginner)` — `DELETE /v1/subscriptions/{id}` под auth.New. Контракт ответа/ошибок и схема композиции: [README](../../../internal/api/subscription/README.md#http-отмена-sub-005).
- READ COMMITTED: user lock → собственная subscription FOR UPDATE → UPDATE с проверкой owner/version/state → ReleaseTerminal → commit. Все четыре незавершённых состояния переходят в cancelled с version+1; blocked снимается, порог/процент/workflow сохраняются. Cancelled/delivered и их версии не меняются. Сервер проверяет текущую версию; клиент не передаёт precondition, чтобы повтор отменял любое текущее незавершённое состояние.
- HTTP 200 содержит id/state/version/message_may_be_in_flight. Предупреждение консервативно true для недоставленной подписки с workflow, включая active/blocked/cancelled: ранее допущенную неоднозначную попытку без истории исключить нельзя. Workflow сохраняется, повтор после рестарта не теряет предупреждение. Это не утверждение, что отправка точно началась; точную историю добавляют отдельные задачи.
- Чужой/отсутствующий ID — одинаковые 404, неверный UUID — 400, отсутствие сессии — 401, сбой транзакции/MaxInt64 — безопасный 500. До commit нет успешного ответа. Telegram-привязка для отмены не требуется. Схема БД не меняется.
