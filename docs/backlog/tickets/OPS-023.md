# OPS-023 — Подключить внешние фазы к совместному измерительному runner

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [OPS-019](OPS-019.md), [OPS-020](OPS-020.md)

Выделен из [OPS-021](OPS-021.md) при сессионной проверке 4 ноября 2026.

## Модель для сессии

- Модель: `gpt-6.1-sol`.
- Уровень размышления: `high` (High).
- Обоснование: Границы двух collectors, жизненный цикл ресурсов и проверка неполных отчётов требуют согласованного управления фазами.

Это рекомендация, а не переключение модели. [Условия выбора](../MODELS.md).

## Один результат

Один disposable runner запускает доверенный внешний adapter между снимками PostgreSQL и Kafka, сохраняя общий протокол фаз.

## Критерии приёмки

- Переиспользовать сбор метрик OPS-019/020; выделить вызываемые интерфейсы снимков и lifecycle без копирования collectors. Kafka сейчас жёстко привязана к internal/tools/kafkameasure, PostgreSQL — к двум окнам empty/adapter: новая точка расширения должна принимать последовательность setup → baseline → именованные фазы → verification. Драйвер может оставаться живым между фазами; каждая фаза завершается явным ack, ошибкой или timeout.
- Один запуск владеет уникальными disposable PostgreSQL/Kafka проектами, портами, prefix и чистыми volumes; применяет штатные миграции четырёх владельцев. Runtime DSNs передаются adapter через environment, диагностический SQL остаётся у runner. Credentials не сохраняются. Рабочие/load volumes не адресуются.
- Определить версию manifest/report: source ID, phase ID, размеры/единицы/max batch, связи event_id/trigger_id/attempt_id, хэши исходников/manifest/схем, версии контрактов и образов, время и ссылки на raw двух collectors. Setup/background/checkpoint отделены; unknown/unsupported и незавершённые фазы блокируют qualified. Семантику checkpoint/FPI и файловых снимков OPS-019/020 сохранить.
- Проверить empty и реальную запись через готовые account.Repository.Create и kafka.New/Publish, затем повтор с новыми чистыми volumes. Это контроль интерфейса, без бизнес-цепочки. Сохранить команды/raw/отчёт; проверить cleanup при успехе, ошибке adapter и timeout. Проверка формата отвергает отсутствующую фазу/метрику и unknown вместо нуля. Полный функциональный/race suite не запускать.

## Проверка

Disposable PostgreSQL/Kafka; контрольные опыты и проверка raw/формата отчёта. Инфраструктурная проверка без искусственных unit-тестов. Недоступная проверка не считается успешной.

## Не входит

Бизнес-manifests API/matcher/notifications/market-data, новые метрики, fault-сценарии бизнес-цепочки, таблица стоимости и ledger.

## Размер сессии

Перед ready проверить прямые интерфейсы зависимостей и один измерительный проход по [workflow](../workflow.md). Новую независимую предпосылку выделить до реализации; при нескольких самостоятельных результатах уточнить разделение.
