# OPS-019 — Собрать физические метрики PostgreSQL на disposable стенде

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [SET-006](SET-006.md), [DEC-008](DEC-008.md)

Выделен из [OPS-017](OPS-017.md) при проверке размера 4 ноября 2026.

## Модель для сессии

- Модель: `gpt-6.1-sol`.
- Уровень размышления: `high` (High).
- Обоснование: Контроль WAL, checkpoint, фоновых записей и физических размеров требует проверки границ измерения.

Это рекомендация, а не переключение модели. [Условия выбора](../MODELS.md).

## Один результат

Изолированный сборщик PostgreSQL с машиночитаемыми исходными снимками и дельтами вокруг заданной последовательности операций.

## Критерии приёмки

- Использовать compose/migrate из SET-006: отдельный disposable проект, явные migrations всех четырёх владельцев, без функциональных failure fixtures и параллельного полного test suite. Рабочие и load volumes не адресуются; cleanup проверен при успехе и ошибке.
- Зафиксировать версии/digest, схему, durability, исходное состояние и команды. Диагностический доступ к четырём БД есть только у runner; вызов реального adapter выполняется под runtime-ролью владельца. Credentials не входят в отчёт.
- Снимать heap/индексы/TOAST с раздельным учётом fork и без двойного счёта, WAL и временные страницы/файлы. Различать логическую дельту WAL и выделенное место WAL-сегментов. Документировать единицы, сброс/задержку статистики и границы снимков.
- Определить протокол checkpoint/full-page writes и фоновых записей; fsync count/time учитывать отдельно, без ослабления durability. Недоступная метрика помечается unsupported и блокирует квалификацию соответствующего компонента, а не заменяется нулём.
- Сохранить сырые снимки и отчёт: пустой контроль, запись через существующий storage adapter, повтор с новым чистым volume. Изменение входа должно быть отделимо от шума; ограничения и округление страниц описаны.

## Проверка

Disposable стенд; контрольные опыты и проверка сырых данных/формата отчёта по критериям выше. Для инфраструктуры искусственные unit-тесты не нужны. Функциональный race runner не заменяет измерений.

## Не входит

Manifest бизнес-сценариев, Kafka collector, таблица стоимости, ledger и нагрузочная квалификация.

## Размер сессии

Перед ready проверить интерфейсы зависимостей и один измерительный проход. Если нужен новый независимый механизм, сначала уточнить границу, не скрывать его в опыте.
