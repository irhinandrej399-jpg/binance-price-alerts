# OPS-077 — Оформить наблюдение и обслуживание постоянного стенда

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [DEC-011](DEC-011.md), [OPS-074](OPS-074.md), [OPS-014](OPS-014.md), [OPS-002](OPS-002.md), [OPS-003](OPS-003.md), [OPS-079](OPS-079.md)

## Модель для сессии

- Модель: `gpt-6.1-sol`.
- Уровень размышления: `medium`.
- Обоснование: Подключение существующих сигналов и безопасного maintenance без дискового ledger.

Рекомендация, не переключение модели. [Условия выбора](../MODELS.md).

## Один результат

Минимальный эксплуатационный runbook с рабочими проверками здоровья, диска и очередей.

## Критерии приёмки

- Использовать существующие health/readiness/метрики: выход процесса, отключённый feed, возраст цены, ошибки БД/relay, pending/blocked delivery и рост очереди. Дать команды диагностики и конкретные начальные пороги предупреждений, настраиваемые под хост; не обещать измеренный SLO.
- Добавить проверку свободного диска для data volumes и ротацию логов, понятное предупреждение и действия оператора. При фактической ошибке записи операция не успешна; сохранять outbox. Точное резервирование физических затрат, inode tracer и capacity ledger не нужны.
- Оформить provisioning/периодический запуск существующего Kafka cleaner с полным обязательным inventory, durable registry и запретом очистки при unknown. Не включать age/size deletion принятых событий. Описать SQL рост, снимки/pins и безопасные существующие процедуры; отсутствующую SQL-очистку вынести отдельной задачей при доказанной необходимости.
- Проверить одно срабатывание каждого основного сигнала на малом fixture, доставку операторского предупреждения через выбранный канал (локальная проверка без внешних сообщений), отказ cleaner при unknown и отсутствие секретов в логах.

## Проверка

Только относящиеся к изменению unit/integration проверки, один небольшой smoke
на имеющихся средствах и обязательные проверки CI. Для поведения Red → Green;
для deployment/docs — проверка команд и фактического запуска, без искусственных
unit-тестов. Отсутствующую предпосылку не разрабатывать скрытно.

## Границы и сессионная проверка

Минимальное наблюдение и существующая maintenance-команда. Большая observability платформа, измерительные collectors и автоматическая потеря данных ради места не входят.

Перед ready сверить фактические интерфейсы и размер по [workflow](../workflow.md).
При независимых результатах разделить; новая рекомендация модели объём не заменяет.
