# IAM-005 — Проверять сессию на защищённом endpoint

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [IAM-004](IAM-004.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Middleware определяет доверенный user_id и должен отклонять подделку/истечение, поэтому ошибки здесь затрагивают изоляцию пользователей.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Middleware, возвращающий проверенный user_id.

## Критерии приёмки

- Отсутствующая, истёкшая или поддельная сессия отклоняется; user_id из запроса не заменяет владельца.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

HTTP-тесты корректной сессии, истечения, подмены и отсутствия credentials.

## Не входит

Администраторские роли.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).

## Ход работы

- Добавлены internal/api/auth/{auth.go,auth_test.go,README.md}. auth.New проверяет единственный Authorization Bearer, auth.UserID возвращает владельца из закрытого ключа context. Query/body user_id и X-User-ID не заменяют владельца.
- Red: `GOTOOLCHAIN=local go test ./internal/api/auth` сначала упал из-за отсутствия implementation; с компилируемой заглушкой упал поведенчески: отсутствующие/некорректные credentials пропускались с 200 вместо 401. `python3 scripts/check_postgres.py` с заглушкой также упал в TestProtectedEndpointWithPostgres: trusted owner lost (200 с пустым ID).
- Первый запуск PostgreSQL внутри sandbox был недоступен из-за Docker socket; повтор с разрешённым доступом выполнил поведенческий Red. Только disposable binance-go-check, рабочая БД не затронута, volume удалён.
- Green / Refactor: `GOTOOLCHAIN=local go test ./internal/api/auth` — exit 0 (opt-in PostgreSQL пропущен). Упрощён JSON отказа; итоговый `python3 scripts/check_postgres.py` — exit 0, все пакеты с `go test -race -count=1 -v ./...`, TestProtectedEndpointWithPostgres PASS, disposable volume удалён.
- HTTP-проверки: валидный токен и регистр Bearer, доверенный ID при чужом query/body/header ID, отсутствие credentials и токен только в query, неверная схема/пустые/дублированные заголовки, поддельный и неканонический токен, истечение до/на/после границы, закрытый pool и отменённый context. Отказ не вызывает защищённый handler; 401 одинаковы и содержат Bearer challenge, 500 не раскрывают детали.
- `GOTOOLCHAIN=local go vet ./...` — exit 0; `GOTOOLCHAIN=local go build ./...` — exit 0, повтор с доступом к Go cache убрал sandbox-предупреждение записи stat cache. `git diff --check` и `python3 scripts/backlog.py check` — exit 0.
- Критерии приёмки выполнены, done. Продуктовые роли и новое поведение других endpoints не добавлены.
