# OPS-010 — Корректно остановить matcher

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [MAT-005](MAT-005.md), [OPS-053](OPS-053.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: SIGTERM посреди цены должен согласовать checkpoint и незавершённых кандидатов с последующим рестартом.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Graceful shutdown matcher с безопасным checkpoint.

## Критерии приёмки

- Новая работа не принимается; незавершённая цена возобновляется после рестарта.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

SIGTERM после частичного списка кандидатов; итоговые уникальные trigger_id совпадают с эталоном.

## Не входит

Graceful shutdown остальных сервисов.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).

## Реализация — 7 ноября 2026

- cmd/matcher/main.go: SIGTERM/SIGINT через signal.NotifyContext; readiness снимается,
  intake/оценки/RPC отменяются, HTTP Shutdown получает 2 с. Replica/readers/Kafka
  присоединяются и SQL grants отзываются до pool.Close и закрытия RPC clients.
  Принятый буфер — SQL Pending/исходы; drain-to-empty при сигнале не требуется.
- Общий предел выхода после сигнала — 20 с, включая joins и pool.Close. Штатная
  отмена с успешным cleanup даёт exit 0; ошибка компонента/HTTP/SQL cleanup — exit 1.
  Watchdog превышения предела завершает с безопасным сообщением и exit 1, без
  удаления durable работы. Бюджеты revoke готовой replica — 3 с на проход.
- replica.ErrCleanup помечает ошибки именно revoke, сохраняя errors.Is при
  объединении с context.Canceled. Владелец не маскирует неотозванную SQL authority
  штатной отменой. Семантика fencing/Prefix/Recover не изменена.
- Сохранён настоящий SIGKILL/restart OPS-053. Затем тот же executable проверяется
  на новом dataset/group: частичные кандидаты, первый durable результат, следующий
  API commit до ответа → SIGTERM. Требуются reaped exit 0 без fallback harness Kill,
  отзыв всех 16 grants, закрытый HTTP, неизменные Pending/исходы и отсутствие
  преждевременного SQL Prefix/broker ack. Новая подходящая Latest → restart с теми
  же identity/bootstrap → все принятые кандидаты имеют ровно один outbox и
  canonical trigger_id, первоначальный ответ и результаты неизменны, Pending пуст,
  SQL/broker Prefix сходятся. Проверены SIGINT после ready и exit 1 при реальной
  SQL row lock на authority во время revoke.
- Process.ExitCode даёт только безопасные reaped metadata; lifecycle test различает
  живого ребёнка и signal exit -1. Использован существующий lifecycle/runner,
  без второго harness. Fixture Seed выделяет chat_id из случайного UUID владельца
  вместо одного фиксированного binding для всех dataset.
- Бюджет всей Go-серии runner для matcher увеличен до 150 с (внешний 180 с):
  исходные crash/startup имеют локальный бюджет 85 с, graceful/recovery/SQL fault —
  60 с. Предел одного shutdown не расширен; gracefulness проверяется до 18 с,
  harness fallback — 22 с, product watchdog — 20 с.
