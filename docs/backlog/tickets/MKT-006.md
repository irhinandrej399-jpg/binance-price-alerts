# MKT-006 — Выдать последнюю известную котировку с возрастом

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [MKT-005](MKT-005.md), [DOM-005](DOM-005.md), [DEC-003](DEC-003.md), [DEC-004](DEC-004.md), [MKT-017](MKT-017.md), [DEC-009](DEC-009.md), [SET-007](SET-007.md), [SET-008](SET-008.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `medium` (Medium).
- Обоснование: Интерфейс последней котировки строится на готовых фильтре и freshness; проверяются отсутствие цены и рестарт.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Внутренний интерфейс последней котировки с монотонной ревизией, временем и предупреждениями.

## Критерии приёмки

- По [DEC-009](../../decisions/DEC-009.md): внутренний интерфейс реализуется как unary gRPC с Protocol Buffers, сервисными полномочиями и конечным deadline; изменяющие операции сохраняют идемпотентность. Контрактные проверки включают сетевой адаптер, deadline и недоступность зависимости. Перед ready проверить готовность генерации и test harness; отсутствующие общие предпосылки выделить отдельно.

- По [DEC-006](../../decisions/DEC-006.md): последняя цена/ревизия и статус потока читаются через готовое хранилище MKT-017 в БД market-data; рестарт не обновляет время сделки и не подтверждает поток автоматически.

- По [ADR DEC-004](../../decisions/DEC-004.md): последняя цена и её ревизия читаются согласованно; поддержаны повторные чтения при проверке доставки, без хранения истории ради исчезнувших возможностей.
- По [ADR DEC-003](../../decisions/DEC-003.md): Котировка, каталог и состояние потока принадлежат market-data. API обращается к внутреннему интерфейсу, сохраняя в подписке только неизменяемую исходную котировку; прямого чтения хранилища market-data нет.
- Возвращаются цена, source ID, время и признак свежести; после рестарта сохранённая цена не объявляется подтверждённо актуальной, но может выдаваться с предупреждением.
- По [ADR DEC-002](../../decisions/DEC-002.md) возвращаются время сделки и время приёма отдельно; возраст оценивается при запросе по времени сделки. Возраст > 5 секунд даёт stale и предупреждение, но цена остаётся доступна. Отдельно передаётся известное состояние потока: разрыв/неподтверждённая актуальность дают предупреждение независимо от возраста, включая рестарт. Возраст не доказывает disconnect; одно открытие соединения не подтверждает сохранённую цену. Недоступность — missing/invalid_time. Чтение, reconnect и replay не обновляют время сделки.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Тесты отсутствующей цены, новой, устаревшей, out-of-order обновления и рестарта; границы 5 секунд, будущего времени, позднего приёма и старения без новых сделок на исправном соединении. Старая цена возвращается с предупреждением; при разрыве и после рестарта корректная сохранённая цена доступна с отдельным предупреждением, даже если она моложе 5 секунд. Проверить независимость возраста и состояния потока.

## Не входит

Публичный график цен и история.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).
