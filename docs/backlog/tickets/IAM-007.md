# IAM-007 — Проверять подлинность Telegram webhook

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [SET-001](SET-001.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `medium` (Medium).
- Обоснование: Один защитный контракт webhook можно проверить через правильный, отсутствующий и неверный секрет до входа в обработчик.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Один защищённый endpoint приёма Telegram update.

## Критерии приёмки

- Проверяется секрет webhook; невалидный запрос не достигает обработчика; регистрация webhook описана без секретов в репозитории.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

HTTP-тесты правильного, отсутствующего и неверного секрета.

## Не входит

Привязка аккаунта и пользовательские команды бота.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).

## Ход работы

- 27 октября 2026: сессионная проверка пройдена. SET-001 done подтверждён go.mod, Go 1.26.3 и cmd; рабочее дерево до старта чистое. Контракт Telegram сверён по официальному setWebhook. Достаточно net/http/httptest из стандартной библиотеки; новых зависимостей и test harness не требуется. Выполнены planned → ready → in-progress → done.
- Один результат — защищённый HTTP-адаптер `internal/api/telegramwebhook`, как у остальных API handlers без подключения пустого cmd/api. Метод/путь: POST /v1/telegram/webhook. Обработка Update передаётся next; привязка и команды остаются IAM-008.
- Конструктор проверяет секрет (1–256 разрешённых ASCII-символов) и наличие next. Ровно один заголовок X-Telegram-Bot-Api-Secret-Token, сравнение SHA-256 constant-time. Неверный секрет: 403 invalid_webhook_secret до чтения тела. Дубли, пробелы, неверные значения и подмена query не проходят. Ошибки не раскрывают секрет.
- Red: `GOTOOLCHAIN=local go test ./internal/api/telegramwebhook` на пропускающей заглушке завершился FAIL: запросы без верного секрета достигали next и читали тело; неверные конфигурация и маршруты принимались.
- Green/refactor: та же команда и `GOTOOLCHAIN=local go test -race ./internal/api/telegramwebhook` — PASS. Проверены правильный, отсутствующий, пустой, неверный секреты, дубли, комбинированный заголовок, формат/границы конфигурации, маршруты, передача тела и ответа next без изменений.
- `GOTOOLCHAIN=local go test ./...` — PASS; opt-in PostgreSQL-тесты без стенда пропущены, новый адаптер БД не использует. Первый build/vet упёрся в sandbox для стандартного Go cache; повтор с кэшами /tmp завершён успешно (см. команды ниже).
- Итог: `GOTOOLCHAIN=local GOCACHE=/tmp/binance-iam-007-go-build GOMODCACHE=/tmp/binance-go-mod GOPATH=/tmp/binance-gopath GOPROXY=off GOSUMDB=off go build ./...` и та же среда для `go vet ./...` — PASS. `git diff --check`, `python3 scripts/backlog.py check` — PASS.
- README пакета описывает подключение, HTTPS, безопасную регистрацию через setWebhook с окружением без секретов в репозитории, проверку ответа и ответственность update handler за повторы. Пример Python проверен синтаксически, сетевой вызов не выполнялся.
- Критерии приёмки выполнены на уровне HTTP-адаптера. Реальные credentials и публичный runtime не требовались и не использовались.
