# OPS-034 — Замкнуть модель ссылок и идентичности work inode

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [OPS-033](OPS-033.md), [OPS-040](OPS-040.md), [OPS-041](OPS-041.md)

Выделен из [OPS-031](OPS-031.md) 5 ноября 2026 при проверке размера сессии.

## Модель для сессии

- Модель: `gpt-6.1-sol`.
- Уровень размышления: `high` (High).
- Обоснование: Alias, inode reuse, наследование и kernel references требуют единой модели полноты и независимых контролей.

Это рекомендация, а не переключение модели. [Условия выбора](../MODELS.md).

## Один результат

Проверяемая модель владения work inode, сохраняющая его lifetime независимо от имени и номера FD в явно ограниченном профиле.

## Критерии приёмки

- На основе capture OPS-033 задать поддержанный профиль PG/ABI/io_method, paths и изоляции внешних владельцев. Сохранить исходные FD/maps и достаточные pathname/identity свидетельства; custom tablespaces либо покрыть, либо блокировать опыт.
- Вести поколения dev/inode, reopen/dup/fcntl, fork/clone/exec/exit, shared FD tables и workers, hardlinks/rename/path crossing, unlink-open и последний reference. Shared inode считается один раз для кластера. Исчезновение pathname само по себе не завершает lifetime.
- Разобрать queued SCM_RIGHTS, mmap и другие kernel references: поддержать с доказательствами либо обнаруживать и блокировать затронутый опыт. Полноту FD inventory не выводить только из известных ptrace children. Новые/потерянные процессы, внешние aliases и неполные inventories дают unknown.
- Реальными FS контролями проверить alias/наследование/reuse, уход имени за work root, unlink-open, queued FD после закрытия отправителя и mapping после close; независимые stat подтверждают identity/size/nlink и интервалы существования. Проверить PG ordinary/shared filesets и полноту backend/worker lineage.
- Raw verifier воспроизводит lifetimes и отвергает пропуски identity/lineage/reference свидетельств; сохранить hashes/команды/cleanup. Опубликовать поддержанный envelope и входной контракт для OPS-035. До доказательства size classifier численные границы остаются null.

## Проверка

Реальные disposable Linux filesystem/PostgreSQL контроли по критериям выше,
raw replay и отказные случаи; инфраструктурные проверки без искусственных
unit-тестов наличия файлов. Сохранить воспроизведение и фактические результаты.
