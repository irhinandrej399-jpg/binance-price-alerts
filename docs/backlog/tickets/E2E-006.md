# E2E-006 — Подтвердить реальный запуск и доставку перед выпуском

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [DEC-011](DEC-011.md), [OPS-075](OPS-075.md), [OPS-076](OPS-076.md), [OPS-077](OPS-077.md), [E2E-007](E2E-007.md), [OPS-080](OPS-080.md), [NTF-017](NTF-017.md), [NTF-019](NTF-019.md)

## Модель для сессии

- Модель: `gpt-6.1-sol`.
- Уровень размышления: `medium`.
- Обоснование: Один реальный пользовательский smoke и release checklist без нагрузочной квалификации.

Рекомендация, не переключение модели. [Условия выбора](../MODELS.md).

## Один результат

Честный итог готовности конкретного deployment: один рабочий сценарий через Binance и собственный Telegram chat.

## Критерии приёмки

- Использовать подготовленный production-профиль, домен/HTTPS, bot credentials и доступный webhook. Данные хоста и разрешение на развёртывание/внешнее сообщение получить при выполнении; не добавлять их в Git. Без них результат blocked, не PASS по fake.
- Регистрация/вход → привязка собственного chat → создание подписки на реально обслуживаемую пару → наблюдаемая цена → одно уведомление → сохранённый API receipt/освобождённый слот. Также одна отмена. Выбирать близкий достижимый порог вручную, без торговли и массовой рассылки.
- Проверить версии deployment, приватность внутренних портов, мониторинг, наличие проверенной резервной копии и инструкции restart/update/rollback с учётом совместимости миграций. Открытые дефекты, лимиты и known gaps записать.
- Готовность заявляется только для фактически проверенного малого deployment. Не требовать million/p99/kernel proofs; не обещать HA, exactly-once Telegram или восстановление пропущенных внешних сделок.

## Проверка

Только относящиеся к изменению unit/integration проверки, один небольшой smoke
на имеющихся средствах и обязательные проверки CI. Для поведения Red → Green;
для deployment/docs — проверка команд и фактического запуска, без искусственных
unit-тестов. Отсутствующую предпосылку не разрабатывать скрытно.

## Границы и сессионная проверка

Реальный smoke не должен создавать новый harness или исправлять независимые дефекты. Это финальная проверка, не автоматический публичный деплой в сессии ревизии бэклога.

Перед ready сверить фактические интерфейсы и размер по [workflow](../workflow.md).
При независимых результатах разделить; новая рекомендация модели объём не заменяет.
