# OPS-053 — Собрать минимальный процесс matcher

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [MAT-011](MAT-011.md), [MAT-015](MAT-015.md), [SUB-016](SUB-016.md), [OPS-007](OPS-007.md), [OPS-052](OPS-052.md), [DEC-010](DEC-010.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Сборка готовой реплики должна сохранить SQL fencing, bootstrap, durable Pending и Prefix; нужны process проверки с реальными зависимостями.

Это рекомендация, а не смена модели; см. [MODELS](../MODELS.md).

## Один результат

Работающий cmd/matcher над готовой replica с конфигурацией, mTLS clients и HTTP health, пригодный для отдельной проверки SIGTERM в OPS-010.

## Критерии приёмки

- До готовности валидируются HTTP_ADDR, matcher DSN, Kafka/topics,
  Environment/Group/устойчивый уникальный replica ID, mTLS endpoints/credentials
  Snapshot/Replay/Delivery/Latest, live budgets и полная явная map bootstrap
  для 16 prices partitions. Нет выбора нуля/конца или broker commit вместо
  bootstrap/SQL Prefix. Миграции отдельно, секреты не логируются.
- Подключены готовые replica.New/Run, snapshotload и Snapshot client,
  Replay/Delivery/Latest clients. Snapshot callback задаёт допустимый стабильный
  request ID для opaque projection ID; Changes создаёт новый changefeed.Source
  с Register/RegisterAt по переданной позиции и владеет его Close.
  Scope/TransportKey/SQL grants/проекция не переизобретаются в cmd.
- OPS-007 подключён к HTTP listener, собственному pool.Ping и replica.Status;
  до bootstrap/recovery/первой оценки readiness 503, после — 200. Ошибки SQL/RPC/
  Kafka и истёкший pin не приводят к тихому reset; terminal Run завершает
  владельца, startup failure освобождает открытые ресурсы.
- Через OPS-052 запускается настоящий executable: полная view/Latest,
  несколько кандидатов → canonical API trigger_id/outbox и durable результаты,
  SQL Prefix до broker ack. После управляемого аварийного завершения restart
  с теми же identity/bootstrap продолжает SQL-состояние без потери принятых
  исходов; не создаёт второй workflow/outbox для уже принятой подписки.
- Проверены config/startup failure и terminal dependency failure. README
  содержит config, команду запуска/проверки и ограничения минимального runtime.
  Если выявлен отсутствующий adapter, выделить его до реализации, а не
  расширять этот тикет новой архитектурой.

## Сценарии TDD (Red → Green → Refactor)

Config/startup → готовность после recovery → цена/кандидаты → canonical workflow/Prefix → crash/restart с SQL-прогрессом. Использовать готовый OPS-052; graceful сигнал здесь не заявлять.

## Не входит

Graceful SIGTERM/drain OPS-010, runtime API/market-data/notifications, автоматическая смена поколения при потере pin, полный E2E и нагрузка.

[workflow](../workflow.md). Локальный профиль — [DEC-010](../../decisions/DEC-010.md).
