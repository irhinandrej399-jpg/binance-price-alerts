# OPS-040 — Проверить reference witnesses и повторить PostgreSQL capture

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [OPS-038](OPS-038.md), [OPS-039](OPS-039.md)

Выделен из [OPS-037](OPS-037.md) после реального preflight 5 ноября 2026.

## Модель для сессии

- Модель: `gpt-6.1-sol`.
- Уровень размышления: `high` (High).
- Обоснование: Независимые reference witnesses, queued SCM_RIGHTS без FD и полный tamper verifier требуют сопоставления реальных контролей.

Это рекомендация, а не переключение модели. [Условия выбора](../MODELS.md).

## Один результат

Проверенный на реальных reference controls и ordinary/parallel PostgreSQL
комплект raw evidence по всем исходным критериям OPS-037, с входным контрактом OPS-034.

## Критерии приёмки

- Использовать готовые inventory/lifecycle capture и verifiers OPS-038/039.
  Расширить существующий runner OPS-033 reference fixture, не разрабатывать
  ещё один capture или фазовый harness.
- Реальные alias/dup/fcntl, наследование/shared FD table, exec/exit,
  повторное использование имени/FD/inode, rename за root и unlink-open.
  Повторно использовать прямые controls зависимостей, сохранив их evidence.
  Фактический inode reuse подтвердить независимыми stat; если не получен,
  указать именно это ограничение, не объявлять его проверенным.
- Отдельные синхронизированные интервалы queued SCM_RIGHTS после закрытия
  отправителем всех source FD до receive и до drop; отдельный mmap после
  close/unlink. Независимые stat/fstat/checkpoints подтверждают identity,
  size/nlink и удержание. Unsupported references обнаруживаются/блокируются
  даже без оставшегося FD; отсутствие FD не завершает lifetime.
- Полный artifact verifier требует inventory/lifecycle/census/isolation и
  независимые helper witnesses; проверяет их связь и обязательные поля.
  Удаление/подмена/неполная опись, включая queue-only/mapping-only интервал,
  отвергается либо явно incomplete/unknown. Tamper вызывает полный verifier
  после пересчёта hashes/seq, не только decoder или проверку checksum.
- Повторить ordinary/parallel PG capture готовым runner на disposable Linux;
  сохранить backend/worker inventories, независимый census/ptrace comparison,
  Linux/ABI/PG/io_method/work paths/mounts/namespaces/isolation, проверку
  default/custom tablespaces, raw/source/binary hashes, команды и cleanup.
  Не заявлять полноту при несогласованном checkpoint или внешних aliases.
- Опубликовать контракт входа OPS-034 и точные пределы evidence. Сверить
  каждый исходный критерий контейнера OPS-037 с результатом OPS-038–040;
  пробелы не объявлять закрытыми. Lifetime/last reference ещё не доказаны:
  peak/lower/upper=null, qualification blocked.

## Проверка

Реальные disposable Linux filesystem/PostgreSQL controls, полный artifact
verifier и rehashed/resequenced tamper, cleanup. Без искусственных unit-тестов.

## Не входит

Разработка inventory/lifecycle capture, reducer поколений/lifetimes OPS-034,
classifier/bounds OPS-035, самостоятельный observer OPS-036, фазовый runner
OPS-023/032 и квалификация квот.
