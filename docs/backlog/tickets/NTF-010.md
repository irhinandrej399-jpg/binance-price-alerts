# NTF-010 — Сохранить успешную доставку

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [NTF-003](NTF-003.md), [NTF-009](NTF-009.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Подтверждённый успех известной попытки нельзя терять после lease; свидетельство, pending report и состояние задания должны сохраняться согласованно.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Атомарное сохранение свидетельства успеха с message_id и обязанностью сообщить API; смена текущей аренды защищена fencing.

## Критерии приёмки

- По [ADR DEC-004](../../decisions/DEC-004.md): вместе с durable свидетельством успеха сохраняется обязанность сообщить API (NTF-014), а не только закрыть локальную работу. Подтверждённый ответ известной попытки, пришедший после lease, сохраняется как свидетельство без изменения чужой текущей аренды.
- После сохранённого успеха повторная обработка не отправляет сообщение; потеря ответа БД разобрана явно.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Тесты success, повторного завершения и результата устаревшего lease.

## Не входит

Exactly-once при внешнем таймауте.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).
