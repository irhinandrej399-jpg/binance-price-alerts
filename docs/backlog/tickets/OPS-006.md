# OPS-006 — Добавить health и readiness market-data

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [MKT-006](MKT-006.md), [MKT-015](MKT-015.md), [MKT-016](MKT-016.md), [DEC-010](DEC-010.md)

## Модель для сессии

- Модель: `gpt-6-luna` (GPT-6 Luna).
- Уровень размышления: `high` (High).
- Обоснование: Health adapter отображает уже готовые состояния feed; reconnect не должен ошибочно превращаться в liveness-сбой.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Проверки жизнеспособности и готовности приёмника цен.

## Критерии приёмки

- Локальный профиль [DEC-010](../../decisions/DEC-010.md): readiness учитывает инициализацию и собственное хранилище; квалификация дисковых квот отложена. Ошибка записи не становится успехом.

- По [ADR DEC-002](../../decisions/DEC-002.md) readiness различает запуск, работающий поток и наблюдаемый разрыв; возраст последней сделки сам по себе не доказывает disconnect и не делает поток неготовым; liveness не превращает каждый reconnect в аварийный рестарт.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Fake feed: запуск, свежая цена, disconnect, восстановление; состояния соответствуют контракту. Редкая пара без новых сделок на исправном потоке не трактуется как disconnect по одному возрасту цены.

## Не входит

Readiness остальных процессов.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).

## Ход работы

- 6 ноября 2026: сессионная проверка пройдена. MKT-006/015/016 и DEC-010 done подтверждены интерфейсами latest/storage, streamplan и reconciler. Новый harness не требуется: fake feed и httptest проверяют HTTP-компонент. Runtime wiring не входит в этот результат. Рекомендация Luna High сообщена; настройки модели не менялись. planned → ready.
- ready → in-progress. Контракт: GET /healthz без зависимостей; GET /readyz — инициализация, bounded probe собственной БД и актуальное подтверждение feed. В readiness JSON отдельно передаётся starting/unconfirmed/disconnected/live; live означает все потоки текущего плана подтверждены, без возрастного порога и без сброса исторического gap.
- Добавлены `internal/marketdata/health/health.go`, `health_test.go`, `postgres_test.go`, `README.md`. `New` принимает probe собственной БД и актуальный aggregate feedSnapshot; единый deadline и отмена HTTP, отсутствие кэширования, безопасный конкурентный SetInitialized. GET/HEAD healthz не вызывает зависимости; readyz отдаёт 200 только для initialized + storage OK + live, иначе 503 с нормализованным состоянием feed. Ошибки/неизвестные значения не раскрываются.

Проверены startup/unconfirmed/live/disconnected/recovery, отсутствие зависимости от возраста сделок, отказ/восстановление БД, liveness без probes, nil/unknown/error, timeout/cancel на обоих этапах даже при nil error, снятие initialized во время probe, HTTP routing/headers и конкурентные запросы.
- Refactor: gofmt и проверка структуры; callbacks не дублируют существующие generation/Accept/SetStatus/reconnect. Контракт runtime, исторического gap и отсутствия гарантии будущей записи явно описан в README. Новая архитектура ingest не добавлялась.
