# OPS-006 — Добавить health и readiness market-data

Статус: `planned`. Приоритет определяется зависимостями, а не номером.

Зависимости: [MKT-006](MKT-006.md), [MKT-015](MKT-015.md), [MKT-016](MKT-016.md), [OPS-016](OPS-016.md)

## Модель для сессии

- Модель: `gpt-6-luna` (GPT-6 Luna).
- Уровень размышления: `high` (High).
- Обоснование: Health adapter отображает уже готовые состояния feed; reconnect не должен ошибочно превращаться в liveness-сбой.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Проверки жизнеспособности и готовности приёмника цен.

## Критерии приёмки

- По [DEC-007](../../decisions/DEC-007.md), используя готовый ограничитель OPS-016 (его реализация не входит в health-задачу): исчерпание бюджета SQL-outbox/диска останавливает durable приём с наблюдаемым разрывом Binance; незафиксированная цена не объявляется принятой. Пороги задаёт DEC-008, принятые записи не удаляются.

- По [ADR DEC-002](../../decisions/DEC-002.md) readiness различает запуск, работающий поток и наблюдаемый разрыв; возраст последней сделки сам по себе не доказывает disconnect и не делает поток неготовым; liveness не превращает каждый reconnect в аварийный рестарт.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Fake feed: запуск, свежая цена, disconnect, восстановление; состояния соответствуют контракту. Редкая пара без новых сделок на исправном потоке не трактуется как disconnect по одному возрасту цены.

## Не входит

Readiness остальных процессов.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).
