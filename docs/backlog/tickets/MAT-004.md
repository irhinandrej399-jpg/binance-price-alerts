# MAT-004 — Обработать цену и запросить фиксацию кандидатов

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [MAT-002](MAT-002.md), [MAT-007](MAT-007.md), [MAT-008](MAT-008.md), [MAT-009](MAT-009.md), [MKT-013](MKT-013.md), [MKT-014](MKT-014.md), [SUB-013](SUB-013.md), [SUB-014](SUB-014.md), [MAT-012](MAT-012.md), [MAT-016](MAT-016.md), [SUB-025](SUB-025.md)

## Модель для сессии

- Модель: `gpt-6.1-sol` (GPT-6.1 Sol).
- Уровень размышления: `high` (High).
- Обоснование: Обработка кандидатов пересекается с отменой и устаревшими версиями; вызывается канонический атомарный переход.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Один handler PriceObserved, вызывающий согласованный атомарный переход у владельца.

## Критерии приёмки

- По [ADR DEC-004](../../decisions/DEC-004.md): handler проверяет последнее состояние пары из готового адаптера, старые ценовые события не создают исторические уведомления.
- Запрашивает через SUB-014 один устойчивый workflow; дубли/отмена/устаревшая версия безопасны, новые события не откатывают цену. Ack после durable результата либо явного superseded.
- Использует готовое хранилище MAT-016: результат/незавершённые кандидаты сохраняются до подтверждения цены; C подписок не подменяет ценовой checkpoint. SUB-014 получает owner/subscription ID и ожидаемую версию, цену читает сам API. Ошибка Unavailable/DeadlineExceeded не считается superseded; Aborted/FailedPrecondition обрабатываются по контракту с повторной выборкой актуального состояния, без разбора текста ошибки.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Новая цена, дубль, 101→99 к моменту обработки, отмена между выборкой и запросом работы; после подключения при последней 101 запрос без ожидания нового пересечения.
