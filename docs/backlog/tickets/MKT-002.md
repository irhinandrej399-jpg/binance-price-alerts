# MKT-002 — Декодировать одно событие сделки Binance

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [CON-003](CON-003.md), [DOM-001](DOM-001.md)

## Модель для сессии

- Модель: `gpt-6-luna` (GPT-6 Luna).
- Уровень размышления: `high` (High).
- Обоснование: Преобразование одного вида сделки в готовую схему — узкий adapter с известными полями и негативными fixtures.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Адаптер raw trade либо aggTrade в PriceObserved.

## Критерии приёмки

- Выбран один источник цены последней сделки; сохраняются source ID и время; malformed payload не становится нулевой ценой.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Fixtures корректного события, большого ID, точной дроби, неизвестного типа и неверной цены.

## Не входит

Сетевое соединение.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).

## Ход работы

- 27 октября 2026: сессионная проверка пройдена; рабочее дерево чистое, CON-003 и DOM-001 подтверждены интерфейсами и тестами. Один результат — чистый adapter raw trade → PriceObserved; сеть и хранилище не нужны. Выбран raw `trade`, источник `binance-spot-trade`; параметры ревизии, приёма и состояния потока предоставляет вызывающий код. Карточка переведена planned → ready.

- Реализация прошла ready → in-progress → done. Рекомендация карточки GPT-6 Luna · High сообщена; настройки модели не менялись. Выбор источника записан в [MKT-002 ADR](../../decisions/MKT-002.md).
- Добавлены `internal/marketdata/trade/decode.go`, `decode_test.go`, `README.md`, две синтетические fixtures в `testdata/`. Decode возвращает валидный PriceObserved либо zero result с ErrInvalidTrade/ErrUnsupportedEvent; сохраняет ID uint64 (включая максимум), точную цену 18/18, независимые T/E и исходный приём в UTC. Ревизия, gap и stream state передаются явно без выдумывания durable состояния.
- Red: `GOTOOLCHAIN=local go test ./internal/marketdata/trade` — FAIL, `no non-test Go files`: реализация отсутствовала, тесты уже заданы.
- Green: та же команда — PASS. Fixtures покрывают корректное событие, максимальный ID, точную дробь, милли-/микросекунды и поздний приём. Негативные сценарии: aggTrade/неизвестный тип, отсутствующие/null e/s/t/p/T/E, неправильные JSON-типы, неверная/нулевая/отрицательная/непредставимая цена, переполнение ID/времени, malformed JSON, combined wrapper и неверные метаданные. Проверено отсутствие частичного результата.
- Refactor: gofmt; точное чтение ключей вместо регистронезависимого fallback encoding/json, общая проверка готового Observed через CON-003. Тесты отсутствующих t/T и e/E защищают от подмены поля другим регистром.
- Первые общие race/vet/build ограничены sandbox: системный Go-кэш и запись module cache недоступны; race также встретил запрет локального httptest listener в готовом каталоге MKT-001. Эти попытки не считались успешными.
- Итоговые проверки с `GOCACHE=/tmp/binance-go-build GOMODCACHE=/tmp/binance-go-mod GOTOOLCHAIN=local`: `go test -race ./...`, `go vet ./...`, `go build ./...` — PASS; race выполнен с разрешённым выходом из sandbox для локального listener. Opt-in PostgreSQL integration по умолчанию пропущены; они к чистому декодеру не относятся.
- `git diff --check`, `python3 scripts/backlog.py check` — PASS. Все критерии MKT-002 выполнены; live WebSocket и runtime не запускались.
