# DEC-007 — Выбрать брокер событий

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [DEC-003](DEC-003.md), [DEC-004](DEC-004.md), [DEC-006](DEC-006.md)

## Модель для сессии

- Модель: `gpt-6-astra` (GPT-6 Astra).
- Уровень размышления: `high` (High).
- Обоснование: Брокер нужно оценить вместе с порядком по паре, retention, ack и replay; решение влияет на восстановление нескольких сервисов.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

ADR с одним брокером и моделью доставки.

## Критерии приёмки

- По [DEC-006](../../decisions/DEC-006.md): граница принятия market-data — PostgreSQL commit котировки и SQL-outbox; API использует журнал с транзакционным C и материализованные снимки. Согласовать порядок публикации/дедупликацию с C, durable pins и прогрессом потребителей; offset брокера автоматически не считается C.

- По [ADR DEC-004](../../decisions/DEC-004.md): разделить replay изменений подписок и обновление последнего состояния цен. Исчезнувшие ценовые условия не восстанавливаются, но workflow/результаты/ack durable. Обосновать S/C, retention, snapshot expiration и latest-price bootstrap.
- По [ADR DEC-003](../../decisions/DEC-003.md): API публикует изменения подписок и срабатывания из своего outbox, market-data публикует принятые цены; matcher и notifications сохраняют результаты обработки у себя. Уточнить durable публикацию рыночной работы и границы ack без распределённой транзакции сервисов.
- Определены порядок по паре, подтверждения, повторное чтение, хранение, повторная доставка и поведение при перегрузке.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Проверка решения

Проследить сбой до и после publish/ack и восстановление индекса из снимка и потока.

Тип: решение, исполняемых тестов не требуется. Решение записать в `docs/decisions/` и обновить требования и зависимые карточки.

## Не входит

Создание кластера и оптимизация производительности.

## Размер сессии

Оценка: **кандидат на одну сессию после закрытия зависимостей**, не подтверждённый `ready`.
Для старта нужны только эта карточка, применимые ADR, готовые интерфейсы из зависимостей и относящийся к поведению код. Если требуется выбрать протокол, реализовать недостающую зависимость или менять независимое поведение, карточка сначала уточняется либо делится по [сессионной проверке](../workflow.md#сессионная-проверка-перед-ready).
