## Один результат

Воспроизводимый disposable harness для измерения физических затрат существующих durable adapters по DEC-008.

## Критерии приёмки

- Используются готовые PostgreSQL/Kafka runners и реальные adapters; рабочие volumes/topics не затрагиваются. Фиксируются версии, durability, конфигурация, исходное состояние, последовательность операций и сырые результаты.
- Измеряются дельты heap/индексов/TOAST, WAL, временных страниц и физических Kafka log/index/segment/transaction затрат; fsync учитывается отдельно. Определено влияние checkpoint/full-page writes, фоновых записей и округления сегментов; неподдержанное измерение явно блокирует квалификацию.
- Сценарий задаётся manifest: размеры входа, максимальный batch, повторные версии, первая публикация, дубль после потерянного commit-ответа и служебные переходы. Идентичности связывают затраты API с продолжением в matcher/notifications и отделяют источник market-data; чужие БД доступны диагностическому runner, не приложениям.
- Проверка harness: пустой контроль, запись через реальный adapter, повтор из чистого состояния; сырые данные и команды сохранены. Функциональный race runner не подменяет измерение физических затрат.

## Проверка

Disposable PostgreSQL/Kafka; контрольные прогоны и проверка формата отчёта. Это инфраструктура измерений, искусственные unit-тесты не нужны.

## Не входит

Квалифицированная таблица стоимости, выбор квот, ledger/admission, новые бизнес-переходы, полный нагрузочный fixture и заявление о достаточности 200 GiB.

## Размер сессии

Перед ready проверить готовые runners и диагностические интерфейсы. Если необходим независимый механизм сбора, уточнить декомпозицию до реализации; не включать продуктовый ограничитель.
