# MAT-012 — Подключить подписку к последней цене

Статус: `done`. Приоритет определяется зависимостями, а не номером.

Зависимости: [MAT-001](MAT-001.md), [MAT-002](MAT-002.md), [MKT-006](MKT-006.md), [MKT-013](MKT-013.md), [MKT-014](MKT-014.md), [DEC-004](DEC-004.md), [MAT-013](MAT-013.md)

Выделен при уточнении [DEC-004](DEC-004.md); не реализуется внутри задачи решения.

## Модель для сессии

- Модель: `gpt-6-astra` (GPT-6 Astra).
- Уровень размышления: `high` (High).
- Обоснование: Регистрация обновлений и чтение последней цены должны сходиться по ревизии без окна и отката при конкурентном обновлении.

Это рекомендация для выбора перед запуском, а не автоматическая смена модели. [Условия выбора и повышения уровня](../MODELS.md).

## Один результат

Один адаптер подключения/повторного подключения подписки к последнему состоянию пары.

## Критерии приёмки

- По [DEC-007](../../decisions/DEC-007.md): регистрация read_committed обновлений предшествует чтению latest из market-data; монотонная ревизия не откатывается при replay. При смене владельца/потере ценового cursor повторить bootstrap; исчезнувшие исторические условия не восстанавливаются.

- Зарегистрировать обновления до чтения MKT-006; объединить snapshot и обновления по монотонной ревизии, выставить ценовую готовность после согласования.
- Старый снимок не откатывает новое обновление; после сбоя/недоступности котировки регистрация восстанавливается, готовность не заявляется преждевременно.
- Подключение передаёт последнее состояние готовому обработчику кандидатов; исторический временный true, исчезнувший к проверке, не восстанавливается.
- Выполнена указанная ниже проверка; соблюдены [общие критерии готовности](../workflow.md).

## Сценарии TDD (Red → Green → Refactor)

Управляемый источник: обновление до/во время/после чтения, поздний старый snapshot, 99→101→99 до подключения, переподключение и ошибка MKT-006. Состояние соответствует последней ревизии, нет пропуска последующего обновления.

## Не входит

Создание брокера, новый WebSocket adapter, terminal-переход API, доставка Telegram и нагрузочные измерения.

## Размер сессии

Кандидат на одну сессию после закрытия зависимостей. Перед ready проверить готовность адаптеров, транзакций и test harness по [workflow](../workflow.md). Недостающие предпосылки не реализовывать скрытно.
