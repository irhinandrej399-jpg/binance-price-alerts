# Работа по тикетам с агентом

Одна новая сессия на один тикет — удобный режим этого проекта. Состояние передаём через файлы репозитория. Для нового агента важны текущие файлы и незавершённый diff; пересылать весь предыдущий чат не требуется.

## Где что хранится

| Файл | Назначение |
| --- | --- |
| [AGENTS.md](../AGENTS.md) | Постоянный порядок работы агента |
| [STATE.md](STATE.md) | Краткая сводка текущей системы и активного ID |
| [requirements.md](requirements.md) | Утверждённое поведение и границы проекта |
| [Карточки](backlog/README.md) | Единственный источник статуса, объёма и результата конкретной задачи |
| [ORDER.md](backlog/ORDER.md) | Единый порядок выполнения: от ранних задач к поздним |
| [MODELS.md](backlog/MODELS.md) и раздел модели в карточке | Рекомендация модели и reasoning для конкретного тикета |
| [decisions/](decisions/README.md) | Принятые архитектурные и продуктовые решения |
| Код, конфигурация, тесты, Git diff | Фактически реализованное состояние |

Codex поддерживает `AGENTS.md` как инструкции проекта. Явное указание прочитать его в стартовом запросе также делает пакет контекста понятным другому агенту. `STATE.md` и журналы в карточках — наше соглашение; это не встроенные автоматические хранилища памяти. Основание: [официальная документация OpenAI](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

## Как выбрать следующий тикет

Из корня проекта:

```sh
python3 scripts/backlog.py next
python3 scripts/backlog.py show DEC-001
```

`next` показывает первую незавершённую карточку из [ORDER.md](backlog/ORDER.md). Если есть `in-progress` или `review`, команда сначала показывает уже начатую работу. Для просмотра следующих пяти пунктов используй `next --limit 5`: это предварительная очередь, а не пять одновременно разрешённых задач. DEC означает обсуждение решения; `planned` требует проверки сессионного размера и артефактов до ready.

Порядок закреплён в ORDER.md и проверяется по зависимостям. Начало: DEC-001 → DEC-008 по возрастанию, затем SET-001, SET-002 и DOM-001 → DOM-005; далее — остальные строки очереди. Если решение меняет зависимости или задача делится, обновляй очередь в том же изменении.

Перед новой сессией посмотри рекомендацию модели/размышления в next или карточке и выбери доступную пару в селекторе клиента. Подпись в Markdown сама настройки приложения не меняет. Для DEC-001 назначена GPT-6.1 Sol · Medium; принципы, ограничения доступности и повышение уровня — в MODELS.md.

## Запрос для одного implementation-тикета

Замени `DOM-003` на выбранный ID:

```text
Работаем только над тикетом DOM-003.
Прочитай AGENTS.md, docs/STATE.md и docs/backlog/tickets/DOM-003.md.
Проверь готовность зависимостей и фактическое состояние кода.
Если тикет готов к одной сессии, выполни его через TDD и проверь критерии приёмки.
Если не готов, зафиксируй причину и нужную зависимость или предложи разделение.
В конце обнови карточку, индекс бэклога и STATE.md, выполни backlog.py check.
После выполнения всех критериев самостоятельно создай коммит по docs/GIT.md.
Следующий тикет в этой сессии не начинай.
```

Это пример шаблона, а не утверждение, что DOM-003 сейчас доступен. По тому же шаблону можно взять SET-001, заменив TDD на указанную в карточке проверку инфраструктуры.

## Запрос для решения DEC

```text
Работаем только над DEC-001.
Прочитай AGENTS.md, docs/STATE.md и карточку DEC-001.
Исследуй нужные факты, предложи конкретную семантику с примерами границ.
Открытые продуктовые решения согласуй со мной.
После согласования запиши ADR, обнови требования, статус и STATE.md, создай коммит по docs/GIT.md.
Реализацию приложения и следующий тикет не начинай.
```

После согласования DEC закрывается как выполненная задача решения; это не означает готовности соответствующего Go-кода.

## Как продолжить незавершённую задачу

```text
Продолжи DOM-003 по AGENTS.md, STATE.md и передаче в карточке.
Сначала сверь записи с текущими файлами и diff, если есть Git.
Заверши только оставшиеся критерии и проверки этого тикета.
```

При незапланированном обрыве журнала может ещё не быть. Тогда агент сверяет код, статус и тесты, восстанавливает точку остановки и дополняет карточку. Одной старой фразы «тесты проходят» недостаточно.

## Что агент записывает после сессии

В самой карточке добавляются два раздела; отдельный бесконечный глобальный журнал не нужен:

```markdown
## Ход работы

- Дата / ID сессии: ...
- Изменённое поведение и файлы: ...
- Red: команда, ожидаемая причина падения, фактический результат.
- Green / итоговая проверка: команды и фактические результаты.
- Критерии приёмки: выполнены / не выполнены, какие именно.
- Ветка и предыдущий commit при продолжении: если есть. SHA нового коммита агент сообщит после его создания.

## Передача следующей сессии

- Статус: done / review / in-progress / planned / decision.
- Что осталось и почему: ...
- Следующее конкретное действие: ...
- Существенные файлы, ADR, известный сбой и способ воспроизведения: ...
```

Для документов/инфраструктуры вместо Red/Green указываются соответствующие проверки. Секреты, токены и дампы личных данных в журнал не попадают. STATE содержит только краткую навигацию; подробности остаются в карточке.

## Завершение и проверка

После результата можно попросить отдельную сессию ревью:

```text
Проверь результат DOM-003 по критериям карточки и текущему diff.
Начни с чтения AGENTS.md и STATE.md.
Проверь корректность поведения, TDD-проверки и отсутствие выхода за объём.
Запиши замечания со ссылками на файлы и строки. Другие тикеты не реализуй.
```

Ревью — отдельный выбранный режим, а не обязательный новый барьер для каждой карточки. `done` ставится по выполненным критериям; недоступная проверка и незавершённая работа не обозначаются как успех. Синхронизацию карточки с индексом проверяет:

```sh
python3 scripts/backlog.py check
```

## Git и сохранение состояния

Агенту уже поручено инициализировать локальный Git и самостоятельно коммитить каждый завершённый тикет. Дописывать разрешение к каждой новой сессии не требуется: оно закреплено в AGENTS.md. Используются текущие настройки автора Git.

Порядок и пример скрипта: [GIT.md](GIT.md). Обычно один завершённый тикет даёт один коммит `type(ID): описание` с пояснением изменений и проверок. Карточка, индекс и STATE сохраняются вместе с результатом. SHA выводится в конце сессии и доступен в Git log; его собственная копия внутри того же коммита не требуется.

Для текущего этапа достаточно последовательной работы в main. Локальные файлы доступны следующей сессии в этой же папке; на другой машине или в отдельном checkout нужно сначала доставить туда нужные commits и рабочие изменения. Закрытие локального тикета не запускает публикацию в remote.
