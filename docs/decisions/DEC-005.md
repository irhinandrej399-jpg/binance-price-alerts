# DEC-005 — Telegram-привязка и возобновление подписки

Дата: 26 октября 2026, Europe/Moscow.
Статус: **принято**.
Карточка: [DEC-005](../backlog/tickets/DEC-005.md).

## Контекст, варианты и согласование

API владеет Telegram-привязкой. По DEC-004 подписка занимает слот до подтверждённой доставки или отмены; отправка требует проверки последней цены.

Для создания рассмотрены: требовать привязку заранее либо принимать без канала и вводить ожидание первоначальной привязки. Выбран первый вариант: без Telegram создание отклоняется, слот не расходуется.

Для потери канала рассмотрены: отмена и новая подписка после исправления либо автоматическое возобновление прежней. Владелец 26 октября выбрал автоматическое возобновление с сохранением порога, проверкой текущей цены при перепривязке и без сохранения отдельной цены блокировки. Вариант ручной отмены/пересоздания отклонён. Решение уточняет DEC-004: остановка отправки в delivery_blocked сохраняется до исправления канала; исправление привязки теперь возобновляет соответствующие подписки.

## Создание и адресат

- Без привязки создание возвращает HTTP 409 с кодом `telegram_not_linked`; подписка, workflow и outbox-событие не создаются, слот не расходуется. Проверка привязки и сохранение подписки согласованы транзакцией API с конкурентным изменением канала.
- При допуске каждой попытки API проверяет текущую привязку, каноническое состояние и последнюю цену. Разрешение фиксирует chat и монотонную версию привязки для одной попытки. Событие работы не является источником актуального адресата; notifications не читает таблицы API.
- Изменение привязки и допуск сериализуются API. Если изменение сохранено первым, старый chat не получает нового допуска. Если первым сохранён допуск, разрешённый запрос может завершиться на прежний chat. Следующая попытка получает текущую привязку. Ограничитель чата применяется к фактическому адресату; смена чата не позволяет обойти лимитер.
- Ошибка чтения API не доказывает отсутствие привязки: попытка откладывается без отправки и потери работы.

## Блокировка и данные

- Если перед допуском привязки нет, отправки нет: API сохраняет delivery_blocked с видимой причиной `telegram_not_linked`. Задание сохраняется, слот занят; отмена доступна. Невозможность доставить из-за заблокированного бота/невалидного chat тоже отмечается как проблема канала.
- Для blocked хранятся причина и версия привязки, на которой возникла проблема. **Отдельная цена на момент блокировки не нужна.** Она не используется как основание будущей отправки.
- Сохраняются прежние ID подписки/workflow, направление, фиксированный порог и исходный снимок создания. Отказ от цены блокировки не отменяет согласованное хранение исходной цены/времени и диагностических результатов попыток. Процент при перепривязке не пересчитывается.

## Автоматическое возобновление

После успешной перепривязки API увеличивает версию привязки. Подписки, заблокированные из-за прежнего канала, автоматически возобновляются без отмены и повторного создания. Отсутствие новых рыночных событий не мешает проверке.

Для восстановления используется периодическая durable проверка того же задания notifications через защищённый допуск API. Настраиваемый интервал с backoff не удерживает lease и слот лимитера во время ожидания; перезапуск восстанавливает назначенную проверку. Это проверка возможности возобновления, а не бесконечные sendMessage на заблокированный chat. При той же/отсутствующей привязке отправка запрещена. Событие перепривязки через брокер для этого механизма не требуется.

При новой версии канала API читает последнюю известную корректную цену у market-data по DEC-002/004:

- Условие истинно: прежняя работа снова допускается к доставке; перед каждой фактической попыткой действует проверка последней цены DEC-004. Разрешение относится только к одной непосредственной попытке после лимитеров.
- Условие ложно: прежняя подписка возвращается в active и продолжает ждать прежний порог. Workflow/job сохраняется; старое достижение порога не отправляется.
- Цена недоступна/некорректна: отложенная повторная проверка; работа не теряется, отправки нет.

Переходы канонического состояния API сохраняет с версией подписки и outbox изменения по DEC-004. Для ошибок канала новая версия позволяет новый цикл попыток того же job, без второго workflow. Исчерпание попыток по иной причине не снимается одной перепривязкой. Дубликаты проверок/запоздалый отказ старой версии не откатывают возобновлённую работу; отменённая или доставленная подписка не возрождается. Новые допуски не выдаются при другой действующей попытке; достоверный поздний успех учитывается по DEC-004.

## Граничные сценарии

| Сценарий | Результат |
| --- | --- |
| Нет Telegram при создании, цена подходит | 409 telegram_not_linked, нет подписки и расхода слота |
| Привязка исчезла до допуска | Нет sendMessage; blocked с причиной и версией канала, слот занят, отдельная цена блокировки не нужна |
| up, порог 100; при перепривязке цена 101 | Тот же workflow продолжает доставку; перед попыткой новая проверка |
| При блокировке было 101, при перепривязке 99 | Нет сообщения о 101; active ждёт 100, порог неизменен |
| Цена стала 99 после проверки восстановления | Финальный допуск возвращает wait_condition; отправки нет |
| Процент +5% от 100, при перепривязке цена 120 | Прежний порог 105; не пересчитывается в 126 |
| После перепривязки нет новых ценовых событий | Периодическая проверка читает последнюю цену без ожидания нового пересечения |
| Перепривязка сохранена до фиксации отказа старой попытки | Отказ содержит старую версию; следующая проверка обнаружит новую привязку и возобновит работу |
| Повтор перепривязки/проверки, рестарт | Один workflow/job, тот же слот; проверка восстанавливается durable |
| Cancelled/delivered или blocked по иной причине | Перепривязка не возрождает подписку и не снимает постороннюю причину |
| Ошибка чтения привязки/цены | Отложить, не отправлять по старым данным |

## Последствия и границы

Требования и карточки DOM-004, IAM-008, SUB-003/017/018/019, CON-004 и NTF-008/012/014 уточнены. Периодическое восстановление выделено в NTF-015; это отдельная planned-задача, не реализация внутри DEC. Список подписок показывает blocked и причину через SUB-004.

Сохранены владельцы DEC-003, слот, workflow и гарантии условной доставки DEC-004. Другие каналы, новые публичные endpoints отвязки, повторная активация delivered/cancelled и Go-код не входят. Наличие привязки не гарантирует доступность Telegram: внешний отказ остаётся наблюдаемым.
