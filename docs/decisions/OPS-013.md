# OPS-013 — Общая квота публичной аутентификации

Дата: 6 ноября 2026. Статус: **принято**.
Карточка: [OPS-013](../backlog/tickets/OPS-013.md).

Пользователь принял предложенную политику ответом «Принять предложенную политику»:
20 попыток за фиксированную минуту на IP совместно для регистрации и входа,
включая успешные и неуспешные запросы. IP берётся из RemoteAddr без доверия
X-Forwarded-For. Общее состояние принадлежит PostgreSQL API. Превышение даёт
429 с Retry-After; недоступность хранилища — 503 без обработки credentials.

Окна UTC полуоткрытые [начало минуты, следующая минута). Production-время
получается из PostgreSQL после блокировки строки IP; приложение не задаёт
собственные часы. Откат часов не возвращает старую квоту. IPv4-mapped IPv6
нормализуется в IPv4. За NAT или reverse proxy все клиенты с одним RemoteAddr
делят квоту; доверенные proxy в этом контракте не настраиваются.

Проверка применяется к POST /v1/accounts и POST /v1/sessions после общего
bodylimit и до JSON/password/storage handlers. 404/405 и отказ bodylimit
не расходуют квоту. Допуск фиксируется до обработки credentials; ошибка
handler его не возвращает. При неизвестном результате commit обработка
не разрешается, хотя попытка могла быть потрачена. Отклонённый лимитером
запрос не увеличивает счётчик. SQL-допуск ограничен одной секундой.

429 возвращает JSON rate_limited и целый округлённый вверх Retry-After до
конца окна; 503 — auth_limit_unavailable. Непригодный RemoteAddr —
400 invalid_request. Ответы лимитера имеют Cache-Control: no-store.
Ни credentials, ни IP не добавляются в логи и labels.

Постоянная строка IP переиспользуется при смене окна. Автоматическая очистка
строк пока отсутствует: объём таблицы растёт с числом уникальных IP.
Фиксированное окно допускает до 40 попыток возле границы двух минут;
это выбранная простая семантика, а не sliding-window защита. Нагрузка,
защита от распределённых источников и production sizing не подтверждаются.
