# DEC-002 — Критерий свежести исходной котировки

Дата: 26 октября 2026, Europe/Moscow.
Статус: **принято**.
Карточка: [DEC-002](../backlog/tickets/DEC-002.md).

## Контекст и проверенные факты

Для процентной подписки нужна исходная цена; по [DEC-001](DEC-001.md) цена создания также определяет уже выполненное условие. Кода приложения пока нет.

В официальном контракте Binance Spot для `trade` и `aggTrade` поле `T` обозначает время сделки, `E` — время события. Временные метки по умолчанию передаются в миллисекундах, есть опция микросекунд. Проверено 26 октября 2026: [WebSocket streams](https://github.com/binance/binance-spot-api-docs/blob/master/web-socket-streams.md#trade-streams). Выбор самого потока остаётся в MKT-002.

Предел 5 секунд — согласованная продуктовая политика проекта, а не гарантия Binance и не результат измерения нагрузки.

## Принятый контракт

1. Возраст исходной котировки: `age = now_utc - traded_at`, где `traded_at` — время сделки Binance `T`, а `now_utc` — текущее UTC-время сервиса, проверяющего котировку для создания. Часы подставляются в тестах. Сравнение выполняется с полной доступной точностью, без округления возраста до целых секунд.
2. Котировка свежая при `0 <= age <= 5 секунд`. Ровно 5 секунд допустимы. Отрицательный возраст, отсутствующая или некорректная временная метка дают `invalid_time`; отрицательный возраст не обнуляется. Отдельный допуск на рассинхронизацию часов в первой версии не вводится. Рабочее предположение — синхронизированные UTC-часы узлов; ошибка часов может временно блокировать создание.
3. Время приёма приложением `received_at` сохраняется отдельно для наблюдаемости и измерения задержек. Приём, чтение кэша, reconnect и replay не заменяют `traded_at` текущим временем и не продлевают свежесть. Время события `E` также не заменяет время сделки `T`.
4. Доменная проверка различает `fresh`, `missing`, `stale` и `invalid_time`. Непроверенная сохранённая цена после рестарта недоступна для создания до подтверждения актуальными рыночными данными, как уже предусмотрено MKT-006; один лишь перезапуск не подтверждает её.
5. Создание подписки обоих видов — по конкретной цене и по проценту — требует свежей исходной котировки. Проверка выполняется на этапе её использования для создания; ранее выданный признак свежести не является бессрочным разрешением. При отсутствии допустимой цены HTTP возвращает `503 Service Unavailable`, стабильный код `quote_unavailable`; подписка не создаётся, активный слот не расходуется. Внутренняя причина сохраняется для диагностики. Протокол согласования снимка и активации остаётся в DEC-004.
6. Эти 5 секунд ограничивают использование исходной котировки при создании. Они не являются TTL уже принятой durable работы и не разрешают отбрасывать рыночные события при задержке matcher или replay. Протокол обработки активных подписок остаётся в DEC-004/007.

При отсутствии новых сделок по малоликвидной паре последняя цена стареет даже при исправном соединении. Создание временно недоступно до новой допустимой котировки; heartbeat не обновляет цену. Восстановление внешних сделок и REST fallback этим решением не добавляются.

Предел возраста не задаёт период обновления: цена обновляется по мере получения сделок выбранного потока, без ожидания пятисекундного интервала.

## Проверка примеров

Фиксируем `now_utc = 2026-10-26T12:00:10.000Z`. Для строк с ценой предполагается подтверждённая котировка, если не указано иное.

| Время сделки / ситуация | Возраст | Доменный результат | Создание |
| --- | --- | --- | --- |
| 12:00:10.000Z | 0 | fresh | Допустимо |
| 12:00:05.001Z | 4,999 с | fresh | Допустимо |
| 12:00:05.000Z | 5,000 с | fresh | Допустимо, граница включена |
| 12:00:04.999Z | 5,001 с | stale | 503 quote_unavailable |
| Цены нет | — | missing | 503 quote_unavailable |
| 12:00:10.001Z | −0,001 с | invalid_time | 503 quote_unavailable |
| Время сделки отсутствует или некорректно | — | invalid_time | 503 quote_unavailable |
| Сделка 12:00:00.000Z получена в 12:00:09.999Z | 10 с | stale | Поздний приём не омолаживает цену |
| Сохранённая цена после рестарта ещё не подтверждена | Любой | Недоступна на уровне интерфейса котировок | 503 quote_unavailable |

Дополнительно: та же сделка 12:00:05.000Z при проверке в 12:00:10.001Z становится stale. Старый ответ `fresh` нельзя повторно использовать без проверки возраста. При отсутствии новой сделки переход через границу происходит и на исправном соединении.

## Рассмотренные варианты

- **Время сделки и предел 5 секунд включительно — выбран.** Учитывает задержки до приложения и ограничивает возраст базы процентного порога. Пять секунд дают небольшой запас на передачу; пригодность для выбранных пар предстоит наблюдать на работающем стенде.
- **Возраст от локального приёма.** Удобен для монотонных часов одного процесса, но задержанная внешняя сделка выглядит новой сразу после получения.
- **Предел 1 секунда.** Более строгая база создания, выше риск отказов при сетевых задержках и редких сделках. Целевая p99 обработки приложения не задаёт этот предел автоматически.
- **Предел 30 секунд или последняя цена без срока.** Повышает доступность создания для редко торгуемых пар, допускает более старую базу процентного порога.

## Последствия

- Контракт закреплён в requirements.md и реестре ADR; зависимые карточки уточнены.
- CON-003: явно различать время сделки `T`, время события `E` при его передаче и время приёма; нормализовать единицы, сохраняя точность.
- DOM-005: чистая проверка с подставными часами, включённой границей 5 секунд и результатами fresh/missing/stale/invalid_time; тесты всей таблицы применительно к доменной функции.
- MKT-006: возвращать исходные временные метки, проверять возраст при запросе, сохранять защиту от непроверенного значения после рестарта.
- SUB-003: проверять свежесть для обоих видов подписок при использовании котировки; 503 quote_unavailable без создания и расхода слота.
- DEC-004: учесть свежесть снимка создания, не превращать её в TTL обработки событий; протокол активации этим ADR не выбирается.
- Статусы и зависимости implementation-карточек этим решением сами по себе не закрываются. Реализация Go не входит в DEC-002.

## Основание согласования

26 октября 2026 владелец ответом «согласен, делай» согласовал предложенный контракт после обсуждения последствий возраста более 5 секунд. Уточнено, что 5 секунд — предел возраста при создании, а не интервал обновления котировки. Протокол активации и реализация приложения остаются за границами DEC-002.
