# DEC-002 — Критерий свежести исходной котировки

Дата: 26 октября 2026, Europe/Moscow; пересмотрено в тот же день.
Статус: **принято, редакция 2**.
Карточка: [DEC-002](../backlog/tickets/DEC-002.md).

## Уточнение DEC-004

26 октября 2026 [DEC-004](DEC-004.md) отменил безусловное позднее уведомление по уже выполненному исходному условию: при подключении/обработке и перед каждой попыткой Telegram проверяется последняя известная цена; исчезнувшее условие означает продолжение ожидания. Упоминания DEC-001 и исходного условия ниже читаются с этим уточнением. Правила возраста, предупреждений, missing/invalid_time и сохранения исходного процентного порога не изменены. Принятая работа не теряется; обработка старого события может явно закончиться результатом «заменено более новой ценой», без исторического уведомления.

## Контекст и проверенные факты

Для процентной подписки нужна исходная цена; по [DEC-001](DEC-001.md) цена создания также определяет уже выполненное условие. Источник — последняя известная сделка выбранной пары Binance Spot. Кода приложения пока нет.

В официальном контракте Binance Spot для `trade` и `aggTrade` поле `T` обозначает время сделки, `E` — время события. Временные метки по умолчанию передаются в миллисекундах, есть опция микросекунд. Проверено 26 октября 2026: [WebSocket streams](https://github.com/binance/binance-spot-api-docs/blob/master/web-socket-streams.md#trade-streams). Выбор самого потока остаётся в MKT-002.

Отсутствие сделок у малоликвидной пары не доказывает потерю связи. При разрыве связи приложение, напротив, может не знать о более новых сделках. Возраст сделки и известное состояние потока передаются отдельно; ни одно из них не гарантирует совпадение с рынком в момент ответа.

## Принятый контракт

1. Используется последняя известная корректная котировка, выбранная по правилам порядка сделок MKT-005. Максимального возраста, запрещающего её использование, нет. Это относится к созданию обоих видов подписок: конкретная цена сравнивается с последней известной, процентный порог рассчитывается от неё. Исходная цена, время сделки и рассчитанный порог сохраняются; порог впоследствии не меняется. Уже выполненное условие обрабатывается по DEC-001.
2. Возраст: `age = now_utc - traded_at`, где `traded_at` — время сделки Binance `T`, `now_utc` — подставляемые часы сервиса в UTC. При `0 <= age <= 5 секунд` доменный результат — `fresh`; при `age > 5 секунд` — `stale`. Возраст не округляется. **Stale означает предупреждение, а не отказ.** Порог 5 секунд сохранён из первой редакции только для предупреждения; это политика проекта, не гарантия Binance.
3. Предупреждение для старой сделки сообщает её время и возраст: «Последняя известная сделка была давно; цена может не отражать текущее состояние рынка». Оно не утверждает, что цена неверна или связь потеряна. В API результата создания возвращаются исходная цена, время сделки, возраст и предупреждения. Дополнительное подтверждение пользователем не требуется; создание с предупреждением остаётся успешным. Это данные ответа, а не периодическая Telegram-рассылка об ошибках.
4. Известный разрыв связи или неподтверждённое состояние потока (включая запуск/рестарт) дают отдельное предупреждение: «Актуальность рыночных данных не подтверждена; новые сделки могли быть пропущены». Оно возвращается даже для сделки моложе 5 секунд. Если корректная последняя цена сохранена, её можно использовать с предупреждением. Одно лишь открытие нового соединения не доказывает актуальность сохранённой цены; правила подтверждения состояния потока фиксируются в рыночных контрактах, а не выводятся из возраста сделки. Исторический разрыв не объявляется восстановленным: пропущенные внешние сделки в первой версии не восстанавливаются.
5. Возраст и предупреждения определяются при использовании котировки для создания. Время приёма `received_at` сохраняется отдельно для наблюдаемости; приём, чтение кэша, reconnect и replay не заменяют `traded_at` текущим временем. Время события `E` также не заменяет время сделки `T`. Цена обновляется по мере получения сделок, без ожидания пятисекундного интервала.
6. Доменная проверка по-прежнему различает `fresh`, `stale`, `missing`, `invalid_time`. Отсутствие цены — `missing`; будущее, отсутствующее или некорректное время сделки — `invalid_time`. Отрицательный возраст не обнуляется. Рабочее предположение — синхронизированные UTC-часы; отдельный допуск на их расхождение не вводится. При missing/invalid_time HTTP возвращает `503 Service Unavailable`, код `quote_unavailable`; подписка не создаётся, слот не расходуется. Старый возраст и неподтверждённое состояние потока сами по себе такой ошибки не вызывают.
7. Предупреждения не отменяют подписки, не меняют их пороги и не являются TTL принятой durable работы. Сравнение активных подписок выполняется по поступающим сделкам. Протокол активации и гонки остаются в DEC-004, порядок/доставка/replay — в DEC-007. REST fallback и восстановление внешней истории этим решением не добавляются.

## Проверка примеров

Фиксируем `now_utc = 2026-10-26T12:00:10.000Z`. Для строк без оговорок поток работает без известного текущего разрыва, цена корректна.

| Время сделки / ситуация | Возраст / результат | Создание и предупреждение |
| --- | --- | --- |
| 12:00:10.000Z | 0; fresh | Успех, без предупреждения о возрасте |
| 12:00:05.001Z | 4,999 с; fresh | Успех, без предупреждения о возрасте |
| 12:00:05.000Z | 5,000 с; fresh | Успех, граница включена |
| 12:00:04.999Z | 5,001 с; stale | Успех с предупреждением о старой сделке |
| Сделка была минуту назад, редкая пара, поток исправен | 60 с; stale | Успех; предупреждение о возрасте, без утверждения о потере связи |
| Цена 100 была минуту назад; пользователь задаёт рост 5% | stale | Успех, исходная цена 100, фиксированный порог 105, предупреждение |
| Цена 110 была минуту назад; условие up, порог 105 | stale | Принимается с предупреждением; условие уже выполнено по DEC-001 |
| Связь потеряна, сделка 12:00:09.000Z | 1 с; fresh | Успех с предупреждением о неподтверждённой актуальности |
| Связь потеряна, сделка была минуту назад | 60 с; stale | Успех с обоими предупреждениями |
| Корректная сохранённая цена после рестарта, поток ещё не подтверждён | Любой неотрицательный | Успех с предупреждением о потоке и, если возраст > 5 с, о возрасте |
| Цены нет | missing | 503 quote_unavailable, без подписки и расхода слота |
| 12:00:10.001Z | −0,001 с; invalid_time | 503 quote_unavailable |
| Время сделки отсутствует или некорректно | invalid_time | 503 quote_unavailable |
| Сделка 12:00:00.000Z получена в 12:00:09.999Z | 10 с; stale | Успех с предупреждением; поздний приём не омолаживает цену |

Та же сделка 12:00:05.000Z при проверке в 12:00:10.001Z становится stale: изменяется предупреждение, создание остаётся допустимым. Предупреждения о возрасте и состоянии потока независимы.

## Варианты и пересмотр

- **Последняя известная цена без предела возраста, с предупреждениями — выбран в редакции 2.** Поддерживает редкие пары и явно сообщает ограничения информации. Процентный порог может рассчитываться от старой цены; это допускается с раскрытием её времени пользователю.
- **Запрет создания при возрасте > 5 секунд — первоначально принят, затем отменён.** Ошибочно ограничивал доступность редких пар даже при исправном потоке. История первой редакции сохранена в Git; её проверки с отказом для stale больше не действуют.
- **Считать возраст от приёма.** Задержанная сделка выглядела бы новой сразу после получения, поэтому возраст по-прежнему считается от времени сделки.
- **Не сообщать возраст и состояние потока.** Скрывает от пользователя ограничения последней известной цены; не выбран.

## Последствия

- Требования и связанные карточки уточнены; статусы implementation-карточек остаются planned.
- CON-003 сохраняет разделение времён сделки/приёма и обозначение разрыва.
- DOM-005 определяет возрастную классификацию; stale не означает запрет использования. Состояние соединения не входит в чистую функцию возраста.
- MKT-006 выдаёт последнюю известную цену вместе с возрастом и известным состоянием потока; сохранённая цена после рестарта допускается с предупреждением.
- SUB-003 возвращает предупреждения вместе с успешным созданием, сохраняет исходную цену и время; ошибка quote_unavailable остаётся для missing/invalid_time.
- DEC-004 учитывает использование последнего известного снимка с предупреждениями, не вводя скрытый запрет по возрасту. Предикат DEC-001 не меняется; его прежнее слово «свежая» читается с учётом этой редакции DEC-002.
- OPS-006 различает состояние потока и возраст последней сделки: редкие сделки сами по себе не доказывают disconnect.
- Go-код и автоматическая рассылка предупреждений не входят в DEC-002.

Эта редакция заменяет возрастной запрет предупреждением и сохраняет информацию о времени сделки и состоянии потока.
