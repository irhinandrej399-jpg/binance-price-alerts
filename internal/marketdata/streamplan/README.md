# План рыночных потоков — MKT-015

`Build(snapshot catalog.Snapshot, limit int) ([][]string, error)` строит план
из успешного каталога MKT-001. Например, ETHUSDT, BTCUSDT, ETHUSDT при limit=1
дают `[["btcusdt@trade"], ["ethusdt@trade"]]`.

Symbol переводится в нижний регистр, добавляется `@trade` по решению MKT-002.
Повторы удаляются после перевода регистра. Имена сортируются лексикографически
и разбиваются подряд на группы не более limit; пустых групп нет.
Порядок исходного каталога и UpdatedAt не влияют на результат.
Входные данные не изменяются; пустой каталог возвращает nil без ошибки.

Лимит обязателен: 1..`MaxStreamsPerConnection` (1024). Иначе возвращается
`ErrInvalidLimit`, даже для пустого каталога. Пустой symbol даёт
`ErrInvalidSymbol`; при любой ошибке план nil. Проверка доступности spot/USDT
и метаданных активов принадлежит `catalog.Fetch`: планировщику передают его
успешный снимок. Unicode-символы каталога сохраняются с переводом регистра;
ограничение ASCII в последующем декодере/PriceObserved этим не снимается.

Формат lowercase-symbol, raw trade и максимум 1024 streams на соединение
сверены 27 октября 2026 по
[официальному Binance WebSocket-контракту](https://github.com/binance/binance-spot-api-docs/blob/master/web-socket-streams.md).
Можно задать меньший лимит. Число потоков не зависит от пользовательских подписок.

Применение разницы, JSON-команды, ACK, reconnect/ротация соединений готовы в
[stream.Reconciler](../stream/README.md#план-каталога--соединения--mkt-016).
Периодическое обновление каталога и runtime wiring ещё отсутствуют. Сортировка даёт повторяемый план одного снимка,
но не обещает сохранять номера групп при изменении каталога.

Проверка: `GOTOOLCHAIN=local go test -race ./internal/marketdata/streamplan`.
