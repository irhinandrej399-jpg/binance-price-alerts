# Health market-data

`health.New(marketDataPool.Ping, feedSnapshot, time.Second)` возвращает HTTP handler,
первоначально не инициализированный. Runtime вызывает `SetInitialized(true)` после
сборки обязательных компонентов и начала durable поколений перед обслуживанием.
`SetInitialized(false)` снимает готовность; доступ конкурентный.

| Маршрут | Ответ |
| --- | --- |
| GET /healthz | Всегда 200 `{"status":"ok"}`, без обращения к зависимостям |
| GET /readyz | 200 `{"status":"ready","feed":"live"}` либо 503 `{"status":"not_ready","feed":"..."}` |

Readiness проверяет инициализацию, собственную БД market_data и текущий feed.
`feed` — `starting` до инициализации, затем результат callback:
`unconfirmed`, `disconnected` или `live` (также допустим `starting`). Ошибка БД,
ошибка callback, неизвестное состояние или отсутствующий callback дают 503 с
`unconfirmed`: состояние feed в таком ответе не удалось подтвердить.
Внутренние ошибки и credentials в HTTP не передаются.

`feedSnapshot(ctx)` возвращает согласованное текущее состояние **всего требуемого
плана** runtime. Любой известный текущий разрыв означает `disconnected`; при
неподтверждённых потоках — `unconfirmed`. `live` допустим только после явного
подтверждения всех требуемых потоков по контракту ingest. Открытое соединение,
SUBSCRIBE ACK или одна свежая сделка сами по себе не подтверждают весь feed.
Callback не выводит состояние из возраста последней сделки. Пустой успешно
применённый план не требует сделок; его готовность подтверждает runtime.

После reconnect feed остаётся unconfirmed до подтверждения; наблюдаемый разрыв
снимается только фактическим восстановлением текущего потока. Исторический
`GapDetected` при этом не очищается и сам по себе не запрещает готовность.
Редкая пара без новых сделок на подтверждённом потоке остаётся ready.
Поколения и отсечение устаревших callbacks принадлежат runtime/storage;
health не вызывает `SetStatus`, не меняет котировки и не открывает WebSocket.

Один deadline покрывает обе последовательные проверки, по умолчанию 1 с;
отмена HTTP передаётся callbacks. Они обязаны соблюдать context и поддерживать
конкурентные вызовы. Результат с истёкшим context не становится успехом.
Нет фонового кэша состояния: следующий запрос после восстановления может дать 200.
Liveness остаётся успешным при reconnect и отказе хранилища.

HEAD поддерживается по правилам Go ServeMux; неизвестный маршрут — 404,
неподдерживаемый метод — 405. JSON, `Cache-Control: no-store`.

По DEC-010 Ping проверяет доступность своей БД, а не будущий commit, свободное
место или capacity ledger. Фактическая ошибка Accept/SetStatus/commit остаётся
ошибкой операции независимо от health; outbox не удаляется ради готовности.
Другие сервисы, Kafka и внешние HTTP endpoints health напрямую не проверяет.

Проверки: `GOTOOLCHAIN=local go test -race ./internal/marketdata/health`;
реальная БД — `python3 scripts/check_postgres.py` (disposable стенд).
OPS-006 поставляет компонент. `cmd/market-data` пока каркас: HTTP listener,
feedSnapshot, подтверждение ingest и wiring всех компонентов нужны отдельно
перед E2E-002; работающий процесс этим результатом не подтверждён.
