# AlertTriggered — CON-004

`alerttriggered.Triggered` — запрос durable работы доставки по
[DEC-004](../../../docs/decisions/DEC-004.md), а не подтверждённая доставка.
Конверт [CON-001](../event/README.md): `type=alert.triggered`, `version=1`,
`ordering_key=subscription_id`, как у SubscriptionChanged. `Encode`/`Decode`
проверяют конверт, тип, ключ и payload; `Validate`/JSON-методы — payload.

```json
{
  "schema_version": 1,
  "intent": "delivery_requested",
  "trigger_id": "workflow-1",
  "workflow_version": 1,
  "user_id": "user-1",
  "subscription_id": "sub-1",
  "subscription_version": 2,
  "pair": "BTCUSDT",
  "threshold": "100.123456789012345678",
  "direction": "up",
  "candidate_quote": {
    "schema_version": 1,
    "pair": "BTCUSDT",
    "price": "101.123456789012345678",
    "source_id": "9007199254740993",
    "revision": {"stream_id": "binance-spot-trade", "generation": 1, "sequence": 17},
    "trade_time": "2026-10-27T10:00:00.123456Z",
    "received_at": "2026-10-27T10:00:01.123456Z",
    "stream_state": "unconfirmed",
    "gap_detected": true
  }
}
```

| Поле | Контракт |
| --- | --- |
| `schema_version` | Обязательное целое 1; отсутствующая/неизвестная версия — ErrUnsupportedVersion. Не версия конверта. |
| `intent` | Только `delivery_requested`, обязательно. Никакого terminal-успеха или разрешения попытки. |
| `trigger_id` | Непустой непробельный непрозрачный ID одного workflow; ключ дедупликации задания notifications. Совпадает с `SubscriptionChanged.workflow.trigger_id`. |
| `workflow_version` | Положительный uint64, версия канонического workflow API; соответствует `SubscriptionChanged.workflow.version`. |
| `user_id`, `subscription_id` | Обязательные непробельные ID владельца и подписки. Существование и принадлежность проверяет API. |
| `subscription_version` | Положительная каноническая версия подписки на момент сохранения запроса работы. Не версия workflow. |
| `pair` | Нормализованная пара A–Z/0–9, совпадает с парой котировки. |
| `threshold` | Обязательная точная неотрицательная строка Price, до 18 целых и 18 дробных цифр; нулевой порог допустим как в домене. Фиксированный порог, в том числе ранее рассчитанный процентный. |
| `direction` | Обязательное `up` или `down`; равенство входит в предикат. |
| `candidate_quote` | Обязательная диагностическая котировка по полному контракту [PriceObserved v1](../priceobserved/README.md): точная положительная цена, source ID, ревизия, T, время приёма, необязательное E, состояние потока и явный boolean разрыва. Это payload котировки, без вложенного конверта. |

Цена остаётся точной JSON-строкой, числа версий — uint64 без float64. Другим
клиентам нужен lossless parser для значений > 2^53. Неизвестные дополнительные
поля игнорируются и не сохраняются при повторном кодировании. Ошибка decode не
меняет получателя. Ошибки вложенной котировки доступны через `errors.Is` вместе
с ErrInvalidTrigger; неизвестная версия котировки — отдельный sentinel её пакета.

## ID, повтор и возобновление

API сохраняет workflow, канонический переход и outbox атомарно. `trigger_id`
назначается один раз до commit. Если работа уже существует, API возвращает её,
не создаёт второй workflow. Пакет не генерирует ID, время или версии.

Повтор публикации одного события сохраняет весь payload, event_id и метаданные
конверта. После ожидания условия, повторов, рестарта и перепривязки Telegram
сохраняются trigger_id и прежнее задание. Версию workflow назначает API при
канонических изменениях, не relay/worker при каждой попытке. Новое логическое
событие получает свой event_id; это не основание создать новый job для того же
trigger_id. Версии подписки/workflow, ревизия котировки, cursor C и Kafka offset
не заменяют друг друга. Схема проверяет одну запись; монотонность, уникальность,
дедупликация и невозможность возрождения terminal-подписки — обязанности storage
и потребителей, здесь не реализованные.

## Перед каждой отправкой

Событие даже с подходящей candidate_quote никогда не разрешает `sendMessage`.
Старый запрос работы может прийти после ухода цены, отмены или смены канала.
API проверяет каноническое состояние/workflow и получает последнюю котировку
market-data перед каждой попыткой. Допуск возвращает **новую проверенную
котировку**, времена/предупреждения и разрешение конкретной попытки. Текст
уведомления формируется по результату допуска. Историческая candidate_quote
не заменяет его; проверка схемы не вычисляет текущий предикат и не вводит TTL.

Если условие исчезло — `wait_condition`, active и ожидание в прежнем workflow;
при недоступной цене — отложенная проверка без отправки по старой цене. Только
сохранённый API подтверждённый успех Telegram завершает подписку и освобождает
слот; само событие этого не делает. Lease допуска, fencing и фиксация исхода —
будущие SUB-017–020 и NTF-014, durable создание запроса/job — SUB-013 и NTF-001.

По [DEC-005](../../../docs/decisions/DEC-005.md) chat и версия привязки определяются
API при допуске. В этом событии их нет, как и attempt_id/токена допуска.
`user_id` — идентичность владельца, не адрес отправки. Потеря канала блокирует
работу с сохранением слота/ID; перепривязка возобновляет прежний workflow с
проверкой последней цены. Старое событие не удерживает прежний chat. Уже
допущенный внешний запрос может завершиться на прежнем chat; следующая попытка
получает актуальную привязку. Контракт допуска и Telegram runtime сюда не входят.

Проверка: `GOTOOLCHAIN=local go test ./internal/contracts/alerttriggered`.
