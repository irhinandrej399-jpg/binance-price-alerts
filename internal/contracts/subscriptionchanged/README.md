# SubscriptionChanged — CON-002

Пакет задаёт полный after-image подписки в JSON-конверте CON-001.
`Encode` и `Decode` проверяют метаданные и payload; `Changed.Validate`,
`json.Marshal`/`json.Unmarshal` проверяют сам payload. Ошибка декодирования
не меняет получателя. Неизвестные дополнительные поля допускаются, но не сохраняются.

Конверт: `type=subscription.changed`, `version=1`,
`ordering_key=subscription_id`. `event_id`, время и correlation_id задаёт
производитель до commit; сериализация их не генерирует и не заменяет.
`Encode` заменяет `Envelope.Payload` переданным Changed.

| Payload | Правило версии `schema_version=1` |
| --- | --- |
| `position` | Положительная uint64-позиция одной записи транзакционного журнала API. |
| `transaction_end` | Положительная uint64-граница C всей транзакции, не меньше position. Все её записи имеют один конец; последняя имеет position=transaction_end. |
| `subscription_id`, `subscription_version` | Непробельный ID и положительная uint64-версия канонической подписки. |
| `state` | active, pending_delivery, sending, delivery_blocked, delivered или cancelled. Терминальная запись передаётся целиком, не является удалением без версии. |
| `pair` | Нормализованная непустая пара: ASCII A–Z и 0–9. Наличие пары в каталоге проверяет API. |
| `threshold` | Обязательная точная десятичная JSON-строка доменного Price: до 18 целых и 18 дробных цифр, без float64. Ноль допустим по контракту Price. |
| `direction` | up или down; включённое равенство определяется доменным предикатом. |
| `activation` | Только latest_price. Matcher регистрирует обновления, читает последнюю цену и объединяет ревизии по MAT-012/DEC-004. Ценовая готовность не следует из получения этого события. |
| `creation_snapshot` | Обязательные price (точная строка Price) и trade_time (ненулевое RFC3339-время). Исходный снимок для порога/аудита; никогда не разрешение отправки и не начало replay цен. |
| `workflow` | Необязательный объект trigger_id (непробельный устойчивый ID) и version (положительная uint64-версия workflow). Обязателен для pending_delivery, sending и delivered. Active может сохранять прежний workflow при исчезновении условия; cancelled — при отмене уже существующей работы. Delivery_blocked допускает отсутствие workflow при блокировке до его создания. |

Версия payload независима от версии конверта. Неизвестная/отсутствующая
schema_version даёт `ErrUnsupportedVersion`, ошибочные поля/JSON —
`ErrInvalidChange`; ошибки метаданных — ошибки пакета event. Используйте
`errors.Is`. Для standalone payload эти же проверки выполняет JSON API.
Незнакомая версия/повреждение должны останавливать партицию по DEC-007.

## Полнота журнала и границы

Выбран предусмотренный DEC-007 полный журнал, без фильтрации записей relay или
SQL-replay. По DEC-006 номер выделяется каждому изменению представления подписки;
в одной транзакции может быть непрерывный диапазон. Каждая выделенная позиция
содержит SubscriptionChanged, даже если конкретный consumer не меняет по ней
свою проекцию (например, повторное незавершённое состояние или terminal).
Записи других бизнес-операций, не меняющих представление подписки, номера
этого журнала не расходуют. Публиковать только последнюю запись диапазона нельзя.

Например, после сохранённого C=40 транзакция с двумя изменениями выдаёт
(position=41, transaction_end=42), затем (42,42). Следующая транзакция —
(43,43). Получение сразу 42 означает недостающую запись 41; отсутствие
интереса проекции к 41 не разрешает скрывать её из потока. Потребитель
продвигает C только после сохранения целой непрерывной транзакции. Повтор
публикации сохраняет event_id, position, transaction_end и версии.

Схема проверяет одну запись и не доказывает непрерывность потока, уникальность
ID, неизменность исходного снимка между версиями или допустимость перехода.
Эти обязанности принадлежат API-журналу SUB-021, relay и matcher/replay.
Kafka offset, ревизия цены, версия workflow и версия подписки — отдельные шкалы;
они не заменяют position/C. uint64 декодируются прямо в целые Go, без float64;
клиенты с неточным JSON number обязаны использовать lossless parsing.

Событие не содержит допуска Telegram. Последняя цена, канал и действующий
workflow проверяются API перед каждой попыткой. Событие не создаёт второй job,
не возрождает отменённую подписку и не восстанавливает историческое условие.
Доставка, БД, проверка последовательности и runtime здесь не реализованы.

Проверка: `GOTOOLCHAIN=local go test ./internal/contracts/subscriptionchanged`.
