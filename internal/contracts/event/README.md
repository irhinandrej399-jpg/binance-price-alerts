# Общий конверт события — CON-001

Пакет `internal/contracts/event` задаёт JSON-конверт и проверяет общие
метаданные через `Envelope.Validate`, `json.Marshal` и `json.Unmarshal`.
Внешних зависимостей нет.

```json
{
  "event_id": "outbox-42",
  "type": "example.changed",
  "version": 1,
  "occurred_at": "2026-10-26T10:00:00Z",
  "correlation_id": "request-7",
  "ordering_key": "BTCUSDT",
  "payload": {}
}
```

Это пример конверта, а не схема конкретного события.

| Поле | Контракт |
| --- | --- |
| `event_id` | Непустой непробельный ID одного логического события. Владелец создаёт его до SQL commit, сохраняет с outbox и использует при каждом повторе публикации. Конверт не генерирует ID. |
| `type` | Непустое непробельное имя события. Список типов и их payload определяют CON-002/003/004. |
| `version` | Версия общего конверта, сейчас только целое `1`. Нулевая, отсутствующая и неизвестная версии дают `ErrUnsupportedVersion`; миграция payload определяется его контрактом. |
| `occurred_at` | Ненулевое время исходного события в RFC3339 (допустимы дробные секунды и часовой пояс), год 1…9999. Сохраняется при повторе. Время публикации не подставляется сюда заново. |
| `correlation_id` | Непустой непробельный ID связанной цепочки работы; производитель передаёт или сохраняет его. У нескольких событий может быть общий correlation_id. |
| `ordering_key` | Непустой непробельный ключ потока порядка: нормализованная пара для цен, subscription_id для delivery-requests. Для subscription-changes порядок целых транзакций по C обеспечивает relay одной партиции. Ключ не задаёт глобальный порядок между topics. |
| `payload` | Непрозрачный `json.RawMessage`. Общий конверт допускает любое JSON-значение, отсутствие и null; обязательность, версия и поля конкретного payload проверяются контрактом типа перед обработкой. |

Строки не нормализуются и не обрезаются. UUID-формат для ID здесь не навязывается.
Неизвестные дополнительные JSON-поля допускаются и не сохраняются при повторной
сериализации; relay должен хранить исходный конверт целиком, если требуется их
передача. Ошибочный JSON и некорректные метаданные дают `ErrInvalidEnvelope`;
ошибки различаются через `errors.Is`. При отказе декодирования получатель
остаётся неизменным. Ошибки сериализации самого payload возвращает encoding/json.

## Независимые шкалы по DEC-007

- `ordering_key` выбирает поток/партицию. Для цен это ключ пары, а не номер её изменения.
- Монотонная ревизия цены, идентичность поколения и source ID — самостоятельные
  поля [payload CON-003](../priceobserved/README.md). Время конверта и event_id их не заменяют.
- Позиция C журнала API и конец целой транзакции — самостоятельные поля
  [payload CON-002](../subscriptionchanged/README.md). Они не записываются в ordering_key или ревизию цены.
- Kafka topic/partition/offset — транспортные метаданные при чтении, за пределами
  конверта. Offset никогда не считается C и не заменяет бизнес-ревизию.

Повтор SQL-outbox сохраняет event_id даже при новом Kafka offset.
Уникальность ID, durable сохранение, порядок relay и дедупликация потребителя
проверяются в будущих outbox/consumer-задачах. Тест повторной сериализации здесь
проверяет сохранение ID контрактом, а не устойчивость ещё не реализованного outbox.
По [DEC-007](../../../docs/decisions/DEC-007.md) потребитель при незнакомой версии
или повреждении должен показать ошибку и остановить соответствующую партицию,
сохраняя checkpoint; молчаливый skip/ack запрещён. Runtime-потребителей здесь нет.

Проверка: `GOTOOLCHAIN=local go test ./internal/contracts/event`.
