# Источник цен matcher (MAT-013)

`pricefeed` — ephemeral вход Kafka для [MAT-012](../priceconnection/README.md). Использует закреплённый
franz-go v1.22.2 и `priceobserved.Decode`. Durable обработка/offset commit,
арбитраж ревизий, Latest, consumer group и runtime выполняются отдельно.

```go
feed, err := pricefeed.New(ownerCtx, pricefeed.Config{
    Brokers: brokers, Topic: prefix + "-prices",
    Partitions: assignedPartitions, // внешнее назначение, 0..15
    Buffer: 256,
})
if err != nil { return err }
defer feed.Close()
reg, err := feed.Register(pairCtx, "BTCUSDT", assignedPartition)
if err != nil { return err }
defer reg.Close()
// Только теперь MAT-012 может начать Latest и слияние ревизий.
// Во время bootstrap/live наблюдать reg.Done(); при закрытии — reg.Err().
update, err := reg.Next(waitCtx)
```

На источник допускается одна регистрация пары и не более 1 024 регистраций.
Пара нормализована (A-Z/0-9, ≤64 байт). Caller передаёт согласованную партицию;
адаптер не выбирает hash/manifest и не распределяет владельцев. При обнаружении
пары в другой партиции регистрация теряет непрерывность. Владелец обязан вызвать
`Revoke` **до** передачи/потери назначения; метод завершает весь источник.

## Граница регистрации

New получает у брокера last stable offset (LSO) всех назначенных партиций и
устанавливает **абсолютные** позиции direct consumer. Register под блокировкой
диспетчеризации повторно читает LSO своей партиции, устанавливает регистрацию,
затем возвращает её. `Start()` — включённая граница `(topic, partition, offset)`.
Уже выданная диспетчером запись находится до нового LSO; запись, полученная
во время запроса, ждёт установки регистрации. Это исключает окно между
регистрацией и последующим Latest. Граница может включать уже открытую
транзакцию, которая commit-ится позднее. Использование high watermark вместо
LSO пропустило бы такую цену. События до границы игнорируются; последующие
committed события зарегистрированной пары сохраняются до Next/Close/ошибки.
Незарегистрированные пары не образуют очередь. Регистрация не обещает
исторический replay до своей границы.

Чтение — исключительно read_committed, без control records. `TryNext` неблокирующе
снимает уже накопленную запись (false/nil при пустой очереди); при ошибке источника накопленная работа не выдаётся. Update сохраняет
ключ, envelope/event_id, generation/sequence, точную цену и транспортную позицию.
Дубли выдаются отдельно с прежним event_id и своей Kafka-позицией. Kafka offset
не является C журнала подписок. Next, TryNext и Register **не подтверждают durable работу**.
У direct consumer нет group и механизма auto-commit; опция DisableAutoCommit
в этой версии клиента запрещена без группы. Клиент закрыт внутри адаптера,
методов Commit/SetOffsets в прикладном интерфейсе нет.

## Ограничения и отказы

- Общая очередь источника: по умолчанию 256, максимум 512 событий ≤4 KiB
  каждое (≤2 MiB payload плюс ключи и служебные структуры). Лимит общий для всех
  пар, отдельного неограниченного канала на пару нет. Next освобождает слот.
- PollRecords выдаёт диспетчеру одну запись; один concurrent fetch, fetch/partition
  target ≤64 KiB, decompressed batch ≤64 KiB, broker response ≤1 MiB. Ответы
  брокера и внутренний prefetch входят в RAM компонента, а не в прикладную очередь.
  Это ограниченный профиль ниже 16 MiB прикладных буферов DEC-008, без заявления
  о нагрузочной квалификации RSS/всего процесса. Крупные broker batches не должны
  обходить ограничения памяти; превышение ограничений чтения означает отказ.
- При заполнении следующая запись вызывает ErrOverflow + ErrContinuity.
  Источник останавливается, **все** его регистрации инвалидируются, их очереди
  освобождаются. Ошибка имеет приоритет перед выдачей уже накопленных событий.
  Обработчик должен начать новый источник/регистрацию и Latest-bootstrap;
  нельзя продолжать со старым состоянием после ошибки. На Kafka ничего не ack/skip.
- Неизвестная версия, повреждённый/oversized payload, неверный key/pair,
  недоступный cursor/partition, fetch error и Revoke также завершают весь источник.
  NoResetOffset запрещает автоматический reset на start/end. Возвращаемые ошибки
  не содержат payload, credentials или сырые broker messages.
- Запросы позиции ограничены 3 с. После 1 с без выдачи записи проверяются позиции
  на брокере; отказ обнаруживается и в пустом потоке, а не только при публикации.
  Poll timeout сам по себе не является разрывом. Отмена New/ownerCtx завершает
  источник; отмена Register/pairCtx удаляет регистрацию. Отмена Next/waitCtx
  прерывает только ожидание. Close идемпотентен, ждёт завершения reader/client.
- Во время получения/применения Latest и live-работы MAT-012 обязан наблюдать
  Done/Err, заново проходить bootstrap после разрыва и самостоятельно сливать
  ревизии. Один успешный Next не является гарантией дальнейшей непрерывности.

## Проверка

```sh
bash infra/kafka/verify-go.sh
```

Runner SET-009 запускает race-тесты пакета на уникальном disposable Kafka
проекте и отдельном prices topic (KAFKA_PRICEFEED_TEST_PREFIX), чтобы
повреждённые fixtures не попадали в consumers других пакетов. Проверяются барьер регистрации и конкурентная публикация,
open/abort/commit, дубли/идентичность/позиции, ошибки контракта, bounded overflow,
отмена/закрытие/отзыв, недоступный broker, неизвестная партиция и реальный
OffsetOutOfRange без reset. Fault proxy SET-009 обрывает существующие соединения.
Закрытый opt-in broker обязан провалить тест, а не SKIP. EXIT удаляет стенд и volume.
Обычный `go test ./internal/matcher/pricefeed` явно пропускает реальные Kafka
проверки без KAFKA_INTEGRATION=1; с opt-in отсутствие параметров — ошибка.

Основание семантики direct assignment, read_committed и NoResetOffset:
[исходники franz-go v1.22.2](https://github.com/twmb/franz-go/tree/v1.22.2/pkg/kgo).
