# Подключение последней цены — MAT-012

`Connect(ctx, pair, partition, register, quotes, now)` сначала устанавливает
регистрацию MAT-013, затем вызывает MKT-006 Latest с бюджетом ≤1 с. `quotes`
принимает готовый `latest.Client`; matcher не читает market-data SQL.
`register` возвращает `Registration` и должен учитывать переданный lifetime context.
Например, для действующего источника:

```go
register := func(ctx context.Context, pair string, partition int32) (priceconnection.Registration, error) {
    return feed.Register(ctx, pair, partition)
}
c, err := priceconnection.Connect(ownerCtx, pair, partition, register, latestClient, time.Now)
if err != nil { return err }
defer c.Close()
q, err := c.Current() // первая согласованная цена для обработчика кандидатов
if err != nil { return err }
// Обработать q; далее в одном reader-цикле получать c.Next(waitCtx).
```

После Latest до возврата соединения накопленные обновления сворачиваются в одно
состояние. Сравнение — `Observed.NewerThan`: generation/sequence в пределах пары
и стабильного stream ID; время, source ID и Kafka offset не заменяют ревизию.
Поздний старый snapshot, старое событие и дубль не откатывают цену. Уже накопленные
99→101→99 дают последнюю 99, без исторического кандидата по 101.

`Next` ждёт большую ревизию и также объединяет накопленные обновления.
Обработчик получает исходные точную цену/source ID/ревизию/времена и диагностику
потока. Stale, unconfirmed и gap допустимы по DEC-002; missing, invalid_time,
будущая/некорректная цена и несравнимый stream ID не дают готовности.
На один проход сворачиваются максимум 512 обновлений (лимит источника),
чтобы непрерывный горячий поток не задерживал возврат бесконечно. Дополнительная
очередь не создаётся; хранится одна последняя обработанная котировка. Во время
Latest очередь остаётся bounded в pricefeed; переполнение снимает готовность.

Успешные `Current/Next` означают **ценовую** готовность на момент чтения.
`Current` возвращает последнюю обработанную цену; caller постоянно обслуживает
`Next`, чтобы продвигать её. `Current` и `Close` допускают конкурентные вызовы,
`Next` обслуживает один reader. Возвращаемые указатели независимы от внутреннего
состояния. Отмена отдельного wait не закрывает соединение; уже извлечённое
валидное обновление сохраняется и может вернуться одновременно с отменой.

`Done/Err` позволяют отзывать готовность в том числе при пустом потоке и во время
Latest; отмена lifetime/потеря регистрации отменяет текущий RPC. После потери
непрерывности `Current` больше не выдаёт прежнюю цену. Ошибка контракта также
закрывает соединение. После ошибки Connect регистрация освобождена, готового
объекта нет, даже если в очереди была валидная котировка.

Повторное подключение — новый `Connect` после `Close` прежнего соединения,
с новой регистрацией и новым Latest. Если сам pricefeed завершён, caller сначала
закрывает его и предоставляет новый источник через register. При смене назначения
владелец вызывает Revoke и отменяет ownerCtx **до** передачи партиций; новый
владелец выполняет bootstrap заново. Планирование повторов/backoff и consumer group
принадлежат будущему runtime/MAT-010/011; адаптер не повторяет RPC скрытно.

Это ephemeral состояние: нет ack/commit offsets, SQL-checkpoint, восстановления
исторических условий или готовности всей проекции. MAT-004 получает котировку
через Current/Next и отдельно обеспечивает durable исход/явный superseded до ack.
Кандидаты всё равно проходят SUB-014 с последней ценой API; чтение соединения
не разрешает Telegram. Snapshot/replay проекции и подключение в cmd отдельно.

Проверки:

```sh
GOTOOLCHAIN=local go test -race ./internal/matcher/priceconnection ./internal/matcher/pricefeed
bash infra/kafka/verify-go.sh
```

Управляемый источник проверяет snapshot/update/replay, временный true,
переподключение, ошибки Latest, смену поколения/stream ID, потерю регистрации,
отмену и конкурентное чтение. Существующий loopback harness проверяет реальный
Latest.Client/Server при обновлениях во время RPC. Kafka runner проверяет также
неблокирующий `pricefeed.TryNext` с исходными идентичностью/позицией; его bounded
буфер, read_committed и LSO-барьер остаются контрактом MAT-013.
