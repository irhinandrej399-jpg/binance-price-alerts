# Индекс порогов matcher — MAT-002

Нулевой `Index` готов к использованию. `Put(Entry)` добавляет или заменяет ID,
`Remove(id)` идемпотентно удаляет его, `Candidates(pair, current)` возвращает
копии записей: up с T ≤ P и down с T ≥ P. Равенство включено, предыдущая цена
не нужна; поиск не расходует записи. Version возвращается для проверки API.
Порядок результатов не определён. Price сравнивается через точный `Price.Cmp`,
без float/округления. Неверные ID/version/pair/direction отклоняются до изменения.
Нулевой порог допустим, как в контракте SubscriptionChanged.

По каждой паре/направлению — AVL-дерево с ключом (threshold, ID). Одинаковые
пороги остаются отдельными записями; map ID → Entry позволяет заменить/удалить
ключ без полного поиска. Обновление и удаление O(log n), поиск O(log n + k)
на группу с k результатами, память O(N), результат O(k). Полный подходящий
диапазон неизбежно требует O(k), включая горячую пару. Пустые группы удаляются.
RWMutex защищает методы; возвращённый slice и значения можно менять отдельно.
Индекс после начала использования копировать нельзя.

Caller последовательно применяет **актуальное durable состояние MAT-001**:
для active вызывает Put с ID, SubscriptionVersion, Pair, *Threshold, Direction;
при отмене, доставке или переходе из active — Remove. Возвращение в active
с прежним workflow снова добавляет запись. Pending/sending/blocked и terminal
остаются в durable проекции; задание доставки восстанавливает notifications.
Put безусловно заменяет запись: арбитраж старых версий выполняет MAT-001, а
caller сериализует применение принятых изменений и не подаёт исходные события
в индекс в обход проекции. Mutex сам по себе не упорядочивает SQL commit.

Это перестраиваемый in-memory компонент. Durable commit/ack, загрузка снимка,
перестроение после рестарта, соединение проекции с индексом, регистрация и
готовность последних цен относятся к последующим MAT-007/008/009/012 и runtime.
Результат поиска может устареть сразу после возврата: MAT-004 передаёт Version
в канонический API, проверяющий состояние/версию/последнюю цену. Индекс не даёт
разрешения на доставку и не вызывает API.

Проверки:

```sh
GOTOOLCHAIN=local go test -race ./internal/matcher/thresholdindex
GOTOOLCHAIN=local go test ./internal/matcher/thresholdindex -run '^$' -bench BenchmarkCandidates -benchmem -benchtime=300ms
```

Unit-тесты: точные границы, одинаковые пороги, направления/пары, замена,
идемпотентное удаление, независимые результаты, случайные изменения против
полного доменного предиката, баланс после сортированных/одинаковых ключей,
конкурентные чтения/записи. Benchmark: 100 000 записей, 100 пар; распределённый
набор и 50% на горячей паре, выборки малого и полного подходящего диапазона.
Это локальная стоимость поиска, а не подтверждение целевого burst всего сервиса.
