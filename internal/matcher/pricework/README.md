# Продолжимая обработка цены — MAT-016

`New(matcherPool, scope)` использует собственную БД matcher и миграцию
`004_price_work.sql`. `scope` — стабильная идентичность обработчика/шарда,
сохраняемая при рестарте и смене поколения проекции. Это пространство ключей,
а не lease или fencing token. Один владелец сериализует завершение и ack
ценовой партиции; распределённое владение остаётся MAT-010/011.

| Операция | Вход и результат |
| --- | --- |
| `Accept(ctx, Input)` | Стабильный `Key`, `ProjectionID`, C согласованной view, полная `Observed`, необязательная реальная `Position` и полный набор кандидатов. Цена и все кандидаты принимаются одной транзакцией. Повтор того же входа ничего не сбрасывает. |
| `Get(ctx, key)` | Один REPEATABLE READ view: исходная цена/набор, состояние, заменяющая цена, число завершённых кандидатов и все исходы. `Entry.Result == nil` означает оставшегося кандидата. |
| `Pending(ctx)` | Ключи незавершённых работ в scope, включая пустую работу до Complete. После открытия другого pool доступны прежние работы. |
| `Record(ctx, key, subscriptionID, Result)` | Неизменяемый окончательный исход кандидата и увеличение локального `Completed` одной транзакцией. Точный повтор успешен, включая повтор после завершения работы. |
| `Complete(ctx, key, replacement, prefix, ack)` | `replacement == nil`: завершить только после всех исходов. Иначе сохранить `superseded` с полной строго более новой ценой той же пары/потока. По желанию сохранить отдельно доказанный caller префикс prices. Ack вызывается только после подтверждённого commit. |
| `Checkpoint(ctx, topic, partition)` | Следующий offset явно зафиксированного префикса prices в scope. Отсутствие строки — `pgx.ErrNoRows`, не выдуманный offset 0. |

`Key` назначает MAT-004 **до первой попытки**, сохраняет/восстанавливает при
повторе и не переиспользует для другого входа. Он идентифицирует проверку view,
а не только ревизию цены: новая подписка, ожидаемая версия или C при той же
котировке должны получать новую работу. После сбоя сначала читать Pending/Get,
а не назначать новый случайный ключ прежнему входу. Порядок кандидатов
не влияет на идемпотентность; повтор subscription ID в одном наборе запрещён.
Времена входной котировки нормализуются в UTC. uint64 версий/C/ревизий и точная
десятичная цена сохраняются JSON-байтами без преобразования через float/int64.
Набор кандидатов замораживается до Accept; caller отвечает за его полноту.

Исход `workflow` требует canonical `TriggerID` и положительную
`WorkflowVersion` от SUB-014. Прежний trigger_id не заменяется повтором.
`condition_false`, `version_changed`, `not_active`, `not_found` — окончательные
исходы **этой проверки** без workflow. Timeout, отсутствие котировки,
Unavailable и неоднозначный ответ API не являются окончательными: кандидат
остаётся незавершённым и повторяет тот же canonical запрос. Пакет не вызывает
API, не создаёт workflow, не считает запись matcher разрешением Telegram.

Состояния `completed`/`superseded` неизменяемы. Точное повторное Complete
успешно, конфликтующий исход/заменяющая котировка отклоняются. Superseded
сохраняет все уже записанные результаты и незавершённые строки для аудита;
их больше нельзя завершать новыми Record. Известный точный повтор Record
разрешён. На заменяющую цену caller создаёт отдельную работу: сама отметка
superseded не обещает, что новая цена уже обработана.

## Три независимые шкалы и ack

- `Input.C` и `ProjectionID` — идентичность использованной проекции подписок;
  таблицы/checkpoint MAT-001/014 этот пакет не меняет.
- `Quote.Revision` — поколение/sequence одной пары в потоке market-data.
- `Position` — исходный topic/partition/offset prices, только если котировка
  получена из Kafka. Начальная Latest передаётся с `Position == nil`.

Завершение одной пары **не доказывает** обработку других записей партиции.
Поэтому `Prefix{Topic, Partition, From, Next}` передаётся отдельно: это явное
утверждение вызывающего кода, что весь непрерывный read_committed префикс
`[From, Next)` уже durable. Caller учитывает другие пары/работы и допустимые
физические Kafka gaps; нельзя вычислять Next из C, ревизии или максимума
завершённых offset. Первое From задаётся проверенной транспортной регистрацией;
дальнейшие изменения требуют точного совпадения с SQL checkpoint. Старый
повтор не откатывает более высокий checkpoint. Ошибка CAS откатывает и
завершение работы. Latest не может продвигать транспортный checkpoint.

При наличии Prefix он должен соответствовать позиции работы и покрывать её.
Хранилище проверяет эту связь и CAS, но **не доказывает полноту префикса**:
это обязанность будущего consumer MAT-004/005/010/011. Внешний broker ack должен
подтверждать только явно сохранённый префикс, после успешного Complete/commit;
автоматический OffsetCommit запрещён. Сбой ack возвращается как ошибка, но SQL
результат остаётся; повтор Complete снова вызывает ack после commit.
Вызов без Prefix сохраняет только результат работы, не транспортный прогресс.

## Ошибки и восстановление MAT-004/005

`ErrInvalid` — некорректный ключ/кандидат/исход/позиция/заменяющая цена;
ошибки Validate котировки передаются без потери типа. `ErrConflict` — другой
вход под прежним ключом, изменение принятого исхода, новая запись результата
после terminal или конфликт CAS. `ErrPending` — попытка обычного завершения
с оставшимися кандидатами. Нет работы/кандидата — `pgx.ErrNoRows`.
SQL/context/commit и ошибки callback передаются caller (`errors.Is` работает).
Ни один ненулевой результат commit не разрешает ack: прочитать Get/Checkpoint
либо повторить идемпотентную операцию; исход commit может быть неизвестен.

MAT-005 сначала читает Pending/Get, подключает актуальную последнюю цену и
проверяет текущую view. Исчезнувшее условие старой цены не воспроизводится:
старую работу можно durable supersede более новой ревизией, сохранив уже
принятые workflow. Ошибка API до записи matcher требует повторить тот же
owner/subscription/version для восстановления canonical workflow, а не
генерировать trigger_id. Завершённые работы можно читать по прежнему ключу
при повторной доставке после потери broker ack.

Проверки: `python3 scripts/check_postgres.py` — реальный disposable PostgreSQL,
две pool, race detector, rollback при INSERT/progress/checkpoint и deferred
commit, 37/100, повторы, superseded, Latest, независимые шкалы и CAS. Без opt-in
SQL-тесты явно SKIP. Consumer, API orchestration, fencing, runtime, нагрузка,
постраничное чтение больших работ и очистка результатов остаются отдельно.
