# Каноническая подписка API (SUB-001)

Миграция `migrations/api/005_subscriptions.sql`; пакет `internal/api/subscription`.
`New(db)` принимает pool, connection или `pgx.Tx` через готовый `account.DB`.
`Insert(ctx, Record)` сохраняет полный after-image с заданным устойчивым UUID;
`ByID(ctx, ownerID, id)` читает только запись указанного владельца. Внешний слой
берёт ownerID из доверенного контекста аутентификации. Чужая и отсутствующая
подписка дают одинаковый `ErrNotFound`. Прямой доступ matcher к API-БД запрещён.

Пара, направление и состояния используют существующие доменные значения.
Порог и цена создания — `price.Price`, PostgreSQL `numeric` без typmod с проверкой
диапазона 18/18: лишняя точность отклоняется, не округляется. Процент — необязательный
знаковый десятичный текст; фиксированный порог вычисляет application-слой через
`price.NewPercentageThreshold` до записи. Согласованность процента, порога и
направления остаётся обязанностью этого слоя. Для конкретной цены процент — nil.
Время сделки хранится в `timestamptz` с точностью PostgreSQL до микросекунд;
на входе следует использовать время Binance с милли-/микросекундами, при чтении
возвращается UTC. Возраст при будущем ответе вычисляется заново по времени сделки;
`Stale`, `StreamUnconfirmed`, `GapDetected` сохраняют предупреждения создания.

Версии подписки/workflow — положительные `int64` (до 9223372036854775807), версия
неудачной привязки — неотрицательная. `Activation = latest_price` соответствует
CON-002/DEC-004: отдельная историческая ценовая граница для replay не используется.
Это политика подключения к последней цене, не journal C и не ревизия котировки.
Исходный снимок не является TTL и не разрешает отправку.

Все шесть состояний DOM-004 сохраняются без преобразования; workflow ID и версия
не теряются у active/blocked/terminal. Pending_delivery, sending и delivered
требуют workflow; blocked сохраняет причину и версию канала. PK не позволяет
повторить ID подписки, UNIQUE(workflow_id) — разделить один workflow между двумя
подписками. Таблицы workflow/attempt и их внешние ключи/идемпотентность добавит
SUB-013/017/019: эта миграция хранит только ссылку. SQL-ограничения проверяют
форму записи, не разрешённость перехода DOM-004.

`Insert` — примитив для композиции, не готовая операция создания подписки.
Публичного wiring нет. При записи через транзакцию успешный Insert ещё не означает
commit. Application-операция должна атомарно объединить блокировку пользователя,
Telegram-политику, лимит (SUB-002), подписку и журнал/outbox (SUB-021/011), соблюдая
порядок DEC-006. Ни счётчик квоты, ни события этот пакет сам не создаёт. Универсального
upsert нет: он мог бы затереть новую версию или возродить terminal-подписку.

Ошибки: `ErrExists` для конфликта идентичности, `ErrInvalidInput` для нарушений
схемы/UUID, `ErrStorage` для прочих сбоев; отмена/deadline возвращаются из context.
Сырые ошибки PostgreSQL с пользовательскими значениями наружу не выдаются.
Ошибка SQL внутри `pgx.Tx` требует rollback всей операции или savepoint вызывающего.

Проверка с реальным PostgreSQL и race detector:

```sh
GOCACHE=/tmp/binance-go-build python3 scripts/check_postgres.py
```

Runner применяет миграции к disposable проекту и удаляет его volume. Обычный
`go test` пропускает PostgreSQL-тесты без opt-in и не подтверждает round-trip БД.
