# Журнал API — SUB-021

`Append(ctx, pgx.Tx, []Entry)` сохраняет один полный пакет SubscriptionChanged
в транзакции вызывающего. Сначала вызывающий блокирует и меняет бизнес-строки
в порядке DEC-006: пользователь → подписка → workflow/attempt. Затем **один раз**
передаёт все изменения в Append. После Append нельзя брать бизнес-блокировки
или ждать сеть. Commit/rollback выполняет вызывающий; при любой ошибке нужен
rollback всей операции. Повтор после rollback использует прежние event ID,
correlation ID и время; новый ID не генерируется внутри адаптера.

Миграция `migrations/api/007_subscription_journal.sql` добавляет:

- `app.api_journal_counter`: единственную строку C (начальное значение 0).
  UPDATE выделяет диапазон под блокировкой до commit/rollback. Откат возвращает
  и номера, и журнал, и бизнес-изменения. Sequence/MAX для C не используются.
- `app.api_journal_batches`: конец целой транзакции и уникальный xid8 её
  PostgreSQL-транзакции. Второй Append в той же транзакции приводит к ошибке
  уникальности и её откату: нельзя выдать несколько разных C одной транзакции.
  Xid служит только идентичности пакета, не определяет порядок и не выходит
  в событийный контракт.
- `app.api_journal`: уникальные position/event_id, transaction_end и исходный
  wire-конверт bytea. Он содержит полный after-image, метаданные и точные цены;
  повторное чтение сохраняет ID, версии и наносекунды времени. Публикация не
  меняет эти строки. Runtime имеет SELECT/INSERT, без UPDATE/DELETE; начальные
  default privileges явно отозваны. Счётчик доступен только для SELECT/UPDATE(position).

`Entry` содержит Envelope и Changed. Входные Position/TransactionEnd и
Envelope.Payload заменяются валидированным результатом; входной объект не
меняется. Остальные метаданные обязательны по CON-001/002. Позиции хранилища
ограничены положительным bigint (до 2^63−1), независимо от uint64 wire-типа.

`Current(ctx, reader)` читает C. Для согласованного снимка передайте ту же
REPEATABLE READ транзакцию, в которой читаются бизнес-строки; вызов через pool
сам по себе снимка подписок не создаёт.

`ReadAfter(ctx, reader, C, maxTransactions)` читает строго после C, в порядке
position, без фильтрации событий. C=0 означает начало; ненулевой C обязан быть
концом существующего пакета. Промежуточные/будущие границы отклоняются.
Лимит 1..1000 задаёт число **транзакций**, не записей: пакет никогда не режется
страницей. Один SELECT читает все записи выбранных пакетов в одном MVCC-снимке.
Пустой хвост не означает, что ожидающий писатель уже завершился: после commit
его номер будет больше прежнего C. Продвигать cursor можно лишь после durable
применения целого пакета. Ограничения размера пакета/ответа относятся к будущим
admission и replay-адаптерам.

Ошибки проверяются через `errors.Is`: ErrInvalidInput (включая некорректную
границу/лимит и переполнение), ErrExists (event ID или второй Append), ErrStorage.
Ошибки контекста сохраняются; сырые SQL-ошибки с данными не выдаются.

Здесь нет переходов подписки, outbox relay, snapshot-builder, pins/retention,
очистки, сетевого replay или runtime. Writer обязан сам обеспечить идемпотентный
результат бизнес-команды: конфликт event_id не считается её новым успехом.
Будущий cleaner должен отдельно учитывать жизнь batches/counter и pins;
права удаления данным тикетом не выдаются.

Проверка: `python3 scripts/check_postgres.py` — disposable PostgreSQL, реальные
runtime-права и `go test -race -count=1` всех пакетов. Без POSTGRES_TEST=1
интеграционные тесты пропускаются.
