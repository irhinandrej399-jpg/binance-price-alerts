# Выдача кода Telegram — IAM-006

`telegramcode.Handler(session.New(pool, nil), telegramcode.New(pool, nil))`
обслуживает `POST /v1/telegram/link-codes` и сам подключает Bearer middleware.
Пул принадлежит API и подтверждает запись до ответа. Вход — запрос без тела;
любое непустое тело даёт 400 `invalid_request`. user_id из query и X-User-ID
игнорируется: владелец берётся исключительно через `auth.UserID`.

Успех: 201, JSON с `code`, `expires_in: 600`, `expires_at` (UTC),
Content-Type application/json, Cache-Control no-store. Код — 32 случайных
байта (256 бит) в canonical base64url без padding, 43 символа. Это секрет;
клиент передаёт его боту по HTTPS, приложение не должно писать его в логи,
URL запросов API или события. Точный интерфейс команды бота определит IAM-008.

`Store.Issue(ctx, userID)` сохраняет только SHA-256 от строки кода, user_id
и expires_at в `app.telegram_link_codes` (миграция 003). TTL — 10 минут,
действительность строго `now < expires_at`, равенство уже означает истечение.
Точность сохранения срока — микросекунда. Один аккаунт имеет максимум одну
строку. Успешная повторная выдача заменяет прежний хеш и срок, даже если
старый код ещё действовал. При параллельной выдаче остаётся один код последней
зафиксированной записи; ответ более раннего запроса может уже быть заменён.
Другие аккаунты не изменяются. Ошибка записи не возвращает код; ошибка до commit
не заменяет прежнюю строку. При потере HTTP-ответа клиент может запросить новый код.

Выдача блокирует строку пользователя перед upsert кода (DEC-006). Хеш уникален,
длина проверяется БД, удаление пользователя удаляет код. `Store` принимает
`account.DB`; при передаче транзакции вызывающий отвечает за commit. Runtime
использует пул. Отменённый context возвращается вызывающему; другие ошибки
хранилища скрыты за `ErrStorage`. HTTP — 500 `internal_error` без SQL/credentials.
Ошибки сессии — стандартные 401/500 из [auth](../auth/README.md).

IAM-008 должен атомарно поглотить код вместе с привязкой: найти владельца по
SHA-256, заблокировать пользователя, повторно проверить текущий хеш и строгий
срок, удалить код и сохранить привязку одной транзакцией. Тот же порядок блокировок
обязателен при конкуренции с выдачей. Проверка только по предварительному чтению
недостаточна. Поглощение, команды бота, уникальность chat и версия канала здесь
не реализованы. TTL не зависит от удаления истёкших строк фоновым процессом.

Runtime `cmd/api` ещё не подключён. Rate limits относятся к будущим задачам.
Проверки: `go test ./internal/api/telegramcode`; полный прогон с настоящей БД,
миграциями, параллельной выдачей и race detector — `python3 scripts/check_postgres.py`.
В IAM-006 граница срока и замена проверяются по сохранённому хешу/владельцу и
предикату действительности SQL; работающий путь поглощения проверит IAM-008.
