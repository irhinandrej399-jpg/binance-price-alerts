# Пароли API — IAM-002

`Hash(plain) (string, error)` создаёт Argon2id v19 через
`golang.org/x/crypto/argon2.IDKey`. Параметры: 19 MiB (`m=19456` KiB),
2 прохода, 1 поток, случайная соль 16 байт из `crypto/rand`, ключ 32 байта.
Профиль выбран по [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html#argon2id);
реализация — [Go x/crypto](https://pkg.go.dev/golang.org/x/crypto/argon2).

Строка хранения: `$argon2id$v=19$m=19456,t=2,p=1$<salt>$<key>`;
оба поля — канонический base64 без padding. Её можно передавать как
`passwordHash` в `account.Repository.Create`; БД хранит строку без изменения.
`Verify(encoded, plain) error` использует сравнение ключей за постоянное время:

- `nil` — пароль совпал;
- `ErrMismatch` — пароль не совпал;
- `ErrInvalidHash` — повреждённая строка, неизвестный алгоритм, версия или профиль.

Hash отклоняет пустой пароль (`ErrInvalidPassword`); Verify для него возвращает
ErrMismatch после проверки формата хеша. Остальные байты пароля сохраняются
точно: без обрезки, нормализации Unicode или ограничения bcrypt в 72 байта.
Политика сложности и ограничения HTTP-запроса принадлежат вызывающему API.

Проверка формата и точного профиля выполняется до KDF. Затраты не берутся
из непроверенной строки: даже огромное значение m/t/p будет отклонено.
При изменении профиля нужно явно добавить поддержку старого формата и
миграцию при входе; произвольные параметры сейчас не поддерживаются.

Пакет не логирует данные; ошибки статические и не содержат пароль/хеш.
Вызывающий код также не должен логировать аргументы и результат Hash,
возвращать хеш клиенту или отправлять его в события. Публичное поведение
ошибок входа и защита от перебора относятся к IAM-004 и OPS-013.
Профиль не заменяет ограничение параллельных попыток: каждый вызов KDF
потребляет около 19 MiB, измерение ёмкости runtime пока не выполнено.

Проверки: `go test -race ./internal/api/password`;
`go test ./internal/api/password -run '^$' -fuzz FuzzVerify -fuzztime=5s -parallel=2`.
